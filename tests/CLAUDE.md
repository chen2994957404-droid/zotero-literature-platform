# tests · 离线安全网 —— 给 LLM 的说明

> 你可能是被单独选中这个文件夹打开的。本文件是你的全部上下文。

## 这个文件夹是什么

**整个重构最重要的一块，不是附属品。**

在它出现之前，这个项目零个测试。后果是一条因果链：

> 没有安全网 → 改动有风险 → 接手的人宁可**新加一个脚本**也不改旧的
> → 脚本增殖、互相靠文件路径粘连 → 结构越来越难懂 → 更不敢改。

这里的测试就是为了斩断这条链。跑一次 `python -m pytest -q`，秒级出结果。

## 两组测试

| 文件 | 测什么 |
|---|---|
| `test_core_paths.py` | `core.paths` 的行为。**里面的断言就是数据契约本身** |
| `test_architecture.py` | **架构守卫**：不测功能，只测结构 |

### 架构守卫守的四条

1. **数据路径只许在 `core/paths.py` 里拼装** —— 别处写 `workflow_data` 就红
2. **依赖只能从上往下**（宪法铁律 2）—— `core` 不许 import `domain`/`adapters`/`pipelines`/`apps`
3. **`domain/` 环不许有 I/O** —— 出现 `urllib` / `requests` / `chromadb` / `subprocess` 就红
4. **不许再往 `sys.path` 塞项目根** —— 项目已装成包，补丁只会掩盖「其实没装好」

宪法里这些规则早就写着，但此前**没有任何机制阻止违反它们**，
所以实际上被违反了很多次。规则要有执行者才算规则。

## 硬性要求：这里的测试必须全离线

不许连 Zotero、不许连 Ollama、不许调任何云 API、不许依赖 `workflow_data` 里有数据。

理由：一个「有时候红是正常的」的测试等于没有测试 —— 人会习惯忽略它。
需要真实服务的验证走另一档：`modules/<名>/selftest.py` 和
`python 平台管理/health_check.py`（完整档）。

需要联网的测试请标 `@pytest.mark.live`，默认不跑。

## 怎么跑

```
python -m pytest -q                          # 全部离线测试（秒级）
python 平台管理/health_check.py --offline     # 离线档体检（含上面这一步）
```

**改完任何代码，先跑这两条。** 它们必须是全绿的 —— 红了就是结构被改坏了。

## 加测试的原则

- 优先测 `core/` 和（将来的）`domain/`：纯函数，好测，且是最稳定的部分
- **不要测 `apps/`**（界面层）—— 那里应该薄到没有可测的东西；
  如果你觉得界面层需要测，说明业务逻辑漏进去了，该往下搬
- 每修一个真 bug，补一条会复现它的测试
