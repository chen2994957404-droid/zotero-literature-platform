# 文献自动化科研平台

围绕 Zotero 的个人科研文献平台：**打个标签，文献自动变成中文图文精读**，
并可对整个文献库提问、抽取结构化数据做横向对比、检索补充新文献。

> 这份是给**人**看的地图。给 AI 看的说明在 `CLAUDE.md`，
> 以及每个文件夹里各自的 `CLAUDE.md`。

## 日常怎么用

| 我想干嘛 | 怎么做 |
|---|---|
| 精读一篇文献 | 在 Zotero 里给它打「待处理」标签，然后不用管 |
| **找文献** | 双击 **控制面板.bat** → 最上面「找文献」，输入主题 → 勾选 → 收下 |
| 看系统好不好、改密钥/模型 | 双击 **控制面板.bat** |
| 问我的文献库 | 跟 Claude 说「帮我查查 XX」 |
| 找新文献补库 | 控制面板「找文献」，或跟 Claude 说「帮我找 XX 方向的文献」 |

## 文件夹地图

> ⚠ 正在做一次目录重构（见 `REBUILD.md`），一个工具 = 一个文件夹。
> 九个工具都已经各就各位；剩下的是数据目录与文档的整理。

```
📁 tools/         【一个工具一个文件夹】
   deepread/      PDF → 中文图文精读 → 自动传回 Zotero    ← 最常用
   extract/       抽结构化字段 → 横向对比表（找研究空白用）
   paperdb/       结构化记录 → 能筛能比大小的查询库
   digitize/      论文图里的曲线 → 数据点
   ask/           问自己的文献库（RAG，答得深）
   askworld/      问全世界的文献（带原文出处）
   discover/      找新文献补库：搜全球 → 对照我的库 → 排序 → 收进来
   direction/     方向地图：一条窄带里谁做了什么；创意讨论
   curate/        Zotero 库的标签/元数据/去重/同步  ⚠ 会改你的库

📁 shared/        【共用件】kernel（基础设施）/ domain（纯逻辑）/ adapters（唯一能联网的一层）
📁 host/          【平台自身】控制面板 + 一键体检 + 部署 + MCP     ← 你的操作台
📁 docs/          架构宪法、踩坑记录、变更记录
📁 workflow_data/ 数据（精读结果、向量库、日志）—— 可再生，不进版本库
```

**根目录只放「进这个项目必须先知道的东西」，实现细节一律往下沉一层。**
判据：陌生人打开根目录，应该十秒内知道这是什么、从哪开始。

## 怎么让 AI 精准帮我改某一块

**关键：每个文件夹里都有一份 `CLAUDE.md`，是那一块的完整说明书。**

所以可以在新对话里**只选中某一个文件夹**，AI 一进来就知道：
这块是干什么的、有哪些坑、依赖谁、改完怎么验证。不用把整个项目都塞给它。

- 想改精读的效果 → 选 `tools/deepread`
- 想改问答 → 选 `tools/ask`（问自己的库）或 `tools/askworld`（问全世界）
- 想改某块底层能力 → 选 `shared/<环>/<积木名>`（如 `shared/adapters/llm_client`）
- 不确定问题出在哪、或要动多个部分 → 选整个项目根目录

> 如果 AI 在某个文件夹里想改别处的东西，它会提示你「请改选 XX 文件夹」。

## 两层结构（为什么这么分）

**共用件（`shared/`）**：每块只做一件不可再分的事。稳定，很少改。
**工具层（`tools/`）**：用共用件搭出来的实际功能。经常改。

好处是：改工作流不会动摇底座；底座改一次，上面所有功能一起受益。
维护这个平台，本质就是不断优化「积木」和「积木怎么拼」。

## 装到另一台电脑

1. 装 Python 3.13、Zotero、Ollama
2. 把整个文件夹拷过去（`workflow_data` 可以不拷，数据会重新生成）
3. `pip install -r requirements.txt`
4. 双击 **控制面板.bat**，在里面填密钥和本机设置（Zotero 用户ID、附件目录等）
5. 面板上看各项是否变绿

> 代码里不含任何个人信息；**密钥存在系统凭据库**（Windows 凭据管理器），
> 硬盘上没有明文，也不会被误提交到版本库。

## 两台电脑协作（像两个作者共用一个项目）

代码库放在 GitHub（主仓库：`chen2994957404-droid/zotero-literature-platform`），
两台电脑都从它同步，谁都能改、改完推上去、对方拉下来。

**日常流程（两台电脑都一样）：**

1. 开工前先拉取最新的：`git pull`
2. 改完代码后提交并推送：`git add .` → `git commit -m "改了啥"` → `git push`
3. 对方开工时 `git pull` 就能拿到你的改动

**怎么让另一台电脑有推送权限**：仓库主人（chen2994957404-droid）在 GitHub
仓库 Settings → Collaborators 里把对方账户加为协作者（权限选 Write）。

**两台电脑各自的东西（不互传，各自配）：**

- 密钥（DeepSeek / Zotero / MineRU）——各存各的系统凭据库
- 本机设置（Zotero 用户ID、附件目录、Ollama 路径）——各填各的 `.env`
- `workflow_data/` 数据（精读结果、向量库、日志）——不进版本库，各自生成

> 冲突怎么办：两个人同时改了同一个文件，push 可能被拒。先 `git pull`
> 把对方的改动拉下来合并，再 push；搞不定就把报错发给 Claude。

## 出问题先看这里

1. 双击 **控制面板.bat**，看顶部有没有红色告警、哪一项是红的/黄的
2. 精读没反应 → 看「精读监听心跳」是否正常、进程有没有「⚠重复实例」
3. 问答报错 → 多半是 Ollama 没跑，面板上点重启
4. 还不行 → 把面板截图发给 Claude

## 技术栈

Python 3.13 · Zotero 本地 API + Web API · DeepSeek（精读/抽取/问答）·
MineRU（PDF 解析）· Ollama + bge-m3（本地向量化）· ChromaDB（向量库）

第三方依赖极少（见 `requirements.txt`）——**能自己做的稳定部分自己做，
发展中的部分才用现成的**，这是项目的架构判据，详见 `docs/架构宪法_第一性原理.md`。


## 两台电脑怎么分工（2026-08-26）

详见 `docs/两台机器的分工.md`。一句话：

- **编程端**（装了 Claude Code 那台）：只用来改代码。
  **不许写 Zotero、不许跑精读监听、不许跑全库作业** —— 两台共用同一个
  Zotero 账号，编程端一回写就污染你的真实文献库。代码里有守卫会拦住。
- **主力机**：跑精读监听、Ollama、定时同步，`workflow_data/` 的权威数据在这台。

### 主力机上的四个按钮（不用敲任何命令）

| 双击 | 干什么 |
|---|---|
| `控制面板.bat` | 看状态、改密钥和模型、重启服务 |
| `精读监听.bat` | 手动启动精读监听（平时开机自启，一般不用点） |
| `更新平台.bat` | **拉取新代码 + 体检**，编程端改完代码后点这个 |
| `诊断报告.bat` | 出问题时点它，报告自动复制到剪贴板，直接粘给 Claude |

### ⚠ 拉到新版代码后要做一次

新版加了「机器角色」保护，默认按最安全的「编程端」处理。
所以主力机第一次更新后，**精读监听会拒绝启动**，需要：

> 控制面板 → 本机设置 → **机器角色** 填 `prod` → 保存

改完精读监听就正常了。（编程端保持 `dev` 不用动。）
