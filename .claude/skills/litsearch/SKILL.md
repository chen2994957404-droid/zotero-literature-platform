# litsearch · 对抗式检索的原料通道

**一句话**：把干净的原料递到你手上、替你记账，判断由你自己做。只读、不写 Zotero、不调大模型、不弹窗。

## 什么时候用我

- 你要**多轮、全面地**找某个方向的文献（尤其「最近有什么新做法」）—— 照下面「多轮全面检索」走
- 你要**自己跑对抗式循环**：先想 → 去取 → 读摘要 → 发现缺什么 → 再取
- 你想知道**某个词在全世界有多少篇** —— 这个数字告诉你该收窄还是放宽
- 你要顺着**引用网络**往前（后来谁做了）或往后（这方向的根在哪）摸
- 你要在花钱之前先确认**这篇是不是用户已经有了**

## 怎么用

```
python -m tools.litsearch "borosiloxane"                    # 精确检索
python -m tools.litsearch '"boronic acid" AND silanol' --limit 40
python -m tools.litsearch "borosiloxane" --since 2015
python -m tools.litsearch --abstract 10.1021/ma500632f      # 完整摘要
python -m tools.litsearch --cited-by 10.1021/cm980353l      # 前向雪球
python -m tools.litsearch --references 10.1021/cm980353l    # 后向雪球
```

MCP 上是不弹窗的 tool：
- 检索：`lit_search`（精确）· `lit_semantic`（按意思 / 照着几篇找）· `lit_abstract` · `lit_cited_by` · `lit_references` · `lit_snowball`（多篇）
- 台账：`lit_session`（建 / 定判据 / 下一轮）· `lit_judge`（按条记判断）· `lit_status`（饱和与估计）· `lit_terms`（挖新说法）

## 多轮全面检索（要「找全」时照这个走）

1. **开场**：`lit_session` 建台账；把「相关」拆成 2～4 条判据（例：`剪切硬化或率相关硬化` / `用了动态键` / `2023 年后`）。
   **年份窗口、算不算应用类 / 综述，问用户**，原话写进 `scopeNote`
2. **每轮三条腿都走**（所有检索带 `session=`，第二轮起加 `onlyNew=true` 只看新的）：
   - 词面 `lit_search`：同义词族，每个说法一次，看 total
   - 语义 `lit_semantic`：第一轮用一段话（英文）；之后用 `like=` 本轮最好的 2～5 篇。**必须给 yearFrom**（它不按年份排）
   - 引用 `lit_snowball`：本轮最好的 2～5 篇；找新进展用 `newestFirst=true` + `yearFrom`
3. **判**：读摘要按判据逐条判，`lit_judge` 一次记一批；只看了标题的记 `basis=title`（Elsevier 大多没摘要，别硬判成确定）
4. **看**：`lit_status` —— 每轮每条腿新增了几篇相关；各条腿「只有它找到的」有几篇（哪条腿贡献大）
5. **挖词**：`lit_terms` 给出相关文献里比其余多用的说法 → 下一轮词面检索优先用它们，自己想的词只作补充
   （依据：模型凭空写检索式召回偏低、换次运行就变 —— Wang 2023、SIGIR 2025 复评）
6. `lit_session nextRound=true` 进下一轮。**停**：连续一轮三条腿都没有新的相关篇，且 `lit_terms` 前 10 个都搜过了；
   或到了和用户约定的工作量。报告里原样贴 `lit_status` 的数字，写明用了哪条停止判据
7. 冒出范围外但可能有用的（邻近体系等），**列出来问用户**要不要纳入，别自己扩

## 怎么用好我（这一节比用法重要）

**① 先宽后窄，看命中总数决定下一步。**
`lit_search` 会告诉你全世界一共命中多少篇。几千篇 = 词太宽，加限定；
几十篇 = 正好，可以全捞；0 篇 = 词写错了或这个组合真没人做过（**后者本身就是结论**）。

**② 用精确语法，别写自然语言。**
我做的是「词必须真的出现在标题或摘要里」。
写 `"phenylboronic acid" AND siloxane` 有用；写「苯硼酸和硅氧烷反应的文献」没用。

**③ 判断贴题度要读摘要，别看标题猜。**
标题常常掩盖关键信息。2026-09-09 实测：一篇标题写「用于废水处理的吸附剂」的文章，
摘要里才有「二苯基硅二醇 + 对甲苯硼酸回流 12 小时，90% 产率得到八元环」——
那正是当时最关键的一条证据。

**④ 字面和意思两种检索是互补的，不是二选一。**
2026-09-24 实测「剪切硬化 + 动态键」：按意思找到了「用键解离动力学调控动态共价凝胶的剪切增稠」这类
一个 "shear stiffening" 都没写的文章；字面检索则抓得到没摘要（只能靠标题）的 Elsevier 文章 —— 语义检索对它们偏弱。

**⑤ 雪球是用来补盲区的，不是用来铺量的。**
先用检索把版图铺开，挑出两三篇最核心的，再对它们做前后向雪球，
看有没有漏掉的簇。对每一篇都雪球只会把上下文淹掉。

## 什么时候**别**用我

- **要一份排好序的、告诉你「先读哪几篇」的清单** → `discover`（它会拆检索式 + 雪球 +
  按「跟用户多相关」排序）。我不排序，是刻意的：排序要向量库和本地模型，
  算不出来时会静默退化成「按被引量排」（踩坑 #149），那比不排更坏。
- **搜用户自己的库** → `library_search`（更快，而且我搜的是全世界）
- **要带页码出处、能直接引用的原文片段** → `askworld`（Sciverse 全文库）
- **要正文 / 要收进 Zotero** → `getpdf`（我只给元数据和摘要，不下载不写库）
- **要读全文的某一节** → 先 `getpdf` 的 `paper_fulltext` 拿 id，再 `library_outline`
  看菜单、`library_section` 按地址取。别让我给你全文，我也给不了。

## 边界

- 数据源是 **OpenAlex**（按量计费，免费 key 每天 $1）。**Elsevier 的文章大多没有摘要**（源头不交，踩坑 #188），
  结果里标【无摘要】；`lit_abstract` 会退到证据库原文、Semantic Scholar，都没有就明说
- 语义检索：每次最多 50 条、不能翻页、**不按年份排序**、输入 ≤1500 字；一次调用最多发 8 次（$0.001/次）
- 台账只写本地 `state/searches/session_<名>.json`，不写 Zotero、不写证据库
- 「库里有没有」依赖 Zotero 开着。没开时它一律标「没有」（降级，不报错），
  这时这个标记不可信。
- 除了台账文件我**不写任何东西**，所以在编程端和主力机上行为一致，没有机器角色限制。
