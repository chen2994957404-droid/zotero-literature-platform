# ask —— 问用户自己的文献库

## 什么时候用我

- 用户问「我库里关于 XX 有什么」「我读过的文献里谁做过 YY」
- 需要一段**综合多篇、带来源**的中文回答，而不是一份条目列表

## 怎么用

我是 **prompt**，不是 tool：问一次要花钱，所以由用户在客户端里点，
或者你**先讲清代价、等用户点头**，再跑：

```
python -m tools.ask "问题"
```

如果提示向量库是空的 → `python -m tools.ask.vectorize`（全库作业，只在主力机跑）。

## 什么时候**别**用我

- **只是要找某篇在不在库里 / 要 key / 要 PDF 路径** → `library_search`（免费、秒回）。
  为这种问题调我是纯浪费钱
- **要比数值、要筛条件** → `paperdb`（我是文本检索，比大小会比错）
- **用户库里根本没有这个方向** → `askworld`（问全世界）或 `discover`（找新文献）。
  我只会回答「文献库里没有找到」，那不是故障，是事实
- **要一份可引用的、带页码出处的证据链** → `askworld` 更合适：
  它取的是原文片段并标出处，我给的是「基于我读过的东西的综合」

## 边界

- 答案只基于检索到的 6 个片段左右。**问题问得越具体，检索越准**；
  「帮我总结一下我的库」这种大而空的问题答不好
- 精层（精读过的）答得深，粗层（Zotero 全文索引）只够粗筛。答案里附的来源能看出是哪层
