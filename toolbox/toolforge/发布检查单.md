# 发布检查单 · 脚本查不了的那几件事

`preflight.py` 能查的都自动查了（密钥、公网 IP、用户目录、占位符、许可证、测试）。
这份单子只留**必须由人判断**的部分。推之前从头过一遍，不要跳。

## 一、合规与边界（最容易出事的一档）

- [ ] 这个工具会不会**替别人做他没有权限做的事**？
      （代下载、绕过付费墙、抓需要登录的内容、批量请求别人的服务）
- [ ] 如果它借用了使用者自己的账号/订阅/浏览器登录态：
      README 里**明确写清楚**「用的是你本人的合法权限，本工具不提供也不绕过任何权限」
- [ ] 有没有写明**不该用它做什么**（建盗版库、代下、商业转售抓来的内容）
- [ ] 目标网站/服务的条款有没有明确禁止自动化访问？**不确定就先不发**，
      或者先发一个不含该功能的版本

> ⚠ **一旦想收钱，上面每一条的风险都会放大好几档。** 免费开源出问题多半是被要求下架；
> 收费之后同一件事就变成商业行为。**先纯开源，别急着商业化。**

## 二、隐私（脚本只能查文本，查不了含义）

- [ ] 示例配置里的地址、账号、路径**全是编的**吗？
- [ ] 截图、日志片段、测试数据里有没有真实的文件名、标题、单位名、人名？
- [ ] 提交历史里有没有一度提交过又删掉的配置文件？
      （删掉的还在历史里 —— `git log -p` 搜一下关键词）

## 三、别人能不能用起来（决定它有没有人装）

- [ ] README 第一屏能回答：**这是干什么的 / 我要不要装 / 怎么装 / 怎么跑第一条命令**
- [ ] 从零开始照着 README 走一遍 —— **在一个干净目录里真做一次**，
      别在自己已经配好的环境里"想象"一遍
- [ ] 报错信息说人话：缺配置、缺依赖、参数写错时，它有没有告诉人下一步做什么
- [ ] 说清楚跑它需要什么（Python 版本、要不要自带 API key、要不要花钱）

## 四、名字与门面

- [ ] 名字在 GitHub 上搜一下，别撞上一个知名项目
- [ ] 仓库描述（那一行）说的是**它干什么**，不是"一个强大的工具"
- [ ] 许可证选对了（默认 MIT；不想让人商用就别选 MIT）

## 五、最后

- [ ] `python preflight.py <目录> --tests` **全绿**
- [ ] 在一台没配置过的机器（或干净目录）上 clone 下来跑一次测试
- [ ] 正本登记里已经写了这一件
