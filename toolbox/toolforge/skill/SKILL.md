# toolforge · 把成熟功能拆成独立工具

仓库在 `D:/dev/toolforge`。两个脚本，三份记录。

```bash
python D:/dev/toolforge/new_project.py <名字> --desc "一句话说它干什么"
python D:/dev/toolforge/preflight.py <仓库目录> --tests     # 推到公网之前必跑
```

## 四条规矩（都是踩出来的）

1. **复制，不搬走。** 拆出去的是副本，原项目原封不动照跑 ——
   原项目还在天天用，动它等于拿生产环境冒险。
2. **当场写正本登记**（`toolforge/正本登记.md`）：一份代码变两份就会漂移，
   必须写清楚**哪份是正本**。正在演化的那份就是正本，另一份是对外快照。
3. **推之前 `preflight.py` 必须全绿。** 推到公网的东西，删掉了也已经被抓走、被缓存。
   （第一件 `remote-machine` 就是靠它才发现许可证的版权人一直空着，已经挂了两天。）
4. **别过早抽象。** 拆够三件，共同点自己会浮出来，那时候再谈「通用框架」。

## 拆什么、不拆什么

**判据**：谁也不 import 它、换个项目还有用 → 可以拆；
被别人 import 的、跟这个项目的数据结构绑死的 → 留下。

对外发布还要多问一句：**陌生人装得上吗？** 要先备齐三样付费服务才能跑的东西，
门槛决定了有多少人真的装上。

## 三种形式怎么选（**这一节是这份技能的核心**）

| 形式 | 什么时候选 | 代价 |
|---|---|---|
| **skill** | 默认。它是「知识与判断」：什么时候该用、有哪些坑、命令怎么敲。装在 `~/.claude/skills/` 就对**所有项目**生效 | 最低。一个 md 文件 |
| **MCP** | 要让模型在**别的客户端**里直接调用；且这个操作**单次、便宜、可重来** | 中。⚠ 调用约 60 秒超时 —— 长作业只能做成 prompt 或异步发起 + 轮询 |
| **plugin** | 要**打包给别人装**（skill + 命令 + MCP 一起） | 最高。只有真要分发时才做 |

**先做 skill，几乎总是对的。** 模型本来就能跑命令行；skill 补的是它不知道的那部分
——什么时候用、什么时候别用、哪里会咬人。

**长作业不要做成 MCP tool**：精读一篇、全库抽取、大模型读图都要几分钟，
必然超时。超时之后作业**还在后台跑**，而调用方看到的是失败 ——
这种「看起来失败其实成功了」最容易让人重跑一遍、白花一次钱。

## 已经拆出来的

| 项目 | 形式 | 正本在哪 |
|---|---|---|
| `remote-machine`（从这台操作另一台 Windows） | 全局 skill | 它自己（原项目里那份已删） |
| `zotero-deepread`（Zotero 文献 → 中文精读报告） | 全局 skill | **文献平台**，这份是对外快照 |
| `toolforge`（本身） | 全局 skill | 它自己 |

## 新拆一件的流程

1. `new_project.py <名字>` 生成骨架（不覆盖任何已存在目录）
2. **复制**代码进去，改 import，跑通入口
3. 写 `tests/`：至少保证「什么都没配置的机器上 clone 下来测试全绿」
4. `preflight.py <目录> --tests` → 红的清零
5. **真机验一次**再发布 —— 只验「能 import、测试全绿」不算数，
   发一个自己都没跑通过的工具，第一个 issue 会很难看
6. 建 GitHub 仓库、推、在正本登记里写一行
7. 装成全局 skill（`install.py`），这样任何项目都能用
