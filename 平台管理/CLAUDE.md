# 平台管理 · 给 LLM 的说明

> 你可能是被单独选中这个文件夹打开的，看不到项目其他部分。本文件是你的全部上下文。

## 这个文件夹是什么

平台自己的仪表盘和体检工具 —— **用户与整个系统的交互入口**。

用户是材料方向研究者，**不懂编程**。这个文件夹存在的全部意义是：
让他不用问人就能知道系统好不好、并自己调整配置。

## 各文件职责

| 文件 | 干什么 |
|---|---|
| `panel.py` | 控制面板（本地网页）。双击根目录「控制面板.bat」打开 |
| `health_check.py` | 一键体检，**分离线/实测两档**。任何改动之后都该跑一遍 |

## panel.py 的设计铁律

**面板里一行业务逻辑都不许写。**

它只是「现有积木的视图 + 遥控器」：状态取自 `health_check` 的检查函数，
配置取自 `modules.config`，进程取自系统查询。
如果在面板里另写一套判断，就会出现「面板说正常、体检说异常」两套真相。

要加新功能：**先把能力做成积木或工作流脚本，再让面板调用它。**

### 面板的能力边界（刻意划的线）

- **可做**（可逆、零风险）：看状态/进程/日志/最近处理记录；改密钥与模型；重启后台服务
- **不可做**（不可逆或花钱）：删数据、全库重抽、改 Zotero 库、触发批量精读

理由：面板上一个按钮点错的代价，远大于用户多问一句的成本。**新增按钮前先按这条尺子量。**

### 安全约定

只绑 `127.0.0.1`（外部机器访问不到）；密钥只显示后 4 位；
输入框留空表示「不改动」而非「清空」；每次保存自动备份旧 `.env`。

## health_check.py 的两档设计（2026-08-26 重构阶段 0 引入）

```
python health_check.py --offline    # 离线档：包安装/离线测试/语法/静态检查
                                    #   ← 不依赖任何外部服务，必须永远全绿
python health_check.py              # 完整档：另加配置、Zotero、Ollama、
                                    #   公理件自测、数据资产、后台服务
                                    #   ← 本机没配密钥/没开服务就会红，属正常
```

**为什么要分档**：分档之前默认是「8 通过 / 5 警告 / 1 失败」，
而那 6 项红黄全部只是「这台机器没配密钥、没开服务」——
噪音盖住了真信号，于是没人再认真看体检结果。
分档之后，「离线档必须全绿」成了一条真正可执行的红线。

## health_check.py 的其他设计

- **自动发现工作流文件夹**（`workflow_dirs()`），新增一条线不用改代码
- **运行时导入检查**比语法检查更重要：语法过 ≠ 能跑。
  曾经批量替换把 import 插到了使用之后，语法完全合法但一跑就 NameError。
- 新增了「关键脚本找不到」检查，防止以后目录重组漏搬文件

## 依赖

**积木**（`../modules/`）：`config`（get_key / get_model / get_site / set_keys）
要改积木请让用户改选 `modules/<积木名>` 文件夹。

## 改完怎么验证

```
python -m pytest -q                          # 离线测试 + 架构守卫，应全绿
python health_check.py --offline             # 离线档，应全绿（0 警告 0 失败）
python health_check.py                       # 完整档（本机没配服务会有黄，正常）
python panel.py --no-browser                 # 然后访问 http://127.0.0.1:8777/
```
改面板后务必真的打开页面点一遍，别只看代码。
