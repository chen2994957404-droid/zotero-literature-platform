# tools/direction · 方向地图 —— 给 LLM 的说明

## 是什么

回答「**我的方向过去/现在是什么形势**」，而不是「某一篇讲了什么」。

用户的原话是：想像一个资深导师那样了解方向的真实状况与未来方向，
而不是靠看过的那几十篇论文拼印象。这条线就是那件事。

## 流水线

```
公众号 md 目录
  → adapters.wechat_seed      提 DOI + 推送日期（正文提完即弃）
  → adapters.openalex         DOI 对齐 + 批量拉参考文献（免费无密钥）
  → SQLite（shared.kernel.paths.direction_db()）  works / edges / seeds / clusters
  → bibliometrics/            IDF 文献耦合 + Louvain + 时间趋势（本工具自带）
  → 报告
```

**三步分开，每步单独可跑**，因为 `build()` 是几百次网络请求、要十几分钟；
落库之后 `cluster()` / `report()` 全是本地的，可以反复调参重跑。

```
python -m tools.direction build <公众号md目录>   # 联网，十几分钟
python -m tools.direction cluster                # 本地
python -m tools.direction report --out 地图.txt
python -m tools.direction stats
```

## 实测规模（835 篇公众号推送，2025-01 ~ 2026-08）

```
种子 754 篇（DOI 对齐率 98.2%）
唯一参考文献 39218 篇 / 引用边 55418 条
骨干（被 >=3 篇种子共引）2934 篇
聚类 res=3.0 → 36 个簇，主题纯度 0.48
```

## 三个设计决定，都有实测理由

### ① 只给「骨干」拉元数据，不给全部 39218 篇拉

39218 篇要 1000 次请求、半小时以上，而**其中 90% 只被一篇种子引用**
（各自的背景引用），对「领域长什么样」没有贡献。门槛卡在 `df>=3`，
元数据量降到 1/13，信息几乎不损失。

被共引次数是一条**陡峭的幂律**：`>=2` 有 6886 篇，`>=3` 只剩 2934，`>=10` 只剩 248。

### ② 期刊档次只用于筛种子，扩展层用「被 N 篇种子共引」筛

两层两套判据，各治一个病：

- 种子层用期刊 → 保证**起点不烂**
- 扩展层用共引 → 保证**不漏地基**

实测证据：Leibler 2011 vitrimer、Gong 2013 聚两性电解质这些奠基作，
公众号从不推（太老），靠期刊筛也筛不出来，但**靠共引一下就顶出来了**。
反过来，Multiwfn（发在 J. Comput. Chem.）靠期刊永远进不来，
靠「14 篇种子都引它」一眼可见。

### ③ 时间趋势按**公众号推送日期**分桶，不按论文发表年

问的是「**这个圈子什么时候开始关注它**」，不是「它什么时候发表」。

⚠ **最后一个半年常常不满半年**（比如 2026H2 只有 7、8 两个月），
直接拿它跟前面比会得出「在下降」的错觉。报告里已经印了提醒，别删。

## 数据在哪

`shared.kernel.paths.direction_db()` → `data/serving/direction/map.db`。

**这是可重建的派生层**（和 `library/` 的资产不同）：删掉再跑一遍命令就有。
`build()` 对同一个目录是幂等的，重跑安全。

## 没有加机器角色守卫，为什么

按 `docs/howto/两台机器的分工.md`，「找新文献 / 外部检索」是两台都能做的
（纯网络、免费、无副作用、不碰 Zotero）。OpenAlex 不要密钥也不花钱，
所以不需要 `role.require_prod`。

**如果以后加了要花钱的步骤**（比如用 LLM 给簇起名），那一步必须加守卫。

## 下一步（还没做）

1. **前向雪球**：现在只有「种子引了谁」，没有「谁引了种子」。
   后者才能算**跟进厚度** —— 一个漂亮结果三年没人跟进，通常说明复现不了。
   这是「去水」最直接的信号。
2. **多轮回滚挖源头**：实测一轮雪球带不回 1990 年代
   （top400 参考文献里 2020 年后占 79%，2010 年前只有 5 篇）。
   高影响因子刊的引用习惯本身「重今轻古」，要挖到真源头得对地基论文再滚一轮。
3. **突现检测 / 团队图谱 / 空白格**：空白格要接 `tools/extract` 的结构化字段，
   那是整条链上唯一别人做不出来的部分。

## 五件套（R4 窗补，2026-08-31）

| 文件 | 干什么 |
|---|---|
| `tool.toml` | 工具清单：`expose` / 花不花钱 / 有什么副作用 / 要哪档机器角色 |
| `cli.py` | 人的命令行入口（`python -m tools.direction`），只解析参数 |
| `mcp.py` | 给 agent 的 MCP 面（**只做参数转换，不许有逻辑**）|
| `README.md` | 给人：这是什么、怎么用 |
| `SKILL.md` | 给 agent：什么时候用我、怎么用、**什么时候别用我** |
| `prompts/` | 系统提示词（`<名>_v<N>.txt`）。**只增不改**：改措辞就新建下一版，旧版留着 |
| `evals/` | 评测：10 条金标，**答案由构造保证**（造零重叠的引文图，聚类必须分开）。加用例只改 `golden/clusters.json` |

本工具在 MCP 上是 **prompt**（花钱/有副作用 → 由人在客户端里点，模型不能自己调）。
判据与守卫见 `host/mcp/CLAUDE.md`。
