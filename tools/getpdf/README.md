# getpdf · 把正文弄到手

给一批 DOI，借一个**真实浏览器**把正文 PDF 取到本地。

## 为什么是「借浏览器」而不是「自己下载」

2026-09-04 同一天实测过两条路：

| 路子 | 结果 |
|---|---|
| `requests` + 机构 cookie | ❌ 过不了出版商反爬 |
| 驱动一个人已经在用的浏览器 | ✅ 拿到付费全文 |

旧项目 `AutoPAPER-SCU` 走的是第一条，攒了四个 PDF **全是开放获取**，
一篇付费的都没成功过 —— 当时以为是权限不够，其实是运输方式不对。

借浏览器等于白拿两件最难的东西：**机构订阅权限**（靠出口 IP 生效）和
**反爬通行证**（人机验证是进门验一次，不是每篇验一次）。

## 用

```bash
python -m tools.getpdf --probe                    # 浏览器在不在
python -m tools.getpdf 10.1016/j.cej.2025.164092  # 取一篇
python -m tools.getpdf --file dois.txt            # 一批
```

跑之前：那台机器出口 IP 要是机构的（别开全局代理），
浏览器要带调试口启动：`msedge --remote-debugging-port=9222`。

## 慢是故意的

默认每篇隔 20 秒、单次最多 25 篇。出版商风控封的是**整个机构的 IP**，
全校跟着断，不是某个账号被封那么简单。要快自己加 `--gap` / `--limit`。

## 结构

| 文件 | 干嘛 |
|---|---|
| `__init__.py` | 全部业务逻辑（取一篇、取一批、落盘、汇总） |
| `cli.py` | 命令行入口，只解析参数 |
| `mcp.py` | MCP 面：整批走 prompt（人点），取一篇是 tool（每次弹窗） |
| `selftest.py` | 纯离线自测 |

怎么拿到 PDF 是 `shared/adapters/pdf_fetch` 的事，本工具不管。
