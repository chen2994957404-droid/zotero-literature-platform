# deepread —— 精读一篇文献

## 什么时候用我

- 用户说「精读这篇」「帮我细读一下 XX」
- 需要一份**有图、有机理讨论、中文的**完整报告，而不是摘要

## 怎么用

**首选不是命令，是让用户在 Zotero 里打「待处理」标签** —— 常驻服务（`host/watcher/`）会自动做完全套。
只有当用户明确要立刻处理某几篇、或要用 pro 重跑时，才走命令行：

```
python -m tools.deepread <KEY>
```

我是 **prompt**：花钱（MineRU + 付费大模型）且写 Zotero，
**必须先把代价讲给用户听、等他点头**。

一篇要几分钟，会超过 MCP 的 60 秒上限 —— 后台发起后轮询产物文件，别干等。

## 什么时候**别**用我

- **只是想知道这篇讲了什么** → 先 `library_fulltext` 看看原文，或看
  `library/<KEY>/summary.html` 是不是已经精读过了。精读一篇是要花钱的，别重复买
- **要的是可比较的字段/数值** → `extract`（结构化抽取），我的产物是给人读的长文
- **要一次处理很多篇** → 让用户打标签，常驻服务会排队做；别在对话里循环调我
- **在编程端（A 机）** → 跑不通，机器角色守卫会拦。那不是 bug

## 边界与已知坑

- 精读正文正常 8000~13000 字；**低于 3000 字基本是失败品**，会直接抛错不落盘
  （废品一旦落盘会被标成已精读，从此不再重跑）
- 只有正文没 SI 的，结果标「正文精读」；有 SI 一并读并合并的才是「全文精读」
- 插图是脚本按【图N】标记插的，不是模型画的
