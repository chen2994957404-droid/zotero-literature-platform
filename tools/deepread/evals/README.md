# deepread 的评测

**回答的问题：精读跑出来的东西好不好？**（体检回答的是「能不能跑」，那是两件事。）

## 三样东西

| 位置 | 是什么 |
|---|---|
| `scorers/quality.py` | 客观指标（纯函数）：字数 / 图数 / 带单位数值的密度 / 栏目完整性 |
| `thresholds.toml` | 阈值的唯一出处：废品线 3000 字、校准所需的最少样本量 |
| `golden/` | 目前空着（原因见里面的 README）——真正的金标是用户的人工评价 |
| `__init__.py` | 评价存储：一条评价 = 好/差 + 原因 + 备注 + **当时的客观快照** |

## 为什么每条评价都要带快照

单纯收集「好/差」是一次性的：改完精读逻辑重跑后，没人给新版本打分。

**真正的目的是用用户的主观评分，校准出一个系统能自动算的质量分。**
好、差各攒够 `thresholds.toml` 里的样本量，就能看出「他说好的」和「他说差的」
在客观指标上差在哪 —— 差异显著的那个指标，才是能拿来自动判质量的候选。

改这块之前请先确认这个目的还成不成立，别把它退化成一个评分收集器。

## 数据在哪

`data/state/evalset.json`，原子写入。
**不可重建**，有架构守卫盯着它必须留在版本库里。

## 用户怎么评

在 Zotero 给读完的文献打「读完」标签 → 控制面板的「精读评价」卡片里就会出现，
可直接打开精读、就地评好/差。**评价刻意不回写 Zotero** ——
他的标签栏永远只有「在读 / 读完」两个（他被 707 个自动标签坑过）。

## 改完必须做

```
python -m pytest tools/deepread -q
python host/doctor/health_check.py --offline
```

## 金标评测（2026-09-15 起）：对着人写的范文自动打分

`scorers/golden.py`（纯函数）+ `golden.py`（跑法）。标尺是 774 对高分子学人范文
（`paths.reference()`）。每轮一个 tag，产物在 `data/state/golden_eval/<tag>/`：
每篇一份精读 HTML（**不碰 curated 的正式精读**）+ `scores.json` + `report.md`。

```
python -m tools.deepread --金标评测 --tag v3_local --篇数 10 --本地 --对照
python -m tools.deepread --金标重算 v3_local        # 只改了评分口径
```

量的：骨架 10 项 / 图两段 / 篇幅比 / **数字覆盖**（范文里带单位的数我们写了几成）/
术语覆盖 / 两问条数 / 通俗理解；综合分 0–100 只用来排序看趋势，**单项才指导改什么**。
同一个 `--seed` 永远抽同一批，换模板或换模型就换 tag 再跑，两份 report 并排看。
