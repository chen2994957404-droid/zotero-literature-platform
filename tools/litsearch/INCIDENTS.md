# litsearch 踩过的坑

还没有。

这个文件先占着位置 —— 下次踩到坑的人有地方写，不用先想「该记哪儿」。

写的时候照这个格式：

```
## 现象
（用户或调用方看到的是什么）

## 根因
（真正的原因，不是第一反应）

## 解法
（改了什么，以及为什么这么改）
```

全局的坑记在 `docs/incidents/踩坑记录.md`（编号连续，新增前先
`grep "^## " 看真实最大号`）；本工具特有的同时写这里。

---

## 建这个工具时已经知道的两个雷（不是坑，是预先记下的判断）

1. **别在这里加排序。** 排序要向量库 + 本地模型，算不出来时会静默退化成
   「按被引量排」（见全局踩坑 #149）。一份看起来排过、其实跑偏的清单，
   比不排更坏。要排序去 `tools/discover`。
2. **别让这个包沾上花钱或写库。** 一旦 `tool.toml` 里 `costs_money` 变 true
   或 `side_effects` 非空，守卫就会要求它注册的每个 tool 都弹窗确认，
   对抗式检索一轮十几次调用会被弹窗淹死 —— 这个工具存在的理由当场消失。
