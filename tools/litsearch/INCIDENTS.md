# litsearch 踩过的坑

## 语义检索与摘要的三个实测坑（2026-09-26，全局踩坑 #188）

**现象**：① 拿一篇摘要当 `lit_semantic` 的输入，OpenAlex 回 400；② 按年切 3 片 × 3 条输入串行跑了 62 秒，
超过 MCP 约 60 秒的超时；③ 一次语义检索 50 条里混进 5 条「Review for "…"」审稿意见记录；
另外精确检索结果里约 1/3 没摘要，集中在 Elsevier。

**根因**：① 官方文档写「只用前 2000 字」，实际**超过 1500 字直接 400**；② 单次语义检索 5–8 秒；
③ Crossref 的 peer-review 类型也进了 OpenAlex；Elsevier 不向 Crossref 交摘要，下游都拿不到。

**解法**：适配器先截到 1500 字并标 truncated；`openalex.semantic_many` 错开 1.1 秒并发（官方限速每秒 1 次），
一次调用最多 8 次；语义检索默认 `type:!peer-review`；结果标【无摘要】，`lit_abstract` 退到证据库原文、S2。

## 建这个工具时已经知道的两个雷（不是坑，是预先记下的判断）

1. **别在这里加排序。** 排序要向量库 + 本地模型，算不出来时会静默退化成
   「按被引量排」（见全局踩坑 #149）。一份看起来排过、其实跑偏的清单，
   比不排更坏。要排序去 `tools/discover`。
2. **别让这个包沾上花钱或写库。** 一旦 `tool.toml` 里 `costs_money` 变 true
   或 `side_effects` 非空，守卫就会要求它注册的每个 tool 都弹窗确认，
   对抗式检索一轮十几次调用会被弹窗淹死 —— 这个工具存在的理由当场消失。
