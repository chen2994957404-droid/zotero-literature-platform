# paperdb —— 查抽取出来的结构化数值

## 什么时候用我

- 用户要**比数字**：「拉伸强度超过 10 MPa 的有哪些」「自修复效率最高的几篇」
- 用户要**看覆盖情况**：「哪些篇有合成条件但没有性能数据」「精层抽了多少篇」
- 你要做横向关联分析、找「机理 × 性能」的空白格

只读、免费、秒回，你可以自己调。

## 怎么用

| 工具 | 用途 |
|---|---|
| `paperdb_find` | 按关键词 / 档次 / 某字段有值 / 性能数值范围筛 |
| `paperdb_stats` | 有多少篇、各字段有值率（**先看这个再下结论**）|
| `paperdb_props` | 抽到过哪些性能名、各多少条、范围多大 |
| `paperdb_sql` | 复杂查询自己写 SQL（只接受 SELECT / WITH）|

用 `paperdb_props` 先看性能名怎么写的，再拿去 `paperdb_find`：
性能名是从原文里抽的，不是我们规定的枚举，猜名字十有八九筛出空。

## 什么时候**别**用我

- **筛完要写进库** → 不行，我是只读的；数据要改就去改 `structured/<key>.json` 再 rebuild
- **想读整篇内容 / 摘要 / 机理讨论** → 我只有结构化字段；正文去 `library_fulltext`，
  中文精读报告在 `library/<key>/summary.html`
- **库里没有这篇** → 先 `extract` 抽（花钱），或先让用户精读它
- **要跨单位比较**（MPa vs kPa）→ 我**故意不做单位换算**。把单位一起筛，
  或者自己换算并说清楚，别默认数字可以直接比大小
- **一句话的综合回答** → `ask`

## 边界

- 数值拆自「人话字符串」，拆不出数字的记录 `value` 是 NULL —— `min_value` 筛不到它们
- `tier`（精层/粗层）差别很大：粗层来自 Zotero 全文索引 + 本地小模型，
  **只适合粗筛**，下结论前先看 `paperdb_stats` 里那一档的有值率
