# paperdb 的评测

**回答的问题：查询返回的东西对不对？**（体检回答的是「能不能跑」，那是两件事。）

## 现状：**已经填好了**（2026-09-01）

`golden/queries.json` 里 4 条造出来的记录 + 9 个用例，`scorers/query_match.py`
负责判分，`tests/test_evals.py` 负责跑。**全离线、不花钱、秒级，默认就跑。**

覆盖的都是容易出错的地方：单位混用（kPa 不会被当成 MPa）、区间值按下界入库、
`N/A`/`未提及` 不算有值、综述与研究论文分得开、只读闸门拦不拦得住。

## 再加用例

往 `golden/queries.json` 的 `cases` 里加一项即可，**不用改任何 .py**。
每条必须写 `why` —— 有测试在查这件事：**说不清为什么要验，就说明这条不值得验。**

## 三样东西各放什么

| 位置 | 放什么 |
|---|---|
| `golden/` | 金标输入 + 期望产出（一个案例一个文件，文件名说清它验的是什么）|
| `scorers/` | 评分器：**纯函数**，拿到产出就能打分，不需要联网也不需要真实数据 |
| `thresholds.toml` | 阈值的唯一出处 —— 别在 .py 里再写一遍数字 |

跑评测的测试写在 `../tests/` 里（`tools/paperdb/tests/test_evals.py`），
参照 `tools/deepread/tests/test_evals.py` 的写法。
