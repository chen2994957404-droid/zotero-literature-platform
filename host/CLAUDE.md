# host · 平台自身 —— 给 LLM 的说明

> 你可能是被单独选中这个文件夹打开的，看不到项目其他部分。本文件是你的全部上下文。

## 这个文件夹是什么

**不是能力，是让平台活着的东西。** 判据就这一句：
能力（精读、抽取、问答…）住 `tools/`；面板、体检、部署、协议层、常驻服务住这里。

依赖方向上它在最上层：**`host/` 可以 import 一切，但没人可以 import `host/`**
（REBUILD.md 第三节硬规则 4，有守卫）。所以**跨工具的编排属于这里** ——
工具之间不许互相 import，要把两个工具串起来，那件事就是 host 的活。

## 六块各干什么

| 块 | 干什么 | 用户怎么碰到它 |
|---|---|---|
| `panel/` | 控制面板（本地网页）—— 用户与整个系统的交互入口 | 双击 `launch/控制面板.bat` |
| `doctor/` | 一键体检 + 诊断报告 + 产物缺口 | 双击 `launch/诊断报告.bat` |
| `deploy/` | 拉新代码 + 装包 + 重启服务；数据搬家 | 双击 `launch/更新平台.bat` |
| `watcher/` | **常驻服务**：盯 Zotero 标签 → 精读 → 抽取 → 回写 → 改标签 | 打个标签，剩下不用管 |
| `mcp/` | MCP 协议层：读各 `tools/*/tool.toml` 聚合暴露面 | 在 Claude 里直接用工具 |
| `codegen/` | 所有生成器：`HANDOVER.md` · `.claude/` · `docs/incidents/` | 不直接碰 |

## panel 的设计铁律

**面板里一行业务逻辑都不许写。**

它只是「现有能力的视图 + 遥控器」：状态取自 `doctor` 的检查函数，
配置取自 `shared.kernel.config`，进程取自系统查询。
在面板里另写一套判断，就会出现「面板说正常、体检说异常」两套真相。

要加新功能：**先把能力做成工具或共用件，再让面板调用它。**

### 面板的能力边界（刻意划的线）

- **可做**（可逆、零风险）：看状态/进程/日志/最近处理记录；改密钥与模型；重启后台服务
- **不可做**（不可逆或花钱）：删数据、全库重抽、改 Zotero 库、触发批量精读

理由：面板上一个按钮点错的代价，远大于用户多问一句的成本。**新增按钮前先按这条尺子量。**

### 新增给用户用的东西时

**用户在主力机上只有一个动作：双击。** 所以新写的诊断/维护脚本，
优先**并进 `doctor/report.py`**（用户已经会用，那份报告的设计目标就是「一次给全」），
其次做成面板按钮，最后才考虑往 `launch/` 加 .bat。

**绝不要说「在终端里跑 `python xxx.py`」** —— 双击 .py 窗口一闪而过，
用户什么也看不到（真实发生过）。

### 安全约定

只绑 `127.0.0.1`；密钥只显示后 4 位；输入框留空表示「不改动」而非「清空」；
每次保存自动备份旧 `.env`。

## doctor 的两档设计

```
python host/doctor/health_check.py --offline   # 离线档：包安装/离线测试/语法/静态检查
                                               #   ← 不依赖任何外部服务，必须永远全绿
python host/doctor/health_check.py             # 完整档：另加配置、Zotero、Ollama、
                                               #   自测、数据资产、后台服务
                                               #   ← 本机没配密钥/没开服务就会红，属正常
```

**为什么分档**：分档之前默认是「8 通过 / 5 警告 / 1 失败」，而那 6 项红黄全部只是
「这台机器没配密钥、没开服务」—— 噪音盖住了真信号，于是没人再认真看体检结果。
分档之后，「离线档必须全绿」成了一条真正可执行的红线。

**运行时导入检查比语法检查更重要**：语法过 ≠ 能跑（踩坑 #49）。
另有「关键入口找不到」检查 —— 按**模块名**查，不按文件名（踩坑 #81：搬家会静默失效）。

## watcher：两个进程，别搞混

`service.py` 是轮询器本体，`watchdog.py` 是看门狗（**只在它真死了才重启，
绝不打断正在干活的它**）。计划任务拉起的是看门狗，service 是它 spawn 的孙子进程 ——
所以停任务停不掉 service（踩坑 #62）。找进程要认**模块路径**，只认单个词会出事
（看门狗自己的命令行里也有 "watcher"，会把自己杀掉）。

## mcp：清单驱动，没有硬编码的工具名

加一个工具 = 建一个 `tools/<新名>/` 放上 `tool.toml` 与 `mcp.py`，服务下次启动就有了。
`registry.check()` 强制那条安全铁律：**花钱或有副作用的，不许注册成 `tool`**
（tool 是模型能自己调的，等于把钱包交给模型，踩坑 #86）。

## codegen：靠人记得更新的文档一定会过时

所以凡是能从系统真实状态抓出来的，一律生成：

```bash
python host/codegen/handover.py     # HANDOVER.md + AGENTS.md 的结构树
python host/codegen/skills.py       # .claude/skills/ 与 .claude/rules/（手写即违规，有守卫）
python host/codegen/incidents.py    # docs/incidents/README.md（坑的总目录）
```

## 依赖

只依赖 `shared/`（`config` / `paths` / `role` / `subproc` / `log`…）与各 `tools/`。
要改共用件，请让用户改选 `shared/<层>/<积木名>` 文件夹。

## 改完怎么验证

```
python -m pytest -q                           # 离线测试 + 架构守卫，应全绿
python host/doctor/health_check.py --offline  # 离线档，应 10 通过 0 警告 0 失败
python host/doctor/health_check.py            # 完整档（本机没配服务会有黄，正常）
python host/mcp/server.py --list              # 三类暴露面齐全且与各 tool.toml 自洽
python host/panel/app.py --no-browser         # 然后访问 http://127.0.0.1:8777/
```

改面板后务必真的打开页面点一遍，别只看代码。
