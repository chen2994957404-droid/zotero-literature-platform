# domain · 纯逻辑环 —— 给 LLM 的说明

> 你可能是被单独选中这个文件夹打开的。本文件是你的全部上下文。

## 判据：什么东西该放这里

**只有「我们自己想法变了」才需要改的代码。** 外部世界怎么变都影响不到它。

裁图的坐标换算、SI 正文的分档规则、结构化抽取的 schema、精读 HTML 的排版模板
—— 这些十年不变，是宪法【首要判据】判定为「自己做、要完全掌控」的部分。

反过来：**只要它会因为「某个 API 换版本了/某个模型换代了」而改，它就不属于这里，
属于 `adapters/`。**

## 三条禁令（`tests/test_architecture.py` 强制，违反了 pytest 立刻变红）

```
❌ 不许联网（urllib / requests / httpx / socket）
❌ 不许 import 数据库或外部服务客户端（chromadb、keyring），不许起子进程
❌ 不许 import core.paths
```

**第三条最容易被忽略，但它才是关键**：domain 永远不知道文件放在哪，
路径一律由调用方传进来。一旦 domain 知道了 `workflow_data` 的布局，
它就跟我们的数据组织方式绑死了 —— 既不能独立测试，也不能被复用，
而且改一次目录布局就会波及本该最稳定的一层。

## 现有成员

| 块 | 是什么 |
|---|---|
| `figure_crop` | 按 layout.json 的坐标从原 PDF 裁出**完整 Figure**（不用解析器的碎图，见踩坑 #7）|
| `si_filter` | SI 全文里挑出实验细节、丢掉噪声。**重点是不误杀**（曾把 `Mw = 4200 g/mol`、¹¹B NMR 当作者名单丢掉）|

规划中：`schema`（结构化抽取字段 + 版本号）、`render`（精读 HTML 模板）、
`prompts`（提示词按版本存文件）—— 见 `docs/架构重构_v2总体设计.md` 第二节。
把这三样搬进来之后，「改精读排版」「改提示词」就都变成改一个文件、代码零改动。

## 允许的例外

`figure_crop` 依赖 PyMuPDF 读传入的 PDF。坐标换算这件事十年不变，
PyMuPDF 只是它的计算工具，不是它要适配的外部世界 —— 所以它留在 domain。

## 为什么这一环值钱

它是唯一能**全离线、毫秒级**跑单元测试的一层。整个安全网的地基就在这里：
`domain` 越厚，能被快速验证的逻辑就越多，重构就越不吓人。
