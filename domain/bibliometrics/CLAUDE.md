# bibliometrics · 文献计量纯逻辑 —— 给 LLM 的说明

## 是什么

**输入一堆论文和它们的引用，输出「这个领域长什么样」。** 属于 domain 环：
不联网、不知道文件放在哪，输入输出都是纯 Python 数据结构。

用它的是 `pipelines/direction_map`（方向地图）。

## 为什么在 domain 而不是 pipelines

文献耦合、Louvain、IDF 加权、时间分桶 —— 这些**只有我们自己想法变了才需要改**，
外部世界怎么变都影响不到（OpenAlex 换 API、微信关接口，都不碰这里一行）。
符合 domain 的判据。

## ⚠ 三条实测结论，别再推翻重试（2026-08-28/29）

### ① 簇「塌成巨块」是算法分辨率问题，不是数据脏

标签传播在 754 篇上会塌成 67 篇 / 53 篇的巨块，主题纯度只有 0.30。
换成带 `resolution` 的 Louvain 后同样数据得到 36 个簇、纯度 0.48。

**当时我把顺序做反了**：先怀疑数据脏（工具论文污染），折腾三轮过滤判据都无效，
最后发现换算法一步到位。**先确认算法能给出合适粒度，再去怀疑数据。**

### ② 自动识别「通用工具论文」的判据试了三个，全部失败

| 判据 | 为什么失败 |
|---|---|
| 全球被引 >= 2 万 | 轴选错：关键那篇工具只有 4688 次引用；而真地基（聚多巴胺 10890 次）差点被误伤 |
| 引用者主题熵高 | 指标饱和：211 篇被分成 69 个细粒度主题，任何被 7 篇引的文献熵都是 0.98，于是把 Leibler vitrimer、Gong 聚两性电解质全判成「工具」 |
| 参考文献自身学科不在语料里 | OpenAlex 学科归类噪声太大：大豆蛋白胶归到「营养学」、水凝胶电极归到「神经科学」 |

**所以 `DEFAULT_TOOL_PATTERNS` 是一份显式手工清单。**
判据：小、稳定、众所周知的集合，手工清单胜过任何启发式。

⚠ 清单按标题正则匹配，**实测会误伤**（一篇硫辛酸共聚物被 `density functional` 撞上）。
有稳定 id 时优先用 `exclude=` 显式传 id。

### ③ IDF 已经中和了「被所有论文都引」的文献 —— 工具问题只在「被一部分引」时才咬人

相似度用 `log(n/df)` 加权，`df == n` 时权重直接归零。
所以「全员都引同一批工具」根本粘不住。
真实的假簇成因是工具被**少数**论文共引（Multiwfn 是 754 篇里的 14 篇，IDF 权重很高）。

**这条第一版自测就栽过**：构造了「15 篇全引工具」的语料，怎么都复现不出假簇。
现在的自测直接断言矩阵事实（`S(a0,b0) > 0`），不依赖 Louvain 的判断 ——
用下游涌现行为当断言，会得到一个时灵时不灵的测试。

## 一个反直觉的设计：不按模块度挑分辨率，按主题纯度挑

实测里分辨率调高会让**模块度下降、主题纯度上升**：

```
res=1.5  模块度 0.344  簇 22  纯度 0.42
res=3.0  模块度 0.263  簇 36  纯度 0.48   ← 采用
```

模块度只回答「图切得整不整齐」，主题纯度用的是**外部**标签（OpenAlex 主题），
与我们的聚类完全独立，才能回答「簇是不是真有意义」。
`best_partition()` 因此按纯度挑，并把每一档都报出来 ——
「为什么选这一档」应该看得见，不该是代码里的魔数。

## 接口

```python
from domain import bibliometrics as bib

tools = bib.tool_refs({ref_id: 标题})                    # 通用工具清单
keys, S = bib.coupling_matrix(refsets, exclude=tools)    # IDF 加权文献耦合
labels, report = bib.best_partition(S, keys, topic_of)   # 扫分辨率挑最好的
groups = bib.groups_of(keys, labels, min_size=5)
bib.purity(groups, topic_of)                             # 客观质量指标
bib.top_shared(refsets, min_df=3)                        # 地基清单
bib.half_year('2026-05-13')                              # → '2026H1'
bib.direction([1, 1, 5, 5])                              # → '↑↑'
```

⚠ `trend()` / `direction()` 的调用方要自己记得：**最后一个半年可能不满半年**
（比如 2026H2 只有 7、8 两个月），直接拿它比会得出「在下降」的错觉。

## 依赖

numpy + 标准库。**没有 sklearn / networkx / igraph** —— Louvain 和模块度都是本地实现，
几百到几千个节点用不着那些依赖，而且省掉它们让这一环能在任何机器上离线跑。
