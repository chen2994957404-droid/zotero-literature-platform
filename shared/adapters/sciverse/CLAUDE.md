# sciverse · 全球文献库

> 你可能是被单独选中这个积木文件夹打开的，看不到项目其他部分。本文件是你的全部上下文。

## 这是什么

**一块「公理件」** —— 平台的最小可复用单元。
公理特征：只做一件不可再分的事，这里是「查询全球科学文献并拿回结构化结果」。

用户是材料方向研究者（聚硼硅氧烷/动态键弹性体），**不懂编程**。

## 职责

封装 OpenDataLab **Sciverse**（科研 Agent 的可信证据数据层）：
4.55 亿条记录、3000 万篇 AI-Ready 全文。它**只返回带出处的证据，不生成答案** ——
生成由上层负责，这正是「可追溯」的前提。

## 对外接口

| 函数 | 用途 |
|---|---|
| `available()` | 是否已配密钥。上层据此决定走不走这条路，而不是直接报错 |
| `search_papers(query, limit, year_from, prefer)` | 主题检索元数据。prefer: relevance/impact/fresh/citations |
| `ask_evidence(question, top_k, year_from)` | 拿回可引用的原文片段（含标题、页码、相关度） |
| `paper_relations(unique_id, relation)` | 引用脉络。CITATIONS / REFERENCES / RELATED_WORKS |
| `read_content(doc_id, offset)` | 按 doc_id 读全文上下文 |
| `clean_chunk(text)` / `looks_chinese(text)` | 片段清洗 / 中文检测 |

## ⚠ 最重要的一条（实测教训）

**检索式必须用英文。**

Sciverse 会按 query 的语言做亲和加权。中文问「聚硼硅氧烷的剪切硬化机理」，
召回的是**硼硅玻璃辐照、炉渣、LTCC 陶瓷** —— 含「硼」但方向完全无关，相关度只有 0.35~0.5；
同一问题用英文问，8 条证据相关度**全部 0.89 以上**，且全部对口。

原因：材料领域的高质量文献绝大多数是英文。
所以上层（`库内问答/ask_world.py`）会先把中文问题转成英文检索式再查。
这也符合项目语言约定：**机器用的中间数据用英文，给用户看的用中文。**

配套：调用方应过滤低相关度片段（建议阈值 0.60），宁可少给几条，
也不要拿跑题片段污染答案。

## 为什么要包这一层（关键设计判断）

Sciverse **尚处公测**（官网写着「抢先体验新接口与公测计划」），接口会变。

按架构宪法的首要判据：**发展中的东西可以用现成的，但必须把变化隔离在稳定接口背后。**
上层只认本模块这几个函数；哪天官方改了字段名或路径，只修这里，上层一行不动。

## 其他注意

- 限流默认 **30 次/分钟**，本模块对 429 自动退避重试（批量补库时撞限流是必然事件）
- 返回的 chunk 混着 MinerU 风格的图片占位符 `![](...)`，`clean_chunk` 负责清掉
- 年份字段实测会返回 `2022.0` 这种浮点，也可能为 None，已统一归一
- `unique_id`（形如 `paper:10.xxxx/yyy`）与 `doc_id`（sha256）**不能混用**：
  查引用关系用前者，读全文用后者
- 密钥 `SCIVERSE_KEY` 在控制面板填写，存系统凭据库

## 谁在用它

`找新文献/search_global.py`（搜全球并标出库里已有）、
`库内问答/ask_world.py`（问全世界，带出处的中文回答）。
