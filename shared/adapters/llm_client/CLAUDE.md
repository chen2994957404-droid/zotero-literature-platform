## 这是什么

**一个原子模块** —— 平台的最小可复用单元。整个项目的架构是：
原子模块（原子能力）→ 工作流（工作流）→ 组合。你现在在最底层。

**原子模块的特征：只做一件不可再分的事。** 如果你想在这里加一个「顺便还做 XX」的功能，
那说明 XX 属于上层，不属于这里。保持这块的纯粹，是整个体系不腐坏的前提。

用户是材料方向研究者（聚硼硅氧烷/动态键弹性体），**不懂编程**。
技术决策你自己拿主意，跟他汇报用通俗表述。

## 职责

给 messages，返回模型输出。仅此而已。

## 对外接口

| 函数 | 用途 |
|---|---|
| `chat(system, user, ...)` | 纯文本输出（精读、问答） |
| `chat_json(system, user, ...)` | 强制 JSON 并解析成 dict（结构化抽取） |
| `chat_vision(system, user, image_b64, ...)` | 看图（图表数字化） |

**2026-09-11 起推荐只传 `purpose`**（如 `chat(..., purpose='DEEPREAD')`）：
走哪条通道、用哪个模型、备用是谁，由 `shared.kernel.config.routing` 的两张表决定，
主用失败且「换条路可能有救」（额度用光 / 鉴权失败 / 连不上）时自动切备用。
`provider / model / key` 三件套是老路，仍可用，但那是兜底不是主路。
`purpose` + `model` 同时给 = 走该用途的通道、但用指定模型（「用 pro 重跑」就是这么用）。

用途 id：`DEEPREAD` `EXTRACT` `ASK` `AUTOTAG` `BRAINSTORM` `DIRECTION_QUAD` `DIGITIZE`。

## 实测教训教训（都是真实事故）

1. **DeepSeek V4 思考模式默认开启，推理链 token 计入 max_tokens。**
   给小了会导致正文被截断甚至空输出。`chat()` 有 `thinking` 参数可关闭；
   已加保护：`finish_reason=='length'` 且正文过短时直接抛错，**不静默返回半截**。
2. **必须有 5xx/429 退避重试**（已实现：4 次，5s/10s/20s）。
   批量任务跑几小时，撞上一次服务端抖动是必然事件，没重试就白跑一篇。
   **4xx 立即抛错**（是我们自己的错，重试没意义）。
3. 判别技巧：**4xx 是我们的错，5xx 是对方的错。** 这条能省掉大量「怀疑自己代码」的时间。

## 模型选择原则

**输出少的活用 pro（准），输出多的用 flash（省）。**
flash 与 pro 规格相同（1M 上下文、384K 输出），pro 贵约 3 倍、并发只有 1/5。
