# query_expand · 检索式扩展

> 你可能是被单独选中这个积木文件夹打开的，看不到项目其他部分。本文件是你的全部上下文。

## 这是什么

**一块「公理件」**：一个研究问题 → 多个互补的英文检索式。

用户是材料方向研究者（聚硼硅氧烷/动态键弹性体），**不懂编程**。

## 为什么存在（这块解决的是「搜不全」）

用户反馈平台找文献「有点局限不太全面」。根因**不是检索引擎不好，是单一查询的固有局限**：
材料领域同一个东西有太多叫法 ——

> polyborosiloxane / PBS / boron-siloxane / borosiloxane elastomer /
> silly putty / shear stiffening gel / dilatant compound …

只搜其中一个词，就必然漏掉用别的词写的那批文献。

**实测证据**：搜「polyborosiloxane shear stiffening」，单查询取回约 20 篇；
扩展成 4 个检索式后合并去重得 **45 篇**，且每一式都新增 10~12 篇 ——
**说明单查询漏掉了近 70%。**

这也是前沿文献检索 Agent（PaperPilot、PaSa、SPAR）的共同第一步：
先把研究问题拆成领域概念与术语变体，**而不是拿用户原话直接去搜**。

## 对外接口

| 函数 | 说明 |
|---|---|
| `to_english(q)` | 中文问题 → 英文检索式；已是英文则原样返回 |
| `expand(q, mode, n)` | 产出 n 个互补检索式，**第一个永远是原式** |
| `looks_chinese(t)` | 是否含中文 |

## 两种模式（对应两类真实需求）

| mode | 场景 | 策略 |
|---|---|---|
| `survey`（默认） | 摸清一个方向 | 求**全**：术语变体、同义词、上位/下位概念、邻近领域叫法 |
| `problem` | 解决手头问题 | 求**准**：现象、机理、已知解法、性能指标、典型体系 五个角度 |

实测 `problem` 模式对「材料常温流动怎么解决」拆出了
**cold flow / creep / shape retention additive** 等角度 —— 这些是用户自己未必想得到的切入点。

## 两条设计约束（改的时候别破坏）

1. **第一个检索式永远是原式**（转英文后）。保证不会因为扩展跑偏而丢掉用户本来想搜的。
2. **LLM 不可用时降级为只返回原式**，功能变弱但不失效。

## 为什么必须转英文

Sciverse 等按 query 语言做亲和加权。中文问「聚硼硅氧烷的剪切硬化机理」
召回的是硼硅玻璃辐照、炉渣、LTCC 陶瓷（含「硼」但方向无关，相关度 0.35~0.5）；
同一问题英文问，相关度 0.97 且全部对口（踩坑 #35）。

符合项目语言约定：**机器用的中间数据用英文，给用户看的用中文。**
