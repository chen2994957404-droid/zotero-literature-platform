# 库房维护 · 给 LLM 的说明

> 你可能是被单独选中这个文件夹打开的，看不到项目其他部分。本文件是你的全部上下文。

## 这个文件夹是什么

打理 Zotero 库本身：标签、元数据、命名、去重、同步。
**这里的脚本大多会直接修改用户的 Zotero 库，属于有副作用的操作。**

用户是材料方向研究者，**不懂编程**。

## ⚠ 最重要的一条规矩

**任何会删除数据或修改 Zotero 库的操作，动手前必须先跟用户说清代价并得到确认。**
可还原、零成本的（只读检查、列清单）可以自己跑。

理由：这些操作不可逆，且会通过 Zotero 同步扩散到用户所有设备。

## 各文件职责

| 文件 | 干什么 | 危险度 |
|---|---|---|
| `auto_sync.py` | 定时同步/保活（开机自启任务 LiteratureAutoSync 用它） | 低 |
| `autotag.py` | 用大模型给文献自动打标签 | 中（会改库） |
| `backfill_meta.py` | 补全缺失的元数据 | 中 |
| `zotero_rename.py` | 规范化附件命名 | 中 |
| `tag_to_nested.py` | 标签转成层级结构 | 中 |
| `list_junk.py` | **只列不删**，看看有哪些垃圾条目 | 低（安全） |
| `delete_junk.py` | 真删 | **高，必须先问用户** |

排查问题时优先用 `list_junk.py` 看清楚，别直接上 `delete_junk.py`。

## 依赖

- **积木**（`../modules/`）：`zotero_client`、`llm_client`、`config`
- 需要 `ZOTERO_API_KEY`（写权限）和本机设置 `ZOTERO_USER_ID`

## 血泪教训

1. **自动打标签会失控**。曾经自动生成了 707 种标签，用户一个都没打，最后全清了，
   只留「待处理/正文精读/全文精读/无附件」等有用的状态标签。
   再做自动标签要非常克制，先跟用户确认标签体系。
2. **别「先删再建」**。删除动作进同步链会导致 Zotero 反复弹冲突框，
   正确做法是复用已有条目、只改内容。
3. Zotero 桌面程序必须开着，本地 API（`localhost:23119`）才通。

## 改完怎么验证

```
python ../平台管理/health_check.py     # 含 Zotero 服务连通性检查
python list_junk.py                   # 只读，安全
```
