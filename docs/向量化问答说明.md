# 向量化 & 问答系统 · 说明

> 让你的整个文献库变成"能懂内容的智能搜索"。用大白话提问,从全库找答案。

## 是什么

把文献文本"翻译"成数字向量存进向量库,提问时找出最相关的内容片段,用大模型综合回答。这就是 RAG(检索增强生成)。

## 两种向量化(可共存于同一个库)

| 方式 | 脚本 | 文本来源 | 用途 | 占空间 |
|------|------|---------|------|--------|
| **轻量全库** | `vectorize_library.py` | Zotero全文API | 广撒网,全库可搜 | 极小(139篇=86MB) |
| **精读高质量** | `vectorize.py` | library里的full.md | 精读过的文献,质量更高 | 极小 |

**推荐用法**:先用轻量全库把所有文献铺进去(广度),精读过的再用高质量版覆盖(深度)。

## 日常使用

### 提问
```
python scripts\ask.py "你的问题"
```
或不带问题进入连续问答模式:
```
python scripts\ask.py
```
回答会附上参考来源文献和DOI。

### 加入新文献
```
python scripts\vectorize_library.py    # 增量,只处理还没入库的
```
以后 Zotero 里导入新文献后,跑一次这个就把新的加进可搜索库。

### 重建(换了切块规则/模型时)
```
python scripts\vectorize_library.py --rebuild
```

## 技术组成(都本地免费)

- **embedding模型**:bge-m3(本地Ollama,1024维,中英都强)
- **向量库**:Chroma(本地文件,`workflow_data/vector_db/`)
- **回答模型**:deepseek-v4-flash(检索到内容后综合成答案)
- **切块**:按段落切,约800字/块,自动过滤参考文献部分

## 关键设计

- **过滤参考文献**:向量化时自动截掉 References/参考文献 部分,让检索聚焦正文方法和数据(不然会命中一堆文献列表标题)。
- **文本来源用Zotero全文API**:不解析PDF、不存图片,所以几乎不占空间。Zotero自己已把每篇PDF的文字提取好了,直接取用。
- **增量入库**:已入库的跳过,只处理新文献。
- **与精读解耦**:向量化(轻、免费、全库)和精读(重、花钱、精选)分开,互不依赖。

## 为什么不怕换工具(呼应数据契约)

向量库只是原始数据的"索引副本"。换向量库、换embedding模型,都只需拿同样的数据源重新跑一遍,**原始文献数据零风险**。所以放心用、放心以后升级。

## 常见问题

- **问答说"没找到"**:该内容可能没在向量库里(文献没入库,或被参考文献过滤了)。跑 `vectorize_library.py` 确认文献已入库。
- **要Zotero开着**:向量化和问答都要 Zotero 开着(取全文/元数据)。问答的检索本身不用,但取来源信息时会用到。
- **占空间会不会涨**:向量极小,一篇约0.4MB,一千篇也才400MB。真正占空间的是精读的MineRU解析产物(20-30MB/篇),那个只给精选文献,数量少。
