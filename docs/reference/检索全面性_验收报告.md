# 检索全面性改造 · 验收报告（2026-09-26）

> 规划：`检索全面性_改造规划.md` ｜ 调研：`检索全面性_前沿调研.md`。
> 本份回答三件事：新做法比旧做法强多少、换个弱模型还成不成立、剩下的短板在哪。

## 怎么测的

- **标准集**：三篇 2026 年综述，取它们 2020 年后的参考文献（外部来源，不是我标的）：
  - 练习集：聚硼硅氧烷剪切增稠凝胶防护材料综述（`10.1002/pen.70849`），53 篇
  - 考卷 1（相邻方向）：聚烯烃 vitrimer / 化学升级回收综述（`10.1146/annurev-matsci-072924-115520`），54 篇
  - 考卷 2（完全无关）：植物微针递送综述（`10.1016/j.tplants.2026.04.009`），44 篇
- **去掉背景引用**：综述会引大量背景（塑料产量统计、化肥与土壤……），按主题检索本来就找不到。
  由一个**没看过任何检索结果**的 agent 按范围约定把标准集分成「在范围内 / 背景 / 拿不准」，
  在范围内的：30 / 32 / 12 篇。下文召回都按「在范围内」算
- **检索者**：子 agent 扮演用平台的 agent，只拿到问题 + 范围约定（模拟「已问过用户」），看不到标准集，
  禁止使用那篇综述本身；照 `litsearch` SKILL 的多轮章法走，最多 6 轮
- **旧做法对照不另跑**：台账记了每篇是哪条腿找到的，「只用字面 + 引用」能找回多少直接从同一份台账算

## 结果

**找回** = 标准集里出现在台账中的比例；**判对** = 其中被判为相关的比例。

| 方向 | 模型 | 找回 | 判对 | 只用旧做法（字面+引用）能找回 | 台账篇数 / 判相关 | 子 agent 用量 |
|---|---|---|---|---|---|---|
| 练习集 PBS | sonnet | **87%** | 80% | 67% | 801 / 206 | 32 万 token |
| vitrimer | sonnet | **78%** | 78% | 63% | 1464 / 840 | 43 万 |
| 植物微针 | sonnet | **100%** | 100% | 100% | 918 / 170 | 34 万 |
| vitrimer | haiku（加护栏前） | 16% | 16% | 13% | 1026 / 888 | 11 万 |
| 植物微针 | haiku（加护栏前） | 83% | 25% | 83% | 697 / 7（689 篇没判） | 9 万 |
| vitrimer | haiku（加护栏后） | 53% | 28% | 41% | 2659 / 528 | 11 万 |
| 植物微针 | haiku（加护栏后） | 92% | 92% | 92% | 916 / 568 | 12 万 |

### 三条结论

1. **新做法对强模型明显有效**：两个有难度的方向，按意思检索多找回 **16～20 个百分点**（87 vs 67、78 vs 63）；
   植物微针这种关键词很专一的方向，旧做法已经全找到，新做法不减分。
   各条腿「只有它找到的相关篇」都不为零 —— 三条腿都在起作用。
2. **弱模型第一次跑暴露了「全靠自觉」的问题**：假饱和（没判就说饱和）、整批按关键词判（87% 判相关）、
   问题明说两条路只搜一条。**已加工具层护栏**（待判队列、饱和放行条件、判断体检、分支覆盖、一次判太多条的警告），
   重跑后「找回」大幅回升（16%→53%、83%→92%），两条路都搜了。
   ⚠ 重跑时提示里还加了一句「必须逐篇读，不许写脚本批量判」，改进里有一部分来自这句话，不全是护栏的功劳。
3. **剩下的短板是「判准」，而且护栏治不了**：haiku 重跑仍然
   - vitrimer：8 篇明摆着在范围内的（「聚烯烃的催化升级回收」之类）被判不相关，2659 篇在 11 万 token 内判完 —— 不可能是逐篇读的
   - 植物微针：63% 判相关（sonnet 同一题 19%），自己承认「为了速度按关键词判」
   护栏能**发现**这些（体检已点名「没逐条填判据」「一口气判太多条」），但没法**替它判对**。

## 其它实测发现（已修）

- 语义检索输入超 1500 字直接 400（官方文档写 2000）；单次 5–8 秒，串行会超 MCP 60 秒 → 并发 + 单次 ≤8 次
- 检索结果混进审稿决定信、数据集条目 → 按 type 与 DOI 形状剔除
- 同一篇的正式版 / 预印本 / 版本号各有 DOI → 标题相同（≥40 字）并成一条
- 几个检索同时跑会撞语义检索「每秒 1 次」的限速，报错却写成「额度用完」→ 分开处理，前者自动多等几轮
- 宽题目（vitrimer）6 轮没饱和：每轮仍新增 70 多篇相关；每个检索词几百篇、agent 只取前 50 条是主要漏点 → 章法改为「200 以内一次捞干净，更多就按分支 / 年份拆开」
- `like=` 照着几篇找，会漂到种子的话题邻域（微针递送 → 没用微针的农药载体）→ 章法改为同时给一句话点明手段 + `unlike=`
- Elsevier 摘要缺失：约 1/3～2/5 的候选只能凭标题判（待 Elsevier 开发者 key）

## 待用户拍板

**要不要在工具里加一个「按判据逐条判相关」的专门环节？**（Ai2 Paper Finder 的做法：判相关由专门组件按条判，不靠检索 agent 自觉）

- 做法：台账里每篇新文献，按 agent 和用户商定的判据，由一个固定提示词的模型逐条判（是 / 部分 / 否），agent 只复核边界的
- 好处：判准不再依赖检索 agent 的认真程度 —— 这正是「换模型也成立」缺的那一块；强模型也能省下 30 万 token 的逐篇阅读
- 代价与取舍：① 改了「取舍由 agent 定」的边界（判据仍由 agent 和用户定，只是逐篇套判据交给专门环节）；
  ② 要选模型：按「全部换本地模型、小活用小模型」的原则，在主力机 Ollama 上用小模型，
  先拿本次验收的台账（sonnet 的判断当参照）测一致率再决定用哪个
