# 跟 Zotero 拆开 · 第三步「代码脱钩」清单（2026-10-12）

> 目标：Zotero 没开、甚至卸载了，平台各工具照常工作；Zotero 只当**可选**来源。
> 第一步（身份）、第二步（精读入口）已完成；第四步（只留「推到 Zotero」出口）在后面。
> 盘点方法：全仓库搜 `zotero_client` / `zotero.` 的调用，逐文件看用途。约 30 个代码文件。

## 核心做法：一个总开关

本机设置加 **`ZOTERO`（默认关）**，只在 `shared/adapters/zotero_client` 一处判断：
- 关着时，「顺带问一下 Zotero」的函数**立刻**返回「没有」（`zotero_index` 空集合、`find_pdf` / `find_si` / `has_si` 返回空），
  不再去连 localhost:23119 等超时 —— 今天这些函数在 Zotero 没开时也会降级，但每次要白等连接失败；
- 关着时，「只为 Zotero 存在」的操作（改标签、传附件、建条目、删条目）**明确报错**：「Zotero 已停用（控制面板 ZOTERO=1 可打开）」，
  不静默、不半途而废；
- 开着时一切照旧。以后真要用 Zotero（比如第四步的推送插引用），在控制面板打开即可。

这样「Zotero 在不在」只有一个地方知道，符合「外部世界只在 adapters 一处」的架构规矩。

## 逐项

### A. 已经会自动降级，开关关了直接走「没有」，不用改调用方
| 文件 | 用 Zotero 干什么 | 关掉后 |
|---|---|---|
| `shared/kernel/catalog.py`、`shared/domain/libmatch` | 「这篇我有没有」= 证据库 ∪ Zotero | 只问证据库（它本来就是全集）|
| `tools/litsearch`、`tools/discover`（match / __init__）、`tools/askworld` | 标「库里有」 | 同上 |
| `host/wechat_import` | 找正文 PDF 兜底 | 只用本地正本 |

### B. 本来就为 Zotero 而生的功能 → 关掉时不可用，给出清楚提示（代码留着，第四步或以后要用再开）
| 文件 | 是什么 | 处理 |
|---|---|---|
| `tools/curate`（tags / rename / junk / backfill）| Zotero 库房维护：打标签、改附件名、删重复、补元数据 | 开关关着时整工具拒绝运行并说明；SKILL.md 写明「已停用」 |
| `tools/deepread/tags.py`、`batch.py`；`deepread.request/status` | 打「待处理」标签排队、批量精读回写 Zotero | 同上；`request/status` 改成走文献库应用的作业队列（不打标签）|
| `host/watcher/service.py` | 打标签精读监听 | 已经关着（TAG_DEEPREAD=0）；看门狗里保持不拉起 |
| `host/autosync`、`tools/getpdf/from_zotero`（`--从Zotero落地`）| Zotero → 证据库回流 | 已停（AUTO_BUILD=0、计划任务停用）；开关关着时拒绝运行 |
| `tools/library` 的 Zotero 子命令（stats / search / item / pdf / fulltext / collections / tags / recent）| 查 Zotero | 拒绝并提示改用「库 / 检索」（证据库）；MCP 上这几个工具不再暴露 |
| `tools/discover/importer.py`、`thesis.py` | 把找到的文献建成 Zotero 条目 | 关着时拒绝；它们的「建条目」以后归第四步出口 |

### C. 依赖 Zotero 数据、但该改成用证据库的
| 文件 | 现在 | 改成 |
|---|---|---|
| `tools/extract/batch.py` | 批量抽取的文献清单来自 Zotero，PDF 找 Zotero | 清单来自证据库目录，PDF 用本地正本 |
| `tools/deepread/__init__.py` `run()` | 没给 PDF / SI 时去 Zotero 找 | 只看本地正本（应用的作业本来就显式给了）|
| `tools/ask/vectorize.py` 粗层（`light_all`）| 粗层文本来自 Zotero 全文索引 | 关着时跳过粗层；精层（解析出的全文）照旧。自动建库本来就停着，暂不重做粗层 |
| `tools/library/census.py`（盘点）| 证据库 vs Zotero 两边对账 | 只盘证据库；Zotero 那半关着时不显示 |
| `tools/direction` | 窄带配置里可选「从 Zotero 拿种子」| 关着时跳过（它本来就是可选的）|

### D. 体检 / 面板 / 运维
| 文件 | 现在 | 改成 |
|---|---|---|
| `host/doctor/health_check.py`、`report.py` | Zotero 本地 API、密钥是体检项 | 开关关着时这些项显示「已停用」而不是红黄 |
| `host/panel/app.py` | Zotero 连通、密钥 | 同上；设置页加 `ZOTERO` 开关 |
| `shared/kernel/role.py`（test 角色的 Zotero 测试库核对）| 保留，只在开关打开时有意义 | 不动 |
| 主力机计划任务 `ZoteroApp`（每小时拉起 Zotero）| 已停用 | 不动 |

### E. 留给第四步「出口」
`tools/getpdf` 的 `--to-zotero` / `put_local`、`deepread` 的 `upload_attachment`、`discover` 建条目 —— 第四步统一成「把选中的文献推到 Zotero」一个按钮。

## 怎么验证
- 离线测试：开关关着时 A 类函数立即返回空、B 类函数抛「已停用」、C 类走证据库（各补测试）；
- 主力机：开关关着、Zotero 进程关掉，跑一遍检索应用、`library 库 / 检索 / 找`、`discover` 一次小检索、离线 + 完整体检，确认没有卡住或报 Zotero 的错。
