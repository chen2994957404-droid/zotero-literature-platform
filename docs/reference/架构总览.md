# 架构总览 · System Architecture

> 一页看懂整个系统怎么运作、各部件为什么这么设计。

## 系统在做什么

把一篇英文文献 PDF，自动变成一份"高分子学人"风格的中文图文精读（完整组图 + 逐图解读 + 翻译整理），并归档回 Zotero。

## 完整数据流

```
【入口1·推荐】Zotero 打「待处理」标签
        │
        │ zotero_watcher.py 每60秒轮询（Zotero本地API读，带 Zotero-Allowed-Request 头）
        ▼
   定位本地 PDF（Zotero storage/<附件key>/*.pdf，直接读文件不下载）
        │
        ▼
   mineru_parse.py ── 调 MineRU 云端API ──▶ 解压得到 layout.json + 原PDF + full.md + images/
        │                                    （PUT上传要点：不发Content-Type，见踩坑1）
        ▼
   deepread_v4.py：
     ① 按 layout.json 的 page_size 坐标，从原PDF裁【完整Figure】（1:1对应，见踩坑7）
        - 合并 image/chart/table 三类视觉块
        - 按纵向间隔聚类成图，不依赖题注（鲁棒，对不同期刊通用）
     ② 元数据（标题/作者/DOI）用正则脚本抽（不花LLM的钱）
     ③ DeepSeek 只做翻译+按范式重组（省token、格式稳定）
     ④ 脚本确定性拼装图文 → 内嵌base64的HTML
        │
        ├──▶ workflow_data/summary/<标题>_精读.html（含图完整版）
        │
        ▼
   回写 Zotero（Web API，因本地API只读见踩坑8）：
     - 精读纯文字版作为笔记挂回文献
     - 标签 待处理 → 正文精读/全文精读（状态机，防重复见踩坑10）

【入口2·备用】n8n 表单上传 PDF（http://localhost:5678/form/deepread-upload-001）
        └──▶ n8n 解析+落地到 to_process/ ──▶ watcher.py 接手做精读
             （用于处理不在 Zotero 里的文献；此服务默认不自启，需手动开）
```

## 关键设计决策（为什么这么做）

| 决策 | 原因 |
|------|------|
| 精读用 DeepSeek 而非本地模型 | 3060 跑长输出太慢（踩坑3）；DeepSeek 一篇几分钱、质量高 |
| 图从原PDF按坐标裁，不用MineRU碎图 | MineRU 会把大Figure拆碎（踩坑7） |
| 用 layout.json 的 page_size 做坐标基准 | 1:1精确、对所有文献通用（踩坑7B） |
| 裁图不依赖Figure题注 | 有些期刊题注识别不到会丢图（踩坑7D） |
| 套路活（元数据/图片位置/排版）拆给脚本 | 省token + 输出格式稳定不漂移 |
| Zotero 读用本地API、写用Web API | 本地API只读（踩坑8）；本地读快又不联网 |
| 标签状态机 待处理/正文精读/SI精读/全文精读 | 防重复处理 + 避免API限流（踩坑10） |
| n8n 只做解析落地，精读交宿主机Python | n8n容器没Python（踩坑5） |

## 部件清单

**脚本（scripts/）**
- `zotero_watcher.py` — Zotero闭环主控（轮询→调度→回写），带运行日志
- `mineru_parse.py` — 独立MineRU解析（PDF→解析结果）
- `deepread_v4.py` — 核心：裁完整图 + DeepSeek精读 + 渲染HTML
- `_sys_prompt_v2.txt` — 精读范式提示词（改风格改这里）
- `build_deepread_workflow.py` — 重建n8n工作流（可选路径）
- `watcher.py` — n8n路径的守护脚本（可选路径）
- `archive/` — 迭代过程旧版本，存档参考

**向量化/问答脚本（scripts/）**
- `vectorize_library.py` — ★轻量全库向量化（走Zotero全文API，广撒网）
- `vectorize.py` — 精读文献的高质量向量化（读library的full.md）
- `ask.py` — ★向文献库提问（RAG检索问答）

**结构化抽取脚本（scripts/）** — 见 `结构化抽取说明.md`
- `extract_library.py` — ★粗层：全库结构化抽取（Zotero全文API + 本地qwen2.5，免费广撒网）
- `extract_structured.py` — 精层：重点文献结构化抽取（library的full.md + DeepSeek-pro，已接入watcher）
- 产物：`workflow_data/structured/compare.md`（横向对比表，找idea的载体）
- `backfill_meta.py` — 补齐早期文献的meta.json
- `zotero_upload_attachment.py` — 上传summary附件到Zotero
- `zotero_rename.py` / `delete_junk.py` / `list_junk.py` — 库维护工具

**数据（workflow_data/）** — 见 `数据契约.md`
- `library/<key>/` — ★按文献归档（parsed/ + summary.html + meta.json）
- `vector_db/` — ★Chroma向量库
- `logs/` — 运行日志
- `_incoming/` — 临时处理区

**启动**
- `启动Zotero闭环.bat` — 精读闭环服务（开机自启）
- `重跑精读_PRO版.bat` — 用pro重跑某篇（高质量）
- `启动精读服务.bat` — n8n精读服务（备用，手动）

**基础设施**
- `docker-compose.yml` — n8n容器（含fs放行等配置，备用路径用）

## 问答线（广度）· 数据流

```
Zotero 全库文献
   │ vectorize_library.py（走Zotero全文API，不碰PDF不占空间）
   ▼
取全文 → 过滤参考文献 → 切块 → bge-m3向量化(本地免费)
   ▼
存入 Chroma 向量库（workflow_data/vector_db/）
   ▲
   │ ask.py：问题向量化 → 检索相关块 → DeepSeek综合回答 + 附来源
你用大白话提问
```

关键决策：向量化走 Zotero 全文API（不解析PDF，几乎不占空间）；与精读线解耦（各管广度/深度）；自动过滤参考文献让检索聚焦正文。

## 依赖与外部服务

- Python + PyMuPDF（精读裁图）+ chromadb（向量库）
- DeepSeek API（精读翻译 / 问答回答）
- MineRU API（精读的PDF解析）
- Ollama + bge-m3（本地向量化，免费）
- Zotero（本地API读全文/元数据 + Web API写附件）
- Docker + n8n（备用路径）
