# 文献管理怎么做才科学高效 · 调研（2026-10-08）

> 起因：用户已基本不用 Zotero，想要一个**直连证据库**的轻量管理页面（按作者团队、按方向分类，
> 外加 Claude Science 的管理）。动手前先看外面的研究和现成项目怎么做。
> 标【查到】的有出处；标【推断】的是我据此得出的判断，不是外部事实。

## 一、结论

1. **分类别只做一棵文件夹树，要「固定分组 + 多个维度并用」。**研究证据一致指向混合式：
   项目这种稳定的归属用文件夹，团队 / 方向 / 性能 / 状态这类彼此独立的属性用维度筛选。
2. **团队和方向都不用自己从零认**：OpenAlex 已经给出通讯作者和作者消歧，也给出了主题分类，
   平台的适配器本来就在取这些字段。
3. **方向用「你给清单 + 模型来标 + 你改」**：分类类别已经定好时，模型直接打标签比聚类准；
   聚类只用来「发现清单里还没有的新方向」。
4. **不拿现成开源软件当底座**：最接近的几个都是自带数据库的桌面阅读器，接上就会出现第二个「库」，
   跟「证据库是唯一核心」冲突。只借鉴它们的做法。

## 二、研究证据：人到底怎么管文献

- 【查到】科学家多数按**项目**建文件夹，也有人混用「主题 + 项目 + 事务」三种类别；
  有人干脆不整理，然后经常找不到读过的文献。
  （[Emerald 2022，科学家的个人信息管理](https://emerald.com/insight/content/doi/10.1108/GKMC-04-2022-0082/full/html)；
  [Springer，按文件夹与标签管理参考文献](https://link.springer.com/chapter/10.1007/978-3-319-20612-7_28)）
- 【查到】文件夹和标签对照实验：找回用时差不多（14.5 秒对 15.4 秒），各有长短；
  作者建议把两者结合起来。
  （[Civan 等，Better to organize by folders or by tags?](https://www.researchgate.net/publication/227628722_Better_to_Organize_Personal_Information_by_Folders_Or_by_Tags_The_Devil_Is_in_the_Details)）
- 【查到】人们**嘴上喜欢多重分类，实际很少用**：Gmail 研究里用标签式分类的邮件只占 8%。
  找东西时更多靠**按目录点进去**，而不是搜索。
- 【查到】有研究者因为**标签不能批量删除、不能合并**而干脆不用标签。
  → 标签要能批量改、合并、删除，否则用不起来。
- 【查到】人建文件夹用的其实就是几个固定维度（体裁、任务、主题、时间），
  只是嵌套顺序因人而异。这说明维度式分类更贴近人的真实想法；但维度太多界面会乱，
  也丢掉了「东西放在哪」的位置记忆。主流建议是**混合式**。
  （[Archivaria，个人文件的维度分类](https://www.archivaria.ca/index.php/archivaria/article/view/13359)；
  [CHI 2008 FacetFolders](https://mt.inf.tu-dresden.de/cnt/uploads/2008-CHI-FacetFolders.pdf)）
- 【查到】这类研究样本都小（几十人），证据偏弱，只能当方向参考。

## 三、外面的现成项目

| 项目 | 是什么 | 对我们的意义 |
|---|---|---|

| [Open Paper](https://github.com/khoj-ai/openpaper) | 阅读 + 标注 + AI 问答 | 自己写明以托管服务为主，不适合自己部署 |
| [PaperQA2](https://github.com/future-house/paper-qa) | 高精度的文献问答引擎 | 只管问答，不管文献；我们已有 `tools/ask` |

| Paperlib | 开源桌面文献管理 | 没查到它最近有没有人维护，不推荐 |

## 四、可以直接用的现成资源

- **作者团队**【查到】：OpenAlex 每篇文献的作者记录里标了谁是通讯作者，
  人工核对的准确率约 0.92（[OpenAlex 博客](https://blog.openalex.org/?p=3998)）；
  作者经过消歧，有稳定的作者编号，但**偶尔会把一个人拆成两个、或把两个人并成一个**
  （[作者记录说明](https://help.openalex.org/data/authorships.md)）。
  → 团队 = 通讯作者的作者编号，页面上留「合并 / 拆开」的手动按钮。
- **主题分类**【查到】：OpenAlex 有四级主题（4 大领域 → 26 学科 → 约 252 子学科 → 约 4500 主题），
  每篇最多三个主题、一个主主题（[Topics 说明](https://help.openalex.org/data/topics/)）。
  【推断】对聚硼硅氧烷这么窄的方向，这一套可能太粗，只适合当最上面一层。
- **平台现状**【查到，看了代码】：`shared/adapters/openalex` 已经在取 `authorships`、
  `primary_topic`、`topics`；`curated/<id>/meta.json` 已有 `authors` 字段；
  另有概念矩阵（动态键家族 × 性能）。

## 五、分类方法：按什么来分

- 【查到】类别**已经定好**时，用大模型直接打标签效果好：眼科文献 1000 篇、15–19 类，准确率约 0.86
  （[arXiv 2308.16688](https://arxiv.org/pdf/2308.16688)）；给几个例子还能明显更准
  （[arXiv 2502.15745](https://arxiv.org/pdf/2502.15745)）。
- 【查到】便宜的替代做法：用类别名做种子，在向量空间里聚类，比只靠提示词平均高约 20 个百分点；
  不过那篇用的是老一代模型（[EMNLP 2022](https://aclanthology.org/2022.emnlp-main.587)）。
- 【查到】BERTopic 这类聚类擅长**发现**主题，不适合往定好的类别里分
  （[arXiv 2510.16152](https://arxiv.org/pdf/2510.16152)）。
- 【推断】我们的做法：你给方向清单（可以从概念矩阵起步）→ 本地模型来标 → 你改错的；
  隔一段时间用聚类扫一遍，提示「可能有个新方向」。按「练习集调、考卷报数」的规矩，
  先在一小批你标过的文献上实测准确率，再铺到全库。

## 六、对管理页面的设计启示

1. **两种分类并存**：
   - **我的分组**（文件夹式，手动，按课题 / 项目），一篇可以进多个组；
   - **维度筛选**（自动生成、你可以改）：团队、方向（机理）、性能、材料体系、年份、期刊、
     手上有什么（正文 / SI / 精读）、阅读状态。
2. **团队**：按通讯作者（课题组长）归组，显示单位；同名、拆分的情况能手动合并、拆开。
3. **方向**：你的清单 + 模型标注 + 手动改；你改过的永远以你为准，机器不会覆盖。
4. **标签可以批量改、合并、删除**（研究里有人正是因为这点放弃了标签）。
5. **以「按目录点进去」为主、搜索为辅**：维度别一次全摊开，默认只显示两三个常用的。
6. **Claude Science 一栏**：它取了什么、在排队的、失败的和原因、SciFinder / Reaxys 当天用量。

## 七、还要用户定的

- 「我的分组」先建哪几个（比如按你手上的课题）。
- 方向清单是直接从概念矩阵起步，还是你另列一份。
- 阅读状态要不要（未读 / 粗读 / 精读过）。

## 八、全库实测：团队统计（2026-10-10，主力机只读，脚本 scratch/team_census.py）

口径：证据库 1179 篇，有 DOI 1167，OpenAlex 对上 1160（98%）。
候选组长 = 通讯作者 ∪ 末位作者；组长暂取「候选里 OpenAlex 发文最多的」。

| 指标 | 数 | 占比 |
|---|---|---|
| 没标通讯作者 | 147 | 13% |
| 1 个通讯 | 395 | 34% |
| 2 个通讯 | 355 | 31% |
| 3 个通讯 | 174 | 15% |
| 4 个及以上 | 79 | 7% |
| 末位作者是通讯 | 901 | 78% |
| 发文最多的候选 ≠ 末位作者 | 255 | 22% |

按组长归组：848 个组；≥2 篇 142 组（427 篇）；**≥3 篇 45 组（233 篇，占 20%）**；≥5 篇 11 组；≥10 篇 4 组。
最大的组：Jinrong Wu（四川大学）43 篇，其后 Junqi Sun 14、Peiyi Wu 13、Feng Yan 11、Xinglong Gong 9。
大导 + 小导形态清楚的例子：Peiyi Wu + Shengtong Sun / Zhouyue Lei；Xinglong Gong + Shouhu Xuan；Guangzhao Zhang + Chunfeng Ma。

暴露的问题：
- **长尾**：约 700 个组只有 1 篇。
- **作者被拆成多个编号**：同一个 Qi Wu 以两个编号出现在 Jinrong Wu 组里；有的知名学者在某些文章里挂着「发文 1」的碎片编号。
- **「最近单位」不可靠**：作者档案的 last_known_institutions 有明显错误（例如把 Jian Ping Gong 标成吉林大学）。单位应取**这篇文章署的单位**，不取作者档案。
- 「发文最多 = 大导」只是粗规则：发文数会被拆分 / 合并污染，22% 跟末位作者不一致的需要别的证据。

## 九、作者编号合并规则试验（2026-10-11，主力机只读，脚本 scratch/merge_trial.py、merge_score.py）

**方法**（有文献依据）：ORCID 当标准答案（两边都有 ORCID：相同 = 同一人，不同 = 不同人）；依据看姓名、共同合作者、共同单位，
合作者是最强信号（[Scientometrics 2020](https://link.springer.com/article/10.1007/s11192-020-03826-6)；
[Author-ity2009](https://par.nsf.gov/servlets/purl/10292505)；[CASRAI](https://casrai.org/guides/author-name-disambiguation-orcid-algorithmic-matching-cris)）。
练习集 = 「≥3 篇的组」里的人；考卷 = 「恰好 2 篇的组」里的人（另一批人，调规则时没看过）。

**练习集上发现的三件事**：
1. **姓名不能宽松匹配。**把两字母拼音当缩写（qi ≈ qiang）、用 OpenAlex 的「别名」列表，会配出 Kai Wu ↔ Qiang Fu 这类荒唐的对。改成严格同名（忽略大小写、连字符、姓名顺序）。
2. **真拆分的形状很统一：一个大编号 + 一个小碎片**（碎片发文 1–29 篇），同名、共过单位、有共同合作者。
   ORCID 判为不同人的同名对，两边都是大编号（58–961 篇）。
3. **ORCID 答案本身也有错**：John A. Rogers 两个编号共同合作者 357 人，ORCID 却不同 —— 几乎肯定是同一人。

**冻结的第三版规则**：严格同名 + 共同合作者 ≥2 + 共过单位 + 小的那个编号发文 ≤30。

**考卷成绩**（严格同名且有 ORCID 答案的 27 对，其中 19 对是同一人）：
合对 15、错并 2、漏并 4 → **合并准确率 15/17 ≈ 88%，找全率 15/19 ≈ 79%**。样本小，只能当量级参考。
- 错并：Chao Wang(92)↔(9)、Bowen Cheng(98)↔(28)。两对两边都有 ORCID 且不同（后者共同合作者 38，也可能是 ORCID 错）。
- 漏并：碎片只有 1–3 篇，共同合作者只有 0–1 个（Chaoji Chen、Xi Yao、Jing Liu、Hao Zhang）。

**下一轮要验证的改动**（根据考卷错例提出的，所以必须换新数据再考，不能拿这批报数）：
- 两边 ORCID **都有且不同** → 不自动并，交给 Agent 核实（考卷里的 2 个错并都属于这种）；
- 碎片 ≤3 篇时，共同合作者门槛降到 1。

**量级**：牵涉到的合并只有几十对，全部交给 Agent 逐条核实也不贵 —— 所以规则的作用是「排好先后、给出建议」，不必追求零错。
