# 本地化拆解规划 —— 每个步骤用什么模型、拆成什么样本地能扛（2026-09-20）

> 用户定的三条方向（同日）：**全部换本地模型** · **LLM 插进每个需要判断的步骤** · **模型按步骤挑，不必都用最大的**。
> 本文是动手前的总规划。每一条「建议档位」都标了依据：是**实测**还是**推断**；推断的必须先量再切。
> 硬件：主力机 RTX 3060 12 GB。可用模型见下表。

## 一、五个档位（以后说「这步用 T2」就指这里）

| 档 | 模型 | 适合的活 | 已有实测 | 速度 |
|---|---|---|---|---|
| **T0** | 脚本（正则 / 规则 / 表格解析） | 能写成规则的一律不请模型：切段、认图号、数字回查、格式硬修 | 全项目在用 | 毫秒 |
| **T1** | `gemma3:1b`（0.8 GB） | **封闭判断题**：给定段落 + 给定名单，问「哪个数是哪个样品的什么」；是/否 | chunk_pass 比武：抽 40 条、接地 94%、样品合法 80%，错的两类脚本都能当场判掉 | 3.5 s/段 |
| **T2** | `qwen3.5:4b`（3.4 GB） | **分类 / 短 JSON / 逐句判**：这篇是不是综述、这张图是主图还是辅图、这句原文支不支持 | **未实测** | 待量（推断 5–8 s/次） |
| **T3** | `qwen3.5:latest` 9.7B（6.6 GB，262k 窗口，有 vision） | **中文写作、长材料理解**：精读各栏、要点清单、问答 | 精读金标 40 篇 90.6 分、0 编数 | 约 16 s/次，一篇精读 4 min |
| **T4** | 云端（只在面板点名时） | 目前只剩图表数字化，待 T3 的 vision 重测后决定 | 踩坑 #15/#16（7B 老模型编数据） | — |

选档的规矩：**同一批样本三档都跑，取达标里最小最快的**。达标线由各步的验收指标定（见每节）。
T1/T2 之所以敢用，全靠 T0 的把关层 —— 小模型犯的错必须是脚本能判掉的那种（数不在段里、样品不在名单里、格式不合形）。

## 二、逐条流水线拆解

### 3. 结构化抽取 extract（**本地化的主战场**：整篇一次抽是本地做不好的形状）

现状：`hierarchical_body` 把 5 万字压到 9k 字一次喂 T4/T3 抽 30+ 字段 → 本地只抽到云端 1/4 的数字（2026-08-28）。
根因跟精读一样：**不是模型笨，是没看见 + 一次要的太多**。已有 `chunk_pass` 证明了拆法可行。

## 四、顺序与验收

```
A. 审稿拆三用途 + T2/T3 同批校准选型          ← 校准跑着，今天出数
B. 抽取拆解：chunk_pass 正式化(T1) → 定性字段分类(T2) → 合成条件按样品(T3)
   验收：347 个已核对数字的召回 ≥ 云端的 80%；定性字段与精层记录一致率 ≥ 85%
C. 阅读计划步骤 + 图分级篇幅 + 综述判定换 T2   验收：金标同批分数不降、篇幅比进 0.8–1.3
D. 问答 / 检索式 / 四元组的小活换 T2           验收：各自的抽查
E. 看图：T3 vision 对照 curves 重测            验收：点误差；不达标继续留云端
```

每一步：先在同一批样本上跑候选档位 → 写进 `docs/变更记录.md` 的实测数字 → 再改路由表默认值。
**没有实测数字的档位不许写成默认。**

## 五、第一轮实测已经给的答案（2026-09-20 17:21，审稿 T3 本地校准，同批 5 篇范文）

| | 云端（deepseek） | 本地 T3（qwen3.5 9.7B） |
|---|---|---|
| 干净范文误报率 | 6.3% | **22.1%** |
| 塞错查全率 | 84% | **67%** |
| 漏判（模型没给判定） | 0 | 23/99 句（一批 25 句时后面的不答） |

误报逐条看，三类占了大头，**都是任务形状问题，不是模型笨**：
1. **材料没找对**：范文的药品清单、表征方法在 SI 里；本地窗口小，材料靠「共享数字/英文词」挑段落，
   而「实验药品包含二水氯化钙、乙醇…」这种中文句子一个英文词都没有 → 挑不到段 → 判成编造。
   **改法：用 bge-m3（本地、跨语言）按句子做语义检索挑段落**，不再靠词面重合。这是 T0 层的活，免费。
2. **引言里的常识**（「传统水凝胶易失水」）在范文整篇一栏时没有「引言可宽容」的规则。改法：范文也按段落位置分栏。
3. **一批 25 句太多**，后半批不答。改法：本地一批 10 句。

这轮数字说明：**同一个提示词、同一个流程，云端能扛的本地扛不住 —— 本地化 = 重做任务形状，不是换个模型名。**
上面每一节的「建议」都要按这个标准再过一遍。

## 六、要提前说的风险

- **显存**：T3 6.6 GB + 24k 窗口的 KV 缓存接近 12 GB 上限；T1/T2 与 T3 不能同时驻留，Ollama 会来回换模型（每次换约 5–10 s）。一条流水线里尽量把同档的调用排在一起。
- **速度**：全本地后一篇「精读 + 审稿 + 抽取」估 8–12 分钟；批量靠夜里跑，watcher 已经是排队的。
- **T2 完全没实测**：上面所有「T2」都是推断，第一轮校准就是给它定性。
- **审≠写**做不到：审稿和精读都是 T3。把逐句判换成 T2 之后这条自然满足。

## 七、单元拆解第一轮结果（2026-09-20，20 篇范文 → 3300 条单元，本地 qwen3.5 拆、脚本定位、我复核）

产物在主力机 `data/state/unit_study/u1/`。一篇范文平均 165 条单元。按第一版七类拆完再离线复分类（有没有数字 / 是不是表征手段）：

| 第一版类 | 实际是什么 | 条数 | 占比 |
|---|---|---|---|
| panel 图面板 | 一个子图一条，干净 | 836 | 25% |
| fact 性质事实 | **带数字的只有 388**；另 648 条是定性描述（「生物相容性良好」「易残留空气」）| 388 + 648 | 12% + 20% |
| entity 实体 | 材料 / 样品 / 缩写 | 434 | 13% |
| action 合成动作 | 真正的制备步骤 285；**表征 / 测试手段 102**（「利用电化学阻抗谱」）；只有动词没有量和条件的 125 | 285 + 102 + 125 | 9% + 3% + 4% |
| claim 主张 | 干净 | 249 | 7.5% |
| role 角色关系 | 干净，几乎全在 Q1 | 220 | 6.7% |
| cause 因果关系 | **只有 15 条** —— Q2 的内容被拆成了 fact / claim | 15 | 0.5% |

**分类法要改成九类**：fact 只留带数字的；加 **attribute**（定性性质）；加 **method**（表征 / 测试手段）；cause 的定义改成「Q2 那种为什么」。

**每一栏由什么组成（栏 × 类，20 篇合计）**：

| 栏 | 主要单元 |
|---|---|
| 导读 | entity 110、fact 52、claim 15 |
| 引言 | fact/attribute 157、action（高层策略）117、entity 54 |
| 实验 | action 273、entity 249、fact 98、role 40 |
| Q1 | role 150、fact 40 |
| 图 | panel 835、fact 477（其中带数 266）、claim 61 |
| Q2 | fact 92、claim 53、cause 11 |
| 总之 | fact 102、claim 95 |

**依赖**：panel / entity / fact / action / method 只依赖原文（各自的图注、方法节、表格）→ 可并行、可用小模型；
claim 依赖 fact + panel；role 依赖 entity + action；cause 依赖 claim + fact。

**对模型档位的直接推论**：一篇范文里 **约 70% 的单元（panel、entity、fact、action、method）是封闭抽取**，
输入是图注 / 方法段 / 表格这种几百到几千字符的小片段，输出是固定字段 —— 这正是 T1/T2 的形状。
只有 attribute / claim / role / cause（约 30%）要理解和取舍，才需要 T3。**现在的精读把这两拨活揉在一起，所以每一步都得用 T3。**

定位结果（新规则：数后跟单位 / 附近有样品名 / 参考文献区不算）：带数字的 fact 里 63 条能靠「数 + 单位」钉死在原文，309 条靠样品名，
151 条只是弱匹配；能定到 SI 的只有 5 条 —— 范文里 SI 来源的数字比预想少，或者 SI 解析文本里的单位写法跟范文对不上，下一轮要看。

**下一步（第 2 步）**：用九类分类法对**同一批 20 篇的英文原文**拆单元（不是范文），再算范文的单元有几成能在原文单元里找到对应
（Pyramid 的做法）—— 这就是「原文 → 单元 → 精读」这条路的可行性测试，也是各类单元该用哪档模型的实测场。

## 八、单元拆解第 2 步结果（2026-09-21，同批前 10 篇：英文原文拆九类 → 范文单元覆盖率）

原文拆出 6875 条单元（一篇 470–1070 条），范文 1553 条 —— **精读用了原文单元的约 23%**，「精读 = 从原文单元里选取」这个前提成立。

按类覆盖（范文单元能在原文单元里找到对应的比例；语义类按 bge-m3 相似度 ≥ 0.72 判）：

| 类 | 范文条数 | 覆盖率 | 我抽样复核后的判断 |
|---|---|---|---|
| panel 图面板 | 452 | **87%** | 真实。图号 + 子图能对上，剩下的是原文图注没写子图 |
| fact 数值事实 | 154 | **65%** | 真实（按数配）。漏的一部分是范文换算过的数、一部分在 SI 没切进来的段 |
| action 合成动作 | 187 | 62% | 0.80 以上的对子全对（搅拌 80 ℃ 12 h、乙醚洗涤…），0.72–0.80 一半对；**真实覆盖约 50–60%** |
| attribute 定性性质 | 344 | 59% | **数字不可信**：相似度主要靠样品名对上，0.80 以上也有一半是错配（「可回收性」配到「直径 110 μm」）|
| method 表征手段 | 54 | 46% | 不可信：范文这类单元太空（「采用光学显微镜」），原文侧拆出的 method 也少 |
| claim 主张 | 101 | 7% | **线定高了**：0.65–0.72 那档抽出来多数是对的（「保证室温网络稳定性」↔「ordered H-bonds dissociate last, ensuring stability」）。中英长句改写相似度就是 0.65 左右。真实覆盖估计 50% 以上 |
| role 角色 | 111 | 17% | 0.72 以上一半对；低于 0.72 基本只是组分名对上。真实覆盖约 25–35% |
| cause 因果 | 14 | 0% | **原文侧几乎没拆出 cause**（第一篇 484 条里只有 6 条）—— 是拆解提示词的问题，不是原文没有 |
| entity 实体 | 166 | 8% | 配法错：范文是中文名、原文是英文名，只按缩写配当然低 |

**结论**：
1. 封闭类（panel、fact、action）**从原文抽得出来**，而且覆盖率是真实的 —— 这三类占范文单元的一半，可以直接进入「换小模型」的选型。
2. 语义类靠向量相似度打分不够用（每类的错配方向都不一样）。**正规做法是 Pyramid 的第二步：相似度只负责召回前三名，再由一个小模型判「是不是同一件事」**。这本身就是一个 T2 判断题 —— 正好拿它做小模型的第一次实测。
3. cause 要改原文拆解提示词（把「为什么 X 导致 Y」的判据写清楚），entity 配对要跨语言（同样交给小模型判）。

**第 3 步**：相似度召回 top-3 + qwen3.5:4b 判同异 → 重算语义类覆盖；同时把 4b 的判断跟 9.7B 判的对照 50 对，看 4b 够不够。

## 十四、审稿本地校准第二轮（2026-09-22，同一批范文，三处形状改 + JSON 修复）

| | 云端基线（5 篇） | 本地第一轮（5 篇） | 本地第二轮（10 篇，形状改） | **本地第三轮（10 篇，+JSON 修复）** |
|---|---|---|---|---|
| 干净范文误报率 | 6.3% | 22.1% | 13.8% | **12.2%** |
| 塞错查全率 | 84% | 67% | 59% | **68%** |
| 句子判定率（没漏判） | 100% | 77% | 85% | **87%** |
| JSON 解析失败批次 | 0 | — | 31 | **0** |

三处形状改（范文按范式分栏审 / 本地一批 10 句 / 材料按 bge-m3 语义挑段）把误报几乎砍半；
同一篇最直观：adma.74002 干净版从「79 句标出 23（29%）」变成「95 句标出 8（8%）」—— 误报降三分之二，判得还更全。

**中途抓到的真问题（踩坑 #185）**：本地模型在 JSON 的 why 字段里塞没转义的引号（「原文说 "12.5 MPa"」），
整批解析失败、整批算漏判 —— 第二轮 31 批作废，正好把塞进去的错也吞了，所以查全率反而掉到 59%。
换成现成库 `json_repair` 兜底后 0 失败，查全率回到 68%。**「误报降了、查全也降了」这种同向异常，要先怀疑管道而不是模型。**

**剩下的 12.2% 误报，逐条看是什么**（不是模型笨）：
1. **范文的实验细节来自 SI 的合成节**，而审稿给实验栏的材料是「方法节 + 表 + SI 实验细节」的截断版 —— 长 SI 里靠后的合成步骤没进窗口，于是「化合物 1 的合成：5.0 g / 50 mL / 80 ℃ 12 h」被判成编造。
   → 下一步：实验栏的材料改用**单元库的动作单元**（fine_action 已经把这些步骤按字段抽出来了），而不是再截一遍 SI 原文。
2. **范文替读者做的归纳**（「只能小幅提升拉伸应变」「恢复接近八成」）—— 原文只给了绝对值没给百分比。这类严格说确实是范文的加工，判 unsupported 不算错，但不该拦住我们自己的精读（我们的提示词禁止这种换算）。
3. **表征手段清单写全了但原文只提了一部分**（「拉曼、XPS、固体磷核磁」原文只有 ATR-FTIR）—— 这是**真错**，审稿抓对了。

结论：形状改的方向被证实；下一处形状改是「实验栏材料改喂单元库」，不是继续调提示词。

| 轮 | 改了什么 | 误报率 | 查全率 |

| 本地① | —（形状照搬云端） | 22.1% | 67% |

真正观察到的规律是另一条：**同一篇两次跑，「判了几句」差很多**（46 句里有时判 33 有时判 46），而判满的那次标出的反而少。
→ 下一个该动的不是窗口也不是提示词，是**让模型必须把每句都判到**（漏判的单独补问一次，而不是记成 unjudged）。这也解释了为什么误报率一直在 12–14% 晃：分母（判了几句）本身在晃。
