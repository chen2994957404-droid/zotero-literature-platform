# 代码规范 · 标准脚本模板

> 本文件是**项目唯一的代码格式准绳**（2026-08-11 框架化建立）。
> 改任何 .py、写任何新脚本，先照这里的规矩来。
> 与「架构宪法」（回答**为什么**）不同，本文件只回答**怎么写**，全部可机械检查。

## 一、为什么有这份规范（体检数据，2026-08-11）

79 个 .py 文件里存在三类反复出现的「自由发挥」，每种都有十几种写法：

| 体检项 | 数量 | 问题 |
|---|---|---|
| `sys.path.insert`（把项目根塞进 import 路径） | **78 处、约 50 个文件** | 同一件事十几种写法：`ROOT` 常量、`SCRIPT_DIR`、`_sys/_os` 缩写、三重 dirname、try 包裹…… |
| 手写 `sys.argv` 解析 | **97 处** | argparse 数量为 0，风格至少 10 种：`'--flag' in sys.argv`、`sys.argv.index('--tag')+1`、`args=[a for a in sys.argv[1:] if not a.startswith('--')]`、位置切片…… |
| 强制 UTF-8 输出 | 15 个文件 | 同一段 `sys.stdout.reconfigure(...)` 复制粘贴 15 次 |

后果：AI 接手时每看一个文件都要重新学习它的写法；改一个脚本想照抄另一个都抄不整齐。
**本规范把「怎么写」收敛成一套，让所有脚本长得一样。**

## 二、标准开头（2026-08-26 大幅简化：从 9 行降到 4 行）

> **⚠ 这一节在重构阶段 0 被改写。旧的「走查项目根 + sys.path.insert」写法已全部删除，
> 不要再写回去。** 原委见 `docs/架构重构_v2总体设计.md`。

### 现在的标准开头

```python
# -*- coding: utf-8 -*-
import os, sys
# 【标准开头】强制 UTF-8 输出（项目已装成 Python 包，import 无需再塞 sys.path）
try:
    sys.stdout.reconfigure(encoding='utf-8', errors='replace')
except Exception:
    pass
```

就这些。**不需要任何 sys.path 操作。**

### 为什么那 9 行没了

项目现在是一个真正的 Python 包（根目录有 `pyproject.toml`）。装一次：

```
pip install -e . --no-deps
```

之后 `import core.config`、`from core import paths` 在**任何目录**都能用，
不管你是 `python 文献精读/deepread_v4.py` 还是 `python -m pytest` 还是被
subprocess 拉起来的子进程。

旧写法（沿 `__file__` 往上找含 `modules/` 的目录，再塞进 `sys.path`）
在全项目重复了 **40 多处**，是「项目不是一个包」的补丁。补丁的真正代价不是那几行字，
而是：它让「其实没装好」这类问题被掩盖，故障延后到运行时才以奇怪的形式冒出来。

**架构守卫会拦住回退**：`tests/test_architecture.py::test_不再有塞项目根到sys_path的补丁`
—— 谁再写回去，`pytest` 立刻变红。

### 换电脑 / 重装之后

跑一次 `pip install -e . --no-deps` 即可（平台体检会检查这一项，没装会明确报出来）。

## 二·B、数据路径（一律走 `core.paths`）

**铁律：禁止手写 `workflow_data` 路径。**

```python
from core import paths

open(paths.fulltext(key), encoding='utf-8')   # library/<key>/parsed/full.md
paths.summary(key)                            # library/<key>/summary.html
paths.structured(key)                         # structured/<key>.json
paths.LIBRARY, paths.VECTOR_DB, paths.LOGS    # 目录常量
paths.log('zotero_watcher')                   # logs/zotero_watcher.log
```

为什么：`docs/数据契约.md` 把目录约定写得很清楚，但在此之前那只是散文 ——
路径在 **53 处**手工拼装，契约随时可能被违反而无人发现。收进 `core/paths.py`
之后，改目录布局只需改一个文件，且可以写契约测试扫全库验证。

**架构守卫同样会拦**：`test_数据目录路径只在core_paths里拼装`。
确实必须写这个词的地方（比如遍历时排除数据目录），行尾加 `# paths-exempt` 并写明理由。

## 二·C、从哪个环 import（2026-08-26 阶段 2 建立）

代码分四环，`import` 前先想清楚要的东西住在哪一环：

```python
from core import paths, errors          # 内核：路径、异常分类
from core.cli import pos, flag, opt     # 内核：命令行参数
from core.config import get_key         # 内核：配置与密钥
from core.log import get_logger         # 内核：日志

from domain.si_filter import filtered_text      # 纯逻辑
from domain.figure_crop import crop_figures

from adapters.zotero_client import find_pdf     # 外接口（唯一允许联网的一环）
from adapters.llm_client import chat
from adapters import openalex, vectordb

from pipelines.paper_discovery import search    # 编排
```

**依赖只能从上往下**：`apps → pipelines → domain/adapters → core`。
反向 import 会让 `pytest` 变红（`tests/test_architecture.py`）。

四条硬规则（都有守卫强制）：

1. **只有 `adapters/` 可以联网**。别处要调外部服务，先把它包成一块 adapter，
   本环只调那块 —— 这条守着的是「换外部服务只改一个文件」的承诺
2. **`domain/` 不许 import `core.paths`** —— 纯逻辑永远不知道文件放在哪，路径由调用方传进来
3. **`domain/` 不许 import `adapters/`** —— 否则它就没法离线测试了
4. **不许 import 已经不存在的包**（比如历史上的 `modules`）—— 搬家后漏改会被守卫抓出来

## 二·D、有副作用的操作要加机器角色守卫（2026-08-26）

本平台跑在两台机器上、**共用同一个 Zotero 账号**（见 `docs/两台机器的分工.md`）。
编程端一旦回写，污染的是真实文献库，而且立刻同步到主力机。

**凡是「写 Zotero / 花钱的批量作业 / 常驻服务」，在执行它的函数开头加一行：**

```python
from core import role
from core.cli import flag

def main():
    role.require_prod('批量精读（调用付费 API）', force=flag('--force'))
    ...
```

三条注意：

1. **写在函数体里，不要写模块顶层** —— 写顶层会让 `import` 就抛错，
   体检的「运行时导入」检查、pytest 收集、面板借用逻辑会一起挂。
   守卫要挡的是「执行」，不是「加载」。
2. **动作描述写清楚**，它会原样显示给一个不懂编程的用户看。
3. **常驻服务（watcher / 看门狗）要在 `__main__` 里接住 `WrongMachineError`**，
   打印人话而不是甩 traceback —— 主力机首次部署时这个失败必然发生一次。

守卫测试会扫描所有出现 `api.zotero.org` 的文件，漏一个就变红。

## 三、命令行参数（一律走 `core/cli`）

**铁律：禁止手写 `sys.argv`。** 所有取参数都从 `core/cli` 取：

```python
from core.cli import pos, flag, opt, opts, positionals

query = pos(0)                     # 第 0 个位置参数 → 'polyborosiloxane'
limit = int(pos(1) or 8)           # 第 1 个位置参数，缺省 8
rebuild = flag('--rebuild')        # 开关：命令行出现 --rebuild 即 True
top = int(opt('--top', '10'))      # 带值选项：--top 10
tags = opts('--tag')               # 可重复选项：--tag a --tag b → ['a','b']
rest = positionals()               # 全部位置参数（-- 之前的部分）
```

| 函数 | 语义 | 缺省 |
|---|---|---|
| `pos(i, default=None)` | 第 i 个位置参数（**必须在 `--` 选项之前**） | default |
| `flag(name, default=False)` | 命令行出现 `--名字` 即 True | default |
| `opt(name, default=None)` | `--名字 值`，取紧跟的值 | default |
| `opts(name)` | `--名字` 可重复出现，收集全部值 | [] |
| `positionals()` | 所有位置参数（`--` 之前的部分） | [] |

**约定：位置参数必须在 `--` 选项之前**（`script.py 主题 数量 --limit 20`）。
把选项插在位置参数中间会产生歧义（分不清选项后面是它的值还是位置参数），不支持。

**为什么不用 argparse**：本项目参数都很简单（几个位置参数 + 几个开关），argparse 的
help/子命令等重装备用不上，还引入一套新语法。这符合宪法判据 —— **能自己做的稳定部分自己做**。

**取不到参数绝不抛异常**：缺参时由脚本业务逻辑自己判断（很多脚本允许无参运行，如 `ask.py`）。

## 四、结构与入口

- 文件第一行注释后紧跟 docstring，**第一句说清「这个脚本/模块是干嘛的、谁调用它」**。
- 逻辑拆成**函数**，顶部只留 import 和常量；入口统一：

```python
def main():
    ...

if __name__ == '__main__':
    main()
```

- 一个脚本只干文件夹职责内的一件事（跨职责的活去问积木层有没有，没有就提议新增积木）。

## 五、配置纪律

- 密钥/本机设置/模型名**一律走 `core/config`**：`get_key` / `get_site` / `need_site` / `get_model`。
- **禁止 hardcode**：Zotero 用户ID、附件路径、Ollama 地址、模型名，一个都不许写死在脚本里。
- 必填项用 `need_site(name)` 或 `get_key(name, required=True)` —— **没配就明确报错并告知怎么配**，
  不许静默用默认值（静默用错值比直接报错危险得多，见 config 积木铁律）。

## 六、错误处理纪律

- `except: pass` 禁止裸用 —— **必须带注释说明「为什么这里吞掉错误是安全的」**，
  或至少写 `except Exception:`（不许裸 `except:`）。
- 外部服务（本机 Zotero、Ollama、网络 API）的「降级路径」是合法的吞错场景，
  但注释要写清降级后缺了什么（例：`# Zotero 没开就只做纯检索，不影响主功能`）。
- 主流程的错误要**报得明白**：缺配置 → 提示去哪配；网络失败 → 说出是哪个 API、怎么重试。

## 七、积木准入标准（新增 `<环>/<名>/` 必须三件套）

每块积木 = `__init__.py` + `selftest.py` + `CLAUDE.md`，缺一不可：

- `__init__.py`：docstring 写清「解决的真实问题 + 用法」，公开函数列表用表格注释。
- `selftest.py`：不联网、不依赖用户数据，纯逻辑自测；跑 `python modules/<名>/selftest.py` 全过才算写完。
- `CLAUDE.md`：照 `core/config/CLAUDE.md` 的版式（这是什么 / 职责 / 对外接口 / 谁在用 / 改完必须做）。

**只做一件不可再分的事**：想在积木里加「顺便还做 XX」时，XX 属于上层，请放到工作流层。

## 八、验证纪律（每次改动，缺一不可）

```bash
python modules/<改动的积木>/selftest.py     # 改积木先验单块
python 平台管理/health_check.py              # 全局体检，确认没碰坏别人
python 平台管理/交接.py                       # 改动后顺手刷新 CLAUDE.md 结构树 / HANDOVER.md
```

然后：技术发现记 `docs/踩坑记录.md`，改动记 `docs/变更记录.md`，**git commit**（每步一个提交，可回退）。

## 九、命名约定

- 文件、函数、变量：小写下划线（`fetch_library_snapshot`、`have_dois`）。
- 函数名动词开头；返回「是否有/是不是」的用 `has_`/`is_` 前缀（`has_*`、`is_oa`）。
- 集合/列表用复数名词（`have_titles`、`works`）；布尔开关常量大写（`REBUILD`、`APPLY`）。
