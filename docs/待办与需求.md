# 待办与需求 · 两侧工单板

> **这是应用侧 ↔ 设计侧之间的需求传递通道。**
> 用户在两个对话间搬运信息：应用侧用平台时发现「需要架构性改动」的问题就记这里，
> 设计侧接手时先扫这份，挑能做的实现，做完改状态。
>
> **和另外两份日志的区别：**
> - `踩坑记录.md` = 已诊断清楚的问题 + 根因 + 解法（知识沉淀）
> - `变更记录.md` = 已经做完的改动（交接流水账）
> - `待办与需求.md`（本文件）= **还没做、需要另一侧处理的事**（工单）
>
> ## 怎么用
> - **应用侧**发现「用不顺、需要改架构」→ 加一条：现象 + 期望 + 提出方 + 状态`待处理`。
>   （小 bug 应用侧自己修并记变更记录即可，不用进这里；这里只放需要设计侧动的。）
> - **设计侧**接手先读本文件 → 实现后把状态改 `已解决`，注明改了哪些文件 / 关联踩坑编号。
> - **用户**是两侧传声筒：把应用侧的诉求带到设计侧对话，让设计侧看这个文件接单。
>
> 格式：`- [状态] 标题 · 现象 · 期望 · 提出方/日期 · (解决说明)`
> 状态取值：`待处理` / `处理中` / `已解决` / `搁置`

## watcher 重复实例（面板发现，2026-08-06）

一天内第二次出现 2 个 zotero_watcher 并存。看门狗 `restart_watcher()` 先 taskkill 再启动，
但仍有漏网 —— 疑似「任务计划自启的那份」与「看门狗启的那份」互不相识。
影响：两份都在轮询，会抢同一篇文献的处理权，可能重复精读/重复上传。
建议解法：给 watcher 加**单实例锁**（启动时抢一个 lock 文件，抢不到就退出），
比让看门狗去杀更可靠 —— 从源头杜绝而不是事后补救。
面板已能一眼看出该问题（重复实例会标红）。


### ★ 决定性实测：方向层不需要全文，因此**不受开放获取偏倚影响**

拿我们语料里 200 篇真实论文（多为 AM / AFM / Angew 这类付费刊）实测：

```
开放获取        60 (30%)
付费墙         140 (70%)
有摘要         200 (100%)
★付费墙里有摘要 140 / 140 = 100%
```

**OpenAlex 对付费墙论文同样提供摘要。** 开放获取偏倚咬的是**全文**，不是元数据和摘要。

后果很大：
- 方向层可以覆盖**整个领域**（含付费墙论文），合法、免费、无需 PDF
- 前面担心的「AI 工具只看得见开放获取那一小撮」，**在方向层不成立**
- 全文只在细节层才是瓶颈 —— 而细节层用户明确说先不做

滚到 K 轮不出新文献为止。**收敛才是边界，关键词只是起点。**

### ⚠ 2026-08-30 动手前的现成方案调研（宪法【零号判据】，此前漏做了一次）

**背景**：`domain/bibliometrics` 是我直接开写的 —— Louvain、模块度、文献耦合全部手写，
**没有先查有没有现成的**。用户问「是不是都在重新写」时才补做这次调研。
教训不在已经写的那部分（沉没成本），在于**后面三项动手前必须先查**。

| 计划项 | 现成方案 | 判断 |
|---|---|---|
| **B3 跟进厚度** | `cdindex`（CD/颠覆指数，C 后端，Russell Funk 本人写；另有 novelpy / fast-cdindex）+ sleeping beauty / beauty coefficient | **用现成，而且比原设计好**（见下） |
| **C1 主路径** | **`pybibx`**：内置 Main Path Analysis，支持 SPC / SPLC / SPNP 三种搜索路径法（2026-06 还在更新） | **用现成** |
| **B4 社群桥接** | `networkx`：betweenness_centrality、Burt 结构洞（constraint / effective_size） | **用现成** |
| 聚类 | networkx 3.6 内置 Leiden | **不换**（见下） |
| OpenAlex 客户端 | `pyalex` | **不换**（见下） |

全部可安装（实测 PyPI）：litstudy 1.0.6 · cdindex 1.0.20 · pyalex 0.21 ·
networkx 3.6.1 · leidenalg 0.12.0 · python-igraph 1.0.0 · novelpy 1.4 · pybibx 5.9.5

**① CD 指数比「数跟进篇数」强在哪**（这是本次调研最大的收获）：
它测的是**后来引用这篇的人，是「引它而不再引它的前驱」，还是「连它前驱一起引」** ——
前者说明这项工作**改变了路线**，后者说明它只是**巩固了既有路线**。
这比单纯的被引数或跟进篇数更接近用户想要的「这个结果到底成不成」。
⚠ 但它**需要前向引用网络**（谁引了它、那些人还引了谁），所以 **B2 前向雪球仍是前提**。
⚠ 且网络不完整时 CD 有偏，覆盖度要先报出来。

**② 为什么不换 Leiden**：Leiden 的卖点是修 Louvain「社区内部可能断开」的毛病
（原论文实测最多 25% 连接差、16% 断开）。**在我们的图上实测：47 个簇 0 个断开**。
因为我们的图很稠密（3720 节点 / 317,818 条非零边，平均每点 85 条边），
Louvain 的失效场景是稀疏图 + 反复迭代。**换了不改变结果，所以不换。**

**③ 为什么不换 pyalex**：`adapters/openalex` 现在编码了两条用血换来的知识 ——
踩坑 #76（批量静默丢 30% 数据）与 #77（2026-02 起按量计费 + 免费单条端点兜底）。
换客户端要重新确认它有没有处理这两件事，收益不抵风险。

**判据（补进宪法的实践部分）**：
> **「先查现成的」这条，最容易在「我知道这个算法怎么写」的时候被跳过。**
> 恰恰是这种时候最该查 —— 因为能写出来不等于该自己写，
> 而且现成实现里往往带着你想不到的更好指标（本例：CD 指数之于「跟进厚度」）。

## ✅ 2026-08-30 · R2 窗留下的两处 `tools` 调 `tools`（**R7 窗已解决**）

REBUILD.md 第三节硬规则 2 写着「`tools/*` 不许 import 别的 `tools/*`」，
但 R2 窗搬完之后有两条真实的业务闭环横跨两个工具：

| 位置 | 调用 | 为什么它在那儿 |
|---|---|---|
| `tools/deepread/watcher.py` `process_item()` | `tools.extract.run(key)` | 「打个标签就全自动」这条闭环本来就是精读**加**抽取。而 REBUILD.md 又明确要求 watcher 住在 `tools/deepread/` |
| `tools/extract/batch.py` `_rebuild_index()` | `paperdb.rebuild()` | paperdb 是 `structured/*.json` 的**索引**，抽完不刷新它，用户查到的就是旧数据 |

两处都做成了**延迟 import + 就地写明理由**，第二处还做成了失败不致命。

**R7 窗要做的选择**（守卫写出来之前必须先决定，否则守卫一加就红）：

- **选项 A**：把 `watcher.py` / `watchdog.py` 挪去 `host/` —— 它们本来就是
  「让平台活着的东西」而不是一项能力，而 `host/` 可以 import 一切。
  代价：REBUILD.md 第四节的映射要改一行。
- **选项 B**：把跨工具的那一步做成**调用方传进来的回调**
  （`deepread.run(..., after=extract.run)`），谁组合谁自己负责。
- **选项 C**：承认「刷新索引是抽取的一部分」，把 paperdb 降级成 `shared/` 里的一块。
  代价：它有自己的 CLI 和 MCP 暴露，不太像共用件。

**R7 窗的落地（2026-08-31）：选了 A，第二处用了 C 的判据但没降级 paperdb。**

· `watcher.py` / `watchdog.py` → `host/watcher/{service,watchdog}.py`。
  判据是 host 的定义本身：不是能力，是让平台活着的东西；硬规则 4 又明写
  host 可以 import 一切。理由写在 `host/watcher/__init__.py`。
· 索引刷新**不再由抽取方负责**，改成 `paperdb.query()` 每次比一眼时间戳、
  比源 JSON 旧就自己重建（秒级、不花钱）。没有降级 paperdb ——
  它有自己的 CLI 与 MCP 暴露，确实不像共用件。
  **真正的毛病不在那行 import，而在责任放错了地方**：让写入方负责，
  就得每个写 JSON 的人都记得刷一次，漏一个用户就查到旧数据且不报错。
· `wizard._index_stats()` 改成直接调 `shared.domain.schema.coverage`，
  与 `paperdb.stats()` 同一口径、同一个函数，不是复制一份。
