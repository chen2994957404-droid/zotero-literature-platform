# 待办与需求 · 两侧工单板

> **这是应用侧 ↔ 设计侧之间的需求传递通道。**
> 用户在两个对话间搬运信息：应用侧用平台时发现「需要架构性改动」的问题就记这里，
> 设计侧接手时先扫这份，挑能做的实现，做完改状态。
>
> **和另外两份日志的区别：**
> - `踩坑记录.md` = 已诊断清楚的问题 + 根因 + 解法（知识沉淀）
> - `变更记录.md` = 已经做完的改动（交接流水账）
> - `待办与需求.md`（本文件）= **还没做、需要另一侧处理的事**（工单）
>
> ## 怎么用
> - **应用侧**发现「用不顺、需要改架构」→ 加一条：现象 + 期望 + 提出方 + 状态`待处理`。
>   （小 bug 应用侧自己修并记变更记录即可，不用进这里；这里只放需要设计侧动的。）
> - **设计侧**接手先读本文件 → 实现后把状态改 `已解决`，注明改了哪些文件 / 关联踩坑编号。
> - **用户**是两侧传声筒：把应用侧的诉求带到设计侧对话，让设计侧看这个文件接单。
>
> 格式：`- [状态] 标题 · 现象 · 期望 · 提出方/日期 · (解决说明)`
> 状态取值：`待处理` / `处理中` / `已解决` / `搁置`

## watcher 重复实例（面板发现，2026-08-06）

一天内第二次出现 2 个 zotero_watcher 并存。看门狗 `restart_watcher()` 先 taskkill 再启动，
但仍有漏网 —— 疑似「任务计划自启的那份」与「看门狗启的那份」互不相识。
影响：两份都在轮询，会抢同一篇文献的处理权，可能重复精读/重复上传。
建议解法：给 watcher 加**单实例锁**（启动时抢一个 lock 文件，抢不到就退出），
比让看门狗去杀更可靠 —— 从源头杜绝而不是事后补救。
面板已能一眼看出该问题（重复实例会标红）。

## 【专家层】窄带完备图 · 路线（2026-08-29 立，用户拍板"先做窄带"）

> **目标**：不是做大模型，是做**大模型能调用的库**。最终形态：接上 MCP 后，
> 问"这方向最近什么动态"，agent 能像资深导师那样回答，且每句有出处。
>
> **核心判断（写在最前面，别忘）**：
> **"大"是错的轴。** 专家和 RAG 的差别不是读得多，是**有判断**；
> 而判断不来自更多论文，来自**对已有论文做计算**（数值分布 / 跟进厚度 /
> 引用语境 / 主路径 / 团队图谱）。堆一百万篇 PDF 进向量库，一条也得不到。
>
> **完备性是有停止判据的**：窄带的相关文献是**有限集合**（实测外推 1000~3000 篇），
> 雪球滚到 K 轮不再冒新文献即完备。这跟 OpenScholar 的 4500 万篇是不同的游戏 ——
> 他们要广（只能拿开放获取的），我们要**深且全**（一条窄带里做到完备）。

### ⚠ 架构要求：窄带必须是**参数**，不是硬编码

用户明确说了「我有别的感兴趣方向可以再专门做」。所以第二条窄带必须是
**加一份配置**，不是改代码。当前 `core.paths.direction_db()` 是单例，**要改成按窄带分库**：

```
workflow_data/direction/<band>/map.db      每条窄带一个库
workflow_data/direction/<band>/band.json   窄带定义（关键词/种子DOI/边界判据）
```

### 三条做不到的（天花板，提前写下来免得反复讨论）

1. **付费墙外的全文** —— 只能覆盖用户合法拥有的那些。全世界都一样。
2. **失败与阴性结果** —— 几乎不发表。资深导师最值钱的「我们试过，不行」
   文献里没有。**任何系统都补不了这一条。**
3. **没喂过的方向** —— 窄带外退回普通大模型。这是「做窄才有优势」的另一面。

### 参考的外部现状（2026-08-29 查证，别凭印象推翻）

- **OpenScholar**（Ai2+UW，Nature）：45M **开放获取**论文；8B 模型正确性超 GPT-4o 5%；
  GPT-4o 编造引用 78~90%，它的引用准确率接近人类专家。
  **但它的语料就是开放获取** —— 最强的系统天生带着用户抱怨的那个偏倚。
- **PaperQA2**（FutureHouse）：LitQA2 上超过博士/博后；**开源包，能跑在自己的 PDF 上**。
  ContraCrow 做矛盾检测：随机生物论文平均每篇 **2.34 条陈述被其他文献反驳**。
- **GraphRAG**（微软）：RAG 在面向整个语料的**全局问题**上结构性失效
  （那是查询聚焦摘要，不是检索任务）。我们的引用网络聚类是同一思路的另一种实现。
- **领域专用模型不要做**：LLaMat 用 4M 论文 / 30B token 才超过通用模型；
  而 Darwin 1.5-7B、ChemLLM-7B **反而不如通用大模型**（输在指令跟随）。
- **开放获取偏倚实测**：各家大模型引用里 77.3%~91.8% 指向 OA 文献；
  而化学工程领域 OA 占比**不到 10%**。

### 需要用户确认的（只有一件）

**窄带边界**。基于实测数据的建议（见变更记录 08-29 全量地图）：

```
核心    聚硼硅氧烷 / 硼硅氧烷（polyborosiloxane, boron-siloxane）
紧邻    硼系动态键（boronic ester / B–O / B–N 配位）  ← 簇1 里 8 篇，整簇 ↑↑
功能    剪切硬化 / 冲击硬化 / 阻尼（shear & impact stiffening, damping）← 散在簇 21/5/10/18
骨架    硅氧烷弹性体（silicone / PDMS elastomer）
```

理由：PBS 本身在 19 个月高水平推送里**只有 1 篇**，单独做种子太薄；
而硼系动态键整簇在快速升温。按上面四条画边界，既盖住用户的体系，
又能借到相邻热区的引用网络。
