## 零、一句话

**目标：让编程端能自己验证「写 Zotero」那一半，然后把剩下的工作流也收进 `pipelines/`。**

这两件事是一根链条：阶段 3 把工作流从「五个 subprocess」改成函数之后，
逻辑是能测了，但**回写 Zotero 那一段在编程端仍然一次都没跑过** ——
因为以前编程端和主力机共用同一个 Zotero 账号，一写就污染真实文献库。
独立的测试账号解开的正是这一环。

## 二、第一段：把测试端配通 ✅ 已完成（2026-08-27）

> 角色 `test`、写回 id 与测试 id 一致、三把密钥（DeepSeek / Zotero / MineRU）就位，
> 体检那行已变绿。下面保留操作步骤，换机器或重装时照做。

### 你要做的三件事

1. **建 API key**：<https://www.zotero.org/settings/keys> → 用**测试账号**登录 →
   New Private Key → 勾 **Allow write access** → 保存。
   同一页面上能看到 **userID（一串数字）**，记下来。
2. **在控制面板填 4 项**（先把面板关掉重开，它得跑新代码）：

   | 项目 | 填什么 |
   |---|---|
   | 机器角色 | `test` |
   | Zotero 用户 ID（本地 API） | `0` |
   | Zotero 用户 ID（写回用） | 上面那串数字 |
   | 测试账号的用户 ID | **同上，填一模一样的值** |
   | 密钥区 `ZOTERO_API_KEY` | 刚建的那个 key |

   > 最后两项要一致才放行，这是「别把测试改动写进真实文献库」的执行点。
3. **往测试库里再导 1~2 篇**：一篇**带 SI**（否则 SI 分支测不到），
   一篇**图多**的（验证裁图）。等它同步下来、PDF 落到本地。

### 判据（怎么算这一段完成）

控制面板的体检里出现这一行：

```
[OK] 机器角色: 编程端·测试库（A 机 + 测试 Zotero 账号） —— 允许写，且已确认写回目标是测试库
```

没配对会直接报 `[FAIL]` 并写清楚要改哪一项 —— **不用你自己记得配对没有**。

## 三、第二段：端到端验证 ✅ 已完成（2026-08-27，193 秒跑通）

> 三步全过：零成本回写链路（当场抓到踩坑 #64）、真跑一篇（正文+SI+合并+抽取+回写）、
> 幂等与只补缺的部分。详见 `docs/变更记录.md` 当日条目。
> 下面保留原计划，作为「以后改了精读线该怎么验」的标准动作。

### 原计划（现为回归验证的标准动作）

分三步，**从零成本到花钱，按顺序来**。

### 3.1 只验回写链路（不花钱）

拿一份假的 `summary.html` 走完：上传附件 → 复用已有附件条目 →
覆盖本地 storage → 换状态标签。这段以前在编程端完全无法验证，
而它恰恰是踩坑最多的地方（#28 反复弹同步冲突框就出在这儿）。

**判据**：测试库那篇文献上出现 summary 附件、标签变成「正文精读」，
再跑一次不产生新附件（复用生效）、Zotero 不弹冲突框。

### 3.2 真跑一篇精读（花钱，约 1 篇的 MineRU + DeepSeek）

在测试库里给那篇打「待处理」，让 watcher 跑一遍完整流程。

**判据**：`summary.html` 生成且正文 ≥ 3000 字；
`workflow_data/state.db` 里有 parse / main_summary 两条 `ok` 记录；
Zotero 标签换成「正文精读」；带 SI 的那篇跑出「全文精读」。

### 3.3 幂等与续跑（不花钱）

再打一次「待处理」，确认**一步都不重跑**；
删掉 `summary.html` 再打一次，确认**只补它一个**。

**判据**：日志出现「[跳过正文] 已有精读，不重跑」；状态库里不新增 running 记录。

> 做完这三步，「watcher 端到端」就第一次有了**可重复**的验证手段。
> 在此之前，每次改精读线都只能推到主力机上赌一把。

## 四、第三段：阶段 3 下半（我做，可与第二段并行）

按收益排序：

## 五、这条路上已知的几个坑（别重踩）

- **面板是常驻进程**：改了 `panel.py` 必须关掉重开，否则你看到的还是旧界面。
  更阴的是浏览器标签页里的 JS 也是旧的 —— 刷新页面不够，要重开面板。
- **换 Zotero 账号**：要么新建 profile + 新数据目录，要么**先退出账号、再清空本地**。
  顺序反了（登着旧账号做「重置」并选「推上服务器」）会清空真实库并同步到主力机。
- **测试端不注册自启任务**：watcher 手动起（`精读监听.bat`），验证完就关。
  注册了会跟着开机长跑，白烧 API 额度。
- **主力机什么都不用改**：新增的配置项没填时自动沿用旧值。
  但阶段 3 的代码推过去之后，**要在主力机实测一篇精读**（那边才是权威数据）。
