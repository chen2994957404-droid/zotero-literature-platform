# 深度研究：通用章法

**这是给模型的章法，不是给人的。** 用户的问题通常是一句话，一次检索答不了。
下面的每一步都有出处（信息检索与系统综述方法学的既有结论），不是本项目自己发明的；
项目只是把每一步对应到手头的工具。

## 先认清问题是哪一类

| 类型 | 典型问法 | 主策略 |
|---|---|---|
| 交集 / 可行性 | 「在 A 上引入 B」「A 和 B 结合有人做过吗」 | 积木式 + 邻域放宽 + 质疑空集 |
| 版图 / 综述 | 「这个方向都有谁在做、分几支」 | 逐步收窄 + 滚雪球 |
| 机理归因 | 「X 性能到底来自什么」 | 滚珠式（从一篇公认的好文出发）|
| 方法 / 配方 | 「Y 是怎么做出来的、条件是什么」 | 库内检索直取 SI + 表 |
| 数值比较 | 「哪些体系的 Z 超过多少」 | `paperdb` 直查，不必检索 |

## 第 0 步 · 分面 + 同义词族（所有类型都先做这一步）

把问题拆成 **2～4 个概念面**（材料 / 结构或基团 / 性能或现象 / 方法），每一面写一张
**同义词族**：正式名、缩写、拼写变体、相邻领域的叫法、上位与下位概念。
这是 Harter 的「积木式」策略的前提（Marchionini 第 5 章），也是 Wohlin 滚雪球指南里
「起始集要顾及同义词，否则只抓到用某一种术语的文献」那条。

- 词从哪来：**先从证据库原文里取**（`library_retrieve`，零成本），再从 `lit_abstract`
  读几篇摘要补；别只凭记忆列
- 常见的坑：**用材料名当检索词**。要找的往往是「材料 A + B 的**性能来源基团**」，
  不是「材料 A + 材料 B」—— 后者直接做的人可能就没有，搜不到不说明什么

## 第 1 步 · 选策略并检索（四种经典策略，按需组合）

| 策略 | 做法 | 什么时候用 |
|---|---|---|
| **积木式**（building blocks，Harter 1986） | 每一面用 OR 把同义词族并起来，面与面之间 AND | 默认；问题面清楚时 |
| **逐步收窄**（successive fractions，Meadow & Cochrane 1981） | 先拿一个大集合，再逐面加条件缩 | 问题模糊或很宽；便于回退与监控 |
| **滚珠式**（pearl growing，Markey & Cochrane 1981） | 从一篇已知相关的好文出发，用它的术语、引用、被引扩 | 手上已有一篇公认的好文时 |
| **交互扫描**（interactive scanning，Hawkins & Wagers 1982） | 先粗搜一大把，扫读后提炼术语、作者、方法，再逐轮改检索式 | 领域陌生、还不知道该用什么词 |

对应工具：`lit_search`（看 **total**：这个词全世界多少篇，决定收窄还是放宽）；
结果里 `【可读:id】` 的先读，`【库里有】` 的用 `paper_fulltext` 解析，都没有的按需取（默认 3 篇，慢）。
读法：`library_outline` 看菜单 → 只点要的节 / 段 / 表（`s5.p3`、`t1`）；配比、条件在 SI（`si=true`）。

**邻域放宽**（交集类问题的关键一步）：把某一面换成它的上位或同族概念（母体换近亲、
基团换同一族的键），先看别人在近亲体系里怎么做、踩过什么坑。这一级几乎一定有货。

## 第 2 步 · 滚雪球（Wohlin 2014 的准则）

- **起始集要多样**：覆盖不同出版商、年份、作者，且**彼此不互引**（避免只滚到一个小圈子）；
  领域越宽起始集越大
- 每篇先确认**确实相关**再拿它滚；先剔掉不符合语言 / 年份 / 类型的，再剔掉已见过的
- **前向 + 后向**都做：`lit_references`（它引了谁）、`lit_cited_by`（谁引了它）；
  证据库内部用 `library_refs`（★ 的已在库里能直接读）
- 迭代到**一轮下来没有新文献**为止

## 第 3 步 · 空白的确认：永远质疑空集

Bates 的检索战术里有一条硬规矩：**always question null sets** —— 空集先当成检索式的错，不当成事实。
要说「没人做过」，必须：

1. 每一面至少换过 2～3 种说法再搜（同义词族用完）
2. 从邻域的好文做过前向雪球，确认引用它们的人没有走到这个交集
3. 把「搜过哪些说法、各自 total 多少」原样写进报告

做不到这三条，报告里只能写「没搜到」，不能写「没人做过」。

## 什么时候停

系统综述文献里常用的三种停止判据（择一，且**在报告里写明用了哪一种**）：

- **理论饱和**：新一轮检索 / 雪球不再带来新概念或新文献（首选）
- **工作量上限**：只看前 N 条 / 只滚 K 轮（要明说 N、K）
- **穷尽**：把能找到的全找完（很少用得起）

## 报告的形状（给用户看的，中文）

1. **版图**：面 × 面的矩阵，每格谁做了（id / DOI）
2. **已有路线各自的优缺点**，每条带出处（id + 节地址，如 `<id> s4.p1` / `t4`）
3. **空白**：搜过哪些说法、total 各多少、哪些空；雪球滚了几轮
4. **判断与建议**：这一部分是模型的判断，**明确标出来是判断**
5. **停止判据**：用了哪一种、为什么
6. 附：读过的全文清单（id），用户勾选哪些推到 Zotero

## 别做的

- 别用 `ask_library` 找新方向 —— 那是问他自己的库；找原料用 `library_retrieve`
- 别把整篇端上来 —— 先菜单再点节；长节点段
- 别把「没搜到」写成「没人做过」（第 3 步没做完之前）
- 每条事实带 id 或 DOI；带不上的写「据记忆，未核实」
