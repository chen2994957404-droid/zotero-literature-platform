# 深度研究：怎么用这套工具把一个方向研究透

**这是给模型的章法，不是给人的。** 用户（材料研究者）提的往往是一句话：
「我想直接在聚脲结构上引入聚硼硅氧烷性能来源的基团」。
一次检索答不了这种题 —— 它是一道**翻译题 + 邻域题 + 空白题**。照下面四级走，
每级的产物是下一级的输入；跳级会退回到用户已经做过的东西（2026-09-13 实战教训）。

## 第 0 级 · 翻译：把材料名翻成基团名（问用户自己的库，零成本）

直接搜「聚脲 + 聚硼硅氧烷」几乎搜不到 —— 直接做这件事的人可能就没有，这正是它值得做的原因。
要找的不是「材料 A + 材料 B」，而是「材料 A + **B 的性能来源基团**」。

- `library_retrieve "PBS 的自愈 / 抗冲击性能归因于哪些键"`（`where=main`）→ 看几段原文
- 必要时 `library_section` 读那几节；`ask_library` 只在需要一段中文综合时用（花钱）
- **产物：一张同义词族表**：B–O 配位键 / boroxine / B←N / boronic ester / Si–O–B …
  之后所有检索式都从这张表长出来，**不从材料名长出来**。

## 第 1 级 · 邻域：谁已经把这些基团放进了别的母体

把母体换成近亲（聚氨酯、聚氨酯脲、硅氧烷-脲、环氧、聚酰胺），基团族逐个组合：

- `lit_search "boronic ester polyurethane dynamic network"`、`"boroxine crosslinked polyurethane"`…
  看 **total**（这个词全世界多少篇）决定收窄还是放宽；结果里 `【可读:id】` 的先读，`【库里有】` 的
  用 `paper_fulltext` 解析，都没有的按需 `paper_fulltext` 取（默认最多 3 篇，取是慢的）
- 这一级**一定有货**。你要的是他们踩过的坑：硼氧键遇水、与脲基氢键的竞争、硼怎么引进去
- 读法：`library_outline` 看菜单 → 只点 `[合成]` `[结果]` 那几节，或直接点 `t1` 表、`s5.p3` 段
- 顺着走：`library_refs id` 看它引了谁、哪些已经在库里能直接读（★）

## 第 2 级 · 引入方式：硼从哪进来（化学层面的三条子路）

- 含硼单体：`"boron-containing diamine polyurea"`、`"diol boronic acid chain extender"`
- 含硼交联剂：`"boric acid crosslinker amine"`、硼酸酯与端羟基/端氨基
- 一锅 / 原位：`"in situ borosiloxane polyurea one-pot"`
每条子路各搜一遍，记下**空的检索式** —— 空本身就是信息。

## 第 3 级 · 交集与空白：直接做的有没有

- `lit_search "polyurea boroxine"`、`"polyurea boronic ester"`… **多换几种说法都空了**，
  才敢说「没人做过」（零号判据：外部事实要核实，一条检索式空不算数）
- 从第 1、2 级挑 3 篇最贴的做雪球：`lit_cited_by`（后来谁引了它）、`lit_references`（它的根在哪），看引用它们的人有没有往聚脲走
- `paperdb` 查数值：已抽取的库里，含硼体系的拉伸强度 / 自愈效率分布如何

## 什么时候停

连续两轮没有新的相关文献（新检索式命中的都是已见过的），或读的全文已覆盖每条子路
至少两篇。不要为了「全」无限扩。

## 报告的形状（给用户看的，中文）

1. **领域版图**：基团族 × 母体近亲，各格谁做了（id / DOI）
2. **已有引入方式各自的优缺点**，每条带出处（id + 节地址，如 `2RXYSQLE s4.p1` / `t4`）
3. **直接交集有没有人做**：搜过哪些说法、哪些空
4. **建议路线与风险**（这一部分是模型的判断，**明确标出来是判断**）
5. 附：读过的全文清单（id），用户勾选哪些推到 Zotero

## 别做的

- 别用 `ask_library` 找新方向 —— 那是问他自己的库
- 别把整篇端上来 —— 先菜单再点节；一节 8000 字的点段
- 别在报告里把「没搜到」写成「没人做过」，除非第 3 级做完了
- 每一条事实都带 id 或 DOI；带不上的写「据记忆，未核实」
