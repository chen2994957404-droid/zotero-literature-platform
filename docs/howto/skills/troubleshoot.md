# 排障速查

**铁律：先假设这是已知坑，别现场推理。** `docs/incidents/踩坑记录.md` 有 90 条编号记录，
140 KB —— 它不进上下文，所以必须靠这份索引定位，再去读那一条的原文。

## 一、五条最常把人骗过去的诊断错觉

这五条比任何具体坑都值钱，因为它们让你**以为自己已经排除了故障**：

| 错觉 | 真相 | 坑号 |
|---|---|---|
| 心跳正常 = 工作正常 | watcher 心跳照打，活一篇没干，静默停摆 19 分钟 | #33 |
| 能 import 成功 = 代码没问题 | import 只证明语法过了，函数体里的 NameError 照样在 | #49 |
| 文件换掉了 = 部署完成 | **常驻进程不重启就一直跑旧代码**（watcher / 面板 / Ollama） | #50 |
| 体检是绿的 = 环境是好的 | 体检报「密钥已安全存放」，实际一个都没存；主力机密钥早失效 | #45 #66 |
| 显示乱码 = 只是显示问题 | 长期误诊。子进程编码是**真的把数据写坏了** | #32 #54 |

**推论：任何「我改了但没生效」，第一嫌疑人永远是「跑的是旧代码 / 旧配置」。**

## 二、现象 → 坑号 速查

### 服务不工作
- Ollama 返回空模型列表（"失明"）→ **#4**：启动时没拿到 `OLLAMA_MODELS`。
  `Start-ScheduledTask -TaskName OllamaService`；路径配在控制面板，别写死。
- 常驻服务（`host/watcher/`）打了标签没反应 → **#67**（重新打标签不触发）、**#29**（触发标签名改了）
- watcher 被反复杀 → **#61**（看门狗在杀正在干活的）、**#62**（它是孙子进程，重启计划任务换不掉）
- 面板/子进程弹黑窗口 → **#25 #26 #31**（`-Hidden` 对控制台程序无效）

### 环境与进程
- 子进程拿不到刚 `setx` 的环境变量 → **#19**（MINERU_TOKEN 导致 SI 全失败）
- `pip install -e .` 装完当前进程还是 import 不到 → **#55**（要重开进程）
- 按名字杀进程把自己杀了 → **#56**
- PowerShell 的「当前位置」≠ .NET 的「当前目录」 → **#52**
- 「固定睡 N 秒再打开」→ **#57**，那是在赌，改成轮询条件
- 修环境的工具自己被环境卡死 → **#53**

### 编码（三个地方分别咬人，见 #60）
- PowerShell 输出是 gb2312，按 UTF-8 解码全乱 → **#54**
- 子进程中文乱码 → **#11 #32**
- 改 stdout 编码写法有坑，跑到一半 print 崩 → **#37**
- MCP 服务只设了 stdout 忘了 stdin，中文搜库全乱 → **#43**
- `.bat` 里的非 ASCII 字符 → **#60③**

### 配置 / 密钥
- 面板上改了存不进去 → **#58**（存不进）、**#63**（没点保存就被自动刷新冲回）、**#59**（配置区变 NaN）
- 改了配置不生效 → **#46**：面板存的键名和积木读的键名对不上
- 密钥类问题 → **#45 #66**，且注意 SSH 里跑不了要花钱的作业（拿不到密钥，见 two-machines）

### 模型行为反常
- 精读只出图没有字 → **#27**：DeepSeek V4 思考模式吃光 max_tokens
- SI 精读时成时败 → **#65**：SI 线的 token 额度只有正文线的 1/5
- 长批量任务一撞 5xx 就白跑 → **#28**：云端 API 抖动没重试
- 本地 qwen3.5「卡死」→ **#41**（中文 system 极慢 + 思考模式 + 模型名没对齐）、**#43**（num_ctx 默认 16k 装不下全文）
- 图表数字化数字是假的 → **#15 #16**：本地 7B 会编等差数列，**必须用云端大模型**
- 结构化抽取大面积 N/A → **#12**（schema 字段太窄）、**#68**（从没打开过补充材料）
- 检索召回崩塌 → **#35**（中文检索式）、**#39**（缩写歧义/阈值杀光结果）、**#38**（雪球被高被引通用文献带偏）

### Zotero
- 本地 API 说「刚传的东西不在」→ **#64**，这是它的固有行为，别怀疑上传失败
- 每篇都弹冲突解决框 → **#18**（回写「先删后传」的删除进了同步链）
- 找不到文件 → **#20**（附件记录的文件名与实际写入不一致）
- 精读误读了补充材料 → **#15**（Springer 的 MOESM/ESM 命名逃逸正则）
- SI 漏检 → **#21**（Elsevier 的 SI 是 .docx 不是 PDF）

## 三、本机固有约束（不是 bug，别去修）

- **MCP 调用约 60 秒超时**：精读、全库抽取、大模型读图必然超时，但后台继续跑。
  用「发起后轮询文件结果」，别干等。
- **A 机没有 Ollama / 没有主力机的密钥**：完整体检在 A 机会红，这是正常的。
  只有 `python host/doctor/health_check.py --offline` 该全绿。
- PowerShell 控制台中文乱码：**先用 Read 工具读文件确认真实内容**，再判断是显示还是数据。

## 四、排障纪律

1. 定位到坑号 → 读 `docs/incidents/踩坑记录.md` 那一条的原文（现象/根因/解法三段齐全）
2. 查不到 → 说明是新坑。修完**当场**追加一条到 `docs/incidents/踩坑记录.md`（编号 + 现象 + 根因 + 解法），
   用 Python `io.open(...encoding='utf-8')` 追加，别用 PowerShell 重定向（GBK 乱码）
3. 涉及主力机（B 机）的故障：你在 A 机看不到它的状态，别猜 —— 见 `two-machines` skill
