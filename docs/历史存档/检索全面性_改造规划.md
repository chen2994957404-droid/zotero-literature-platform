## 0. 规划前补测到的四个事实（它们改变了设计）

| # | 事实（2026-09-24 A 机实测） | 对设计的影响 |
|---|---|---|
| F1 | **Elsevier 的文章在 OpenAlex 里大多没摘要**：「shear stiffening」2023 年后 146 篇，Elsevier 49 篇只 13 篇有摘要、RELX 8 篇 0 篇；全部 146 篇里 55 篇缺摘要。Semantic Scholar 对这 55 篇**一篇摘要都没有**，Crossref 也没有（Elsevier 不交摘要） | ① 判相关时 1/3 的候选只有标题 → 必须如实标「只凭标题」，不能硬判；② 按意思检索对这批文章只能靠标题匹配，**天然偏向非 Elsevier** → 词面与引用两条腿不能省；③ 补摘要的唯一靠谱来源是 Elsevier 自己的 API（免费注册，受机构订阅约束）→ 要你定 |
| F2 | OpenAlex 按意思检索**每次最多 50 条、不能翻页**（page=2 返回空，per_page=100 报错） | 要多于 50 条就**按年份切片**分几次调 |
| F3 | 按意思检索**悄悄忽略排序参数**，不加年份过滤时返回的多是 1994–2017 的老文章 | 「最新进展」类问题**必须带年份窗口**，工具默认把年份窗口写进返回头，提醒 agent |
| F4 | 单次调用 2～5 秒；每次 0.001 美元，免费 key 每天 1 美元 ≈ 1000 次 | 一轮十几次调用毫无压力；MCP 60 秒超时只在「切很多片」时要防 |

## 1. 目标形状：一轮 = 三条腿 + 判 + 记 + 挖词

```
            ┌─ 词面：lit_search（同义词族，精确匹配，可 200 条）
  第 N 轮 ──┼─ 语义：lit_semantic（一段话 / 照着已判相关的几篇找）
            └─ 引用：lit_snowball（最好的几篇前后向，一次多篇）
                     │（结果自动进台账：只给新的，标渠道、标有没有摘要）
                     ▼
            agent 读 → lit_judge（按条判：满足哪几条要求）
                     ▼
            lit_status（每轮新增相关数、各渠道重叠 → 还漏多少的估计）
            lit_terms （相关篇里挖出的新说法、常见作者/期刊）
                     ▼
            agent 决定：再来一轮 / 停下问用户 / 出报告
```

## 2. 分块设计

### A. 语义渠道 `lit_semantic`（新 MCP tool，不弹窗）

- **适配器**：`shared/adapters/openalex` 加 `semantic_search(text, filters, limit≤50)`，只这里联网；
  2000 字截断在适配器里做并如实返回 `truncated`。
- **两种输入**（二选一）：
  - `text`：一段话描述要找什么（agent 写，英文；官方说一段话比短语好）
  - `like=[DOI…]`：照着这几篇找 —— 工具自己取每篇的标题 + 摘要（没摘要用标题并标出），
    **每篇单独调一次**（每篇 ≤2000 字），结果按「被几篇同时召回 + 名次」融合（RRF，倒数名次融合，标准做法）。
    这就是相关反馈，agent 不用把摘要搬进上下文。可选 `unlike=[DOI…]`：把跟这几篇最像的往后排（同样是 RRF 减分）。
- **年份**：`yearFrom / yearTo`；`slice_by_year=true` 时按年各调一次（每片 50 条），**最多 6 片**（防 60 秒超时）。
- **返回头**写明：本次调了几次、年份窗口、「语义检索最多 50 条/次，不能翻页，不按年份排序」、
  「无摘要的文章只按标题匹配，Elsevier 居多」。
- 结果行格式与 `lit_search` 完全一致（同一个 `_line`），另加 `【无摘要】` 标记（词面检索也加）。

### B. 批量雪球 `lit_snowball`（新 tool；旧 `lit_cited_by / lit_references` 保留不动）

- 输入 `dois=[…]`（≤10 篇）、`direction=forward|backward|both`、`yearFrom`。
- `snowball.expand` 已支持多种子；工具额外统计**每篇被几个种子连到**（多个相关篇都引 / 都被引的，最该先看），按这个排。
- 这是「排序」但只按可数的事实（连到几个种子），不猜贴题度，不违反 litsearch「不替判断」的原则。

### C. 检索台账（完成 `tools/litsearch/session.py`）

**所有 lit_* 检索类工具加一个可选参数 `session`**。不给 = 现在的行为，一点不变（旧用法零改动）。给了：

- 结果自动记账（渠道：`keyword / semantic / cited_by / references`）
- 返回时每条标 `【新】/【见过·第2轮】/【已判:相关】/【已判:不相关】`；`only_new=true` 时只返回新的（省上下文的关键）
- 台账文件：`data/state/searches/session_<名>.json`（可重建层，删了只丢历史）

**会话的数据结构**（在现有半成品上补齐）：

```
question        用户原话
criteria        agent 和用户商定的「相关」要几条，如 ["剪切硬化/率相关硬化", "用了动态键", "2023 年后"]
scope_notes     范围约定原话（例：「应用类的不算」「综述单列」）—— agent 问过用户后写进来，后续轮次照着办
round           当前轮次
searches[]      每次检索：轮次、渠道、检索式/种子、年份、全世界命中数、返回数、新增数
works{DOI}      标题、年份、期刊、摘要（有无）、渠道列表、首次出现轮次、
                judgment: {verdict: 相关/部分/不相关/没法判, per_criterion: {条: 是/部分/否}, basis: 摘要|仅标题|全文, reason}
```

**新 tool**：

| tool | 干什么 |
|---|---|
| `lit_session` | 建 / 读会话：写问题、判据、范围约定；进下一轮 |
| `lit_judge` | 批量记判断（一次多篇）；`basis=仅标题` 的相关判断在统计里单列 |
| `lit_status` | 每轮 × 每渠道的新增 / 新增相关；渠道两两重叠 + 捕获–再捕获估计（**只拿「引用」对「词面/语义」算**，因为词面和语义不独立；写成「估计」+ 前提）；没判的还有多少；「仅标题」判了多少 |
| `lit_terms` | 相关篇 vs 其余篇的对数几率比挖词（已写好），排除已搜过的；外加相关篇里反复出现的作者、期刊（给「顺着作者找」用） |

**判据拆条是这个方案里对弱模型最友好的一步**：每条都是小判断（「有没有用动态键」），
比「这篇贴不贴题」容易判对，也方便你事后抽查某一条。

### D. 摘要补齐（F1 的对策，分两档）

- **本期做**：`lit_abstract` 的回退链 OpenAlex → 证据库（我们自己有全文的直接取摘要段）→ Semantic Scholar；
  都没有就明说「这篇源头没有摘要」。
- **要你定**：注册 Elsevier 开发者 key（免费，非商业；能取到什么受你们学校订阅约束，要在主力机上实测）。
  有了它，Elsevier 那 1/3 的判相关才能从「只凭标题」变成「有摘要」。

### E. 章法（`deep-research` skill + `litsearch` SKILL.md，都是生成物，改源再跑生成器）

改写成按轮的循环，明确写：

1. **开场先定判据和范围**：把问题拆成 2～4 条判据；年份窗口、算不算应用类/综述/专利，**问用户**，写进 `lit_session`
2. **每轮三条腿都走**：词面（同义词族）+ 语义（第一轮用一段话，之后用 `like=` 已判相关的 3～5 篇）+ 引用（本轮最好的 2～5 篇）
3. **下一轮的词从 `lit_terms` 来**，模型自己想的词只作补充（依据：模型凭空写检索式召回低、不可复现）
4. **判相关按条判**；只有标题的标 `仅标题`，不许当确定
5. **停**：连续一轮三条腿都没有新的相关篇，且 `lit_terms` 前 10 个都搜过了；或达到和用户约定的工作量上限。
   报告里写用了哪条、`lit_status` 的数字原样贴
6. **「最新创新」类问题**：先按窗口前的文献画出「已有做法」，再列窗口内的新东西 —— 新不新是**对比出来的**，
   报告用「做法 × 年份」表
7. 遇到范围之外但可能有用的（比如邻近体系），**列出来问用户要不要纳入**，不自己扩

### F. 不做 / 后置

- **S2 推荐接口**：单种子实测只有 1/20 相关；台账有了之后用多正例 + 负例再测一次，不行就不接（后置，不在本期工作量里）
- **本地模型批量初筛**：候选上百篇时可以让本地小模型按判据先筛一遍再给 agent。和「取舍由 agent 定」有张力，
  先不做；等真实跑下来看 agent 上下文是不是瓶颈再说
- **改 `discover` / `query_expand`**：不动（它们服务别的流程）
- 本地向量库扩到全世界、训练专用检索模型：不做（OpenAlex 已经做了向量化）

## 3. 架构与守卫（事先想清楚，免得做到一半被守卫打回）

- 全部落在 `tools/litsearch` 一个包里；联网只在 `shared/adapters/openalex`（`semantic_search`）；台账是 litsearch 私有，不下沉
- `tool.toml` 仍是 `costs_money=false / side_effects=[]`：台账和现有检索日志一样只写可重建的本地状态，
  OpenAlex 在免费额度内。**我会在 tool.toml 注释里写明这条判断**，守卫若不认就回来问你
- 新 tool 走 `expose=tool`（只读公开数据 + 写自己的状态文件），不进 `agent_tools` 白名单（那是给花钱入口的）
- 每个 tool 的 handler 返回 dict（踩坑 #150）；返回文本控制长度：默认 25 条、每条摘要预览 300 字，要全文摘要用 `lit_abstract`
- 花销：每个会话记 OpenAlex 调用次数，`lit_status` 里显示；超过免费额度时 OpenAlex 回 429，沿用现有退路和提示

## 4. 验收（做完才测，不先测旧的）

- **标准集**：挑 3 个方向，各取一篇 2024–2026 的综述，**综述的参考文献里落在年份窗口内的**当标准答案（外部来源，不是我标的）。
  一个在你的方向里（剪切硬化 / 动态键弹性体），一个相邻（如 vitrimer），**一个完全无关**（检验不拟合）。
  调章法只用第一个；报数用后两个。
- **指标**：相对召回（标准集找回几成）；找到的「相关」里标准集之外的有多少（前沿的东西综述可能还没收）→ 我抽 10 篇核；
  调用次数；轮数。
- **各条腿的贡献不用另跑**：台账记了每篇是哪个渠道找到的，直接算「只用词面能找回几成 / 加语义 / 加引用」。
  这同时就回答了「旧做法差多少」，不用单独测旧的。
- **换模型也成立**：同一个方向用两个不同的模型各跑一遍（Claude + 一个便宜的），召回差距写进报告。

## 6. 风险

| 风险 | 对策 |
|---|---|
| OpenAlex 语义检索是新功能，参数可能变 | 全部隔离在适配器一个函数里；selftest 每天体检会报 |
| 捕获–再捕获前提（渠道独立）不成立 → 估计偏乐观 | 只用「引用 vs 其余」算；报告写「估计」；停不停主要看饱和曲线 |
| 1/3 候选只有标题 | 标出来、单列统计；D 档的 Elsevier key |
| agent 上下文被结果淹掉 | 台账的 `only_new` + 默认 25 条 + 摘要预览 300 字 |
| 标准集（综述参考文献）偏老、偏高被引，测不出「最新」 | 额外统计标准集之外的「相关」并抽查，写进报告 |
