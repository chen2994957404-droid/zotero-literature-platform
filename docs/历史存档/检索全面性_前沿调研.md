# 检索的全面性：前沿方法 vs 我们现在的做法（2026-09-24 定稿，待用户点头再动手）

> 用户目标：让 agent（Claude 等）用这个库时能**多轮、全面**地找到某方向的最新创新文献
> （例：剪切硬化最近用了什么新动态键、新结构）。靠模型补检索词 + 多轮「取结果 → 总结 → 再检索」。
> **原则**：工具只做通用能力，取舍由 agent 和用户对话时决定；不拟合任何领域；方法换模型也成立。

## 一、前沿怎么做（出处见文末）

| 系统 | 求全的渠道 | 判相关 | 多轮怎么转 | 停 |
|---|---|---|---|---|
| **Ai2 Paper Finder**（2025） | 模型改写多个检索式 + **三个语义（向量）索引** + 关键词 + 从命中片段里抽引用 | 把要求拆成几条**分别判**（完全 / 有些 / 不相关）再合并 —— 他们说这一步显著提高准确度 | 找到相关的 → **按读到的内容重写检索式** → 对最好的几篇前后向引用 → 再判 | 找够了或看的候选太多 |
| **Undermind**（商用） | 关键词 + 引用，约 2 亿篇标题摘要 | 模型逐篇判 | 反思结果 → 找关键信息 → 调整 → 再搜，约三轮 | 固定轮数 |
| **PaSa**（ACL 2025） | 搜索 + 扩引用 | 独立的「挑选」agent | 「求全」和「判准」分成两个 agent | 学出来的 |
| **SPAR**（2025） | 查询分解 + 沿引用链演化检索式 + 多数据源 | — | Query Evolver | — |
| **系统综述 / TAR 方法学** | 布尔检索 + 引用追踪 | 人判 | 主动学习：判过的当训练样本 | 饱和曲线、捕获–再捕获、统计停止规则（Callaghan 2020） |

关键数字：
- **LitSearch 基准**（EMNLP 2024）：语义向量检索 recall@5 比词面检索（BM25）**高 24.8 个点**。
- **只靠模型写检索式召回偏低，还不可复现**：Wang 2023（ChatGPT 写布尔检索式）精度高、召回低；
  2024 复现研究换随机种子结果就变；SIGIR 2025 复评：模型「优化」检索式同样是精度升、召回降。
  → 「让模型凭空补词」这条路本身有天花板，必须用**从真实命中文献里来的词和文本**补。

## 二、实测（2026-09-24，A 机，各一两次调用）

同一个问题「剪切硬化 + 动态键，2023 年后」：

- **词面精确检索** `"shear stiffening"`：146 篇，多是应用 / 复合材料（防护织物、鞋垫、传感器）。
- **OpenAlex 语义检索**（一段话描述问题）：返回里有
  「用键解离动力学调控动态共价 tetra-PEG 的剪切增稠」「动态 thia-Michael 交联的 tetra-PEG 剪切增稠」
  「动态共价键是合成水凝胶应变硬化的来源」等 —— **全都没用 "shear stiffening" 这个词**，
  词面检索永远搜不到，而这正是「新动态键」要找的那类。两种检索**互补**，不是替代。
- **Semantic Scholar 推荐接口**（给一篇 PBS 论文当正例）：20 条里只有 1 条 PBS，其余是泛泛的 2026 年高分子论文。
  单个种子不够用；多正例 + 负例的效果要等有台账后再测。

## 三、现有做法差在哪（按影响排）

1. **给 agent 的只有词面检索一条腿**（`lit_search` = OpenAlex `title_and_abstract.search`）。
   换了说法的同一件事完全搜不到。Sciverse 的语义检索只在 OpenAlex 限流时当退路，agent 主动用不了。
   → 这是前沿与我们差距最大的一处，而且实测直接看得见。
2. **没有「照着这几篇找相似的」**（相关反馈 / 以文找文）。Paper Finder、S2 推荐、TAR 都靠它；
   我们的 agent 读到好文后只能自己再想词。
3. **补词靠模型凭空想**：`query_expand` 在看到任何结果之前一次性生成，还拿用户库的标题当语境
   （和「找新东西不拿库当标准」冲突）。文献说这条路召回低、不稳定、换模型结果就变。
   前沿做法是**从已判相关的文献里取词**（Paper Finder 的重写、TAR 的相关反馈）—— 这不依赖模型强弱。
4. **多轮没有状态**：每次 `lit_search` 都是孤立的，agent 记不住哪些看过、判过，
   第三轮就开始重复读、重复花上下文；也说不出「搜全了没有」—— deep-research 章法里写了饱和判据，
   但没有任何东西在量它。
5. **判相关没有章法**：agent 对着整个问题一次性判。Paper Finder 实证「按条拆开分别判再合并」更准，
   而且这对弱模型更友好（每条是个小判断）。
6. `discover` 按「跟库多近」排序且只给人点，不适合 agent 的多轮循环 —— 不改它，不走它。

## 四、更好的方案（四块，按性价比排）

**A. 加语义检索渠道**（`lit_search` 加 `mode=semantic`，或单列 `lit_semantic`）
- 调 OpenAlex `search.semantic`（GTE-Large 向量，覆盖全部标题 + 摘要；可加年份等过滤）
- 输入是**一段话**：可以是 agent 写的问题描述，也可以直接是**已判相关那几篇的摘要拼起来** ——
  后者就是「以文找文」，一个渠道同时补上第 1、2 两条差距
- 限制（官方文档）：每次最多 50 条、输入前 2000 字、每秒 1 次；每次 0.001 美元，免费 key 每天 1 美元 ≈ 1000 次，够用
- 难度：**小**（适配器加一个函数 + 工具加一个参数 + 测试），约半天

**B. 检索台账**（完成 `tools/litsearch/session.py` 并接进 lit_* 工具）
- 每次检索 / 雪球带上会话名：结果自动标「上一轮见过 / 已判相关 / 新的」，可只返回新的
- `lit_judge`：agent 记下判断（可按条记：满足了哪几条要求）
- `lit_status`：每轮新增**相关**数（饱和曲线）、各渠道（词面 / 语义 / 引用）找到的相关篇重叠 →
  捕获–再捕获估计还漏多少。⚠ 词面与语义两个渠道不独立，估计会偏乐观，报告里写成「估计」不写成定论
- `lit_terms`：从已判相关的标题摘要里统计挖出**真实文献里的新说法**（对数几率比，不用模型、不预设词表），
  agent 拿去组下一轮检索式 —— 替代「模型凭空补词」
- 难度：**中**，session.py 已写一半，约 1～2 天（含测试与 MCP 面）

**C. 改 deep-research 章法**（纯文档）：每轮固定三条腿
`词面（同义词族）+ 语义（相关摘要当查询）+ 引用（最好的 2～3 篇前后向）` →
按条判相关 → `lit_terms` 挖新词 → 下一轮；停：连续一轮三个渠道都没有新的相关篇 + 台账估计。
遇到范围问题（年份、要不要算应用类、要不要算综述）**停下来问用户**。难度：**小**。

**D.（后置）S2 推荐接口**：多正例 + 负例、只推近期论文，正好对「最新创新」。
单种子实测效果差，等 B 有了已判相关的一批再测，不行就不接。

**不做的**：本地跑 SPECTER2 / 自建全世界的向量库 —— OpenAlex 已经替我们向量化了 2 亿多篇，本地没必要重复。
训练专门的检索 agent（PaSa 那种强化学习）—— 超出范围；我们让通用 agent + 好工具去做。

## 五、怎么验收（做完之后，不先测旧的）

「相对召回」（Sampson 2006）：挑 2～3 个方向，各拿一篇**近两年的综述的参考文献**当标准集（外部来源，不是我标的），
看 agent 按新章法跑完找回几成；一个方向调、另一个方向报数（练习集 / 考卷分开）。
