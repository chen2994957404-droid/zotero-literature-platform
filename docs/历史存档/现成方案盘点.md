# 现成方案盘点 —— 全流程里哪些手写逻辑该换成现成库 / 模型（2026-09-21）

> 用户定的规矩：单位、词表、分区这类东西找现成库和方案，别靠碰到一个补一个（见记忆 use-existing-libs-not-patches）。
> 本文把整条流水线过一遍：每处手写逻辑、对应的现成方案、是否查证过、建议优先级。**「查证」= 今天搜到并确认存在；「未试」= 没在我们的数据上跑过。**

## 建议顺序

1. **GLiNER 试样品识别**（#4）—— 直指当前最弱的样品归属 52%；2 篇快筛，半天。
2. **pySBD 替掉两处手写切句**（#3）—— 顺手，零风险。
3. **多语 NLI 交叉编码器做判同异**（#6）—— 审稿和单元覆盖两处受益，还能顺带做论文类型分类（#14）；60 条对照量一致率。
4. **pandas.read_html 替表格解析**（#8）—— 等抽取线要正式化时做。
5. Docling（#11）留到 MineRU 额度出问题时。

## 不该换的

找数正则（#2，现成的不如自己的）、骨架正则（#9）、数字核对（#12）、术语表（#15）—— 要么现成的更差，要么本身就是数据驱动。
