# 架构重构 v2 · 总体设计

> 本文回答一个问题：**怎么拆，才能让每一部分各自升级、互不影响。**
> 它服从 `架构宪法_第一性原理.md`，是宪法的**补完**而非替代 ——
> 宪法说了「公理→定理→界面」，但没说清各层之间**靠什么表达依赖**。
> 这份文档补的就是这一点。
>
> 立于 2026-08-26。

## 零、先承认现状（不粉饰，否则设计没有靶子）

### 做对了的
- `modules/` 公理层方向正确，17 块大多干净、单一职责、带 selftest。
- 数据以 Zotero item key 为单元组织（数据契约），这个决定非常好，是资产。
- 配置/密钥统一走 `modules/config`，密钥进系统凭据库。
- 面板 + 体检 + 自动交接文件，让非程序员能掌控运行状态。

### 做坏了的（有据可查）

| 病 | 证据 |
|---|---|
| **工作流之间靠「文件路径 + argv 顺序」耦合** | `文献精读/zotero_watcher.py` 用 subprocess 拉起 `mineru_parse.py` / `deepread_v4.py` / `si_deepread.py` / `merge_summary.py` / `数据抽取/extract_structured.py` 五个脚本，接口就是参数的先后顺序 |
| **公理层被绕过、重复实现** | `zotero_watcher.py:82-93` 重写了 `zget` / `find_pdf` / `SUPP_PAT`，而 `modules/zotero_client` 里已有同名实现（违反铁律 1） |
| **数据契约没有进代码** | `workflow_data/...` 在 **53 处**手工拼路径 |
| **脚本既是程序又是库** | `from extract_structured import SYS`、`import zotero_watcher as W`；import 的瞬间就触发副作用（读配置、建目录、劫持 print） |
| **每文件 9 行 sys.path 补丁** | 40+ 处。根因是项目不是一个可安装的 Python 包 |
| **没有离线可跑的测试** | 0 个 pytest；selftest 依赖 Ollama/Zotero，默认 4 红 |
| **界面层混着业务逻辑** | `平台管理/panel.py` 1012 行 = HTTP + HTML + 业务 + 起进程；`panel.py:205` 靠 `sys.path.insert('找新文献')` 借用逻辑 |
| **手写的地图会死** | `docs/架构总览.md` 仍在描述 `scripts/`、n8n、`workflow_data/summary/` —— 均已不存在 |

### 根因（只有一条）
**没有安全网 → 改动有风险 → 接手者宁可新加脚本也不改旧的 → 脚本增殖、靠路径粘连。**
所以重构的第一步不是搬文件，是**先造安全网**。

## 一、总体形状：四环 + 两条横切

```
        +----------------------------------------------+
        |  apps/    界面环 —— 人和机器怎么触发           |
        |  cli · panel · mcp · watcher                 |   零业务逻辑
        +---------------------+------------------------+
                              | 只调 pipelines 的函数
        +---------------------v------------------------+
        |  pipelines/   编排环（宪法的「定理」）          |
        |  deepread · si · extract · vectorize ·       |   由 step 组成
        |  discover · ask                              |   幂等、可续跑
        +------+-----------------------+---------------+
               |                       |
    +----------v----------+  +---------v-------------+
    | domain/  纯逻辑环    |  | adapters/  外接口环    |
    | figure · chunk ·    |  | zotero · llm · mineru |
    | si_filter · schema ·|  | embed · vectordb ·    |
    | render · prompts    |  | sciverse              |
    | X 不碰网络不碰硬盘   |  | V 唯一允许联网/第三方库|
    +----------+----------+  +---------+-------------+
               +-----------+-----------+
        +------------------v---------------------------+
        |  core/   内核环 —— 谁都依赖它，它不依赖任何人  |
        |  paths · config · cli · log · errors ·       |
        |  jobs · proclock · subproc                   |
        +----------------------------------------------+

   横切 A：core.jobs   —— 状态与进度（SQLite，谁做到哪一步）
   横切 B：core.paths  —— 数据契约的唯一实现（所有路径只此一处）
```

**依赖只能从上往下，绝不反向**（宪法铁律 2，这里第一次变成可被工具检查的规则）。

### 为什么是这四环，而不是别的分法

分层的判据是**「它依赖什么、多久变一次」**，不是「它属于哪个业务」：

| 环 | 判据 | 变化频率 | 怎么对待 |
|---|---|---|---|
| `core` | 不依赖任何人 | 几乎不变 | 一次做对 |
| `domain` | 只依赖 core，**无 I/O** | 十年不变（数学、格式） | 自己写，全量单元测试 |
| `adapters` | 各包住一个外部系统 | 几个月换代 | 用现成的，包一层稳定接口 |
| `pipelines` | 把上面三者按顺序编排 | 需求一变就变 | 随便改，改了也不影响下面 |
| `apps` | 只把 pipelines 暴露出去 | 加入口时变 | 薄到没有可测的东西 |

这正是宪法【首要判据】「稳定的自己做、发展的用现成」的**目录化落地** ——
以前这条判据只存在于脑子里，现在它变成了目录结构：违反了就 import 不上。

## 二、这样拆之后，「独立升级」具体长什么样

这是本设计要交付的唯一承诺。**升级隔离矩阵**：

| 你想升级什么 | 需要改的地方 | 其余部分 |
|---|---|---|
| 换 PDF 解析（MineRU → 别的） | `adapters/mineru.py` 一个文件 | 全部不动 |
| 换精读大模型 / 供应商 | `core/config` 一行配置 | 全部不动 |
| 换向量库（Chroma → 别的） | `adapters/vectordb.py` 一个文件 | 全部不动 |
| 改精读的**排版风格** | `domain/render/` 模板文件 | 裁图、LLM、写回全不动 |
| 改精读的**提示词范式** | `domain/prompts/deepread_v3.txt` + 版本号 | 代码零改动，旧产物自动被标记为「待刷新」 |
| 改裁图算法 | `domain/figure.py` | 纯函数，单元测试直接验证，不用跑全流程 |
| 加一条新工作流（如「综述生成」） | 新增 `pipelines/review.py` | 现有工作流零感知 |
| 加一个新入口（微信机器人 / Web API / 新 MCP 工具） | 新增 `apps/xxx/` | 业务逻辑一行不写 |
| 结构化抽取加字段 | `domain/schema.py` 加字段 + 版本号 +1 | 只有该字段为空的文献会被重抽 |
| 换 Zotero 为别的文献管理器 | `adapters/zotero.py`（大改，但只此一处） | pipelines 以上全部不动 |

**关键：每一行的「需要改的地方」都是一个文件，不是一片文件。**
今天做不到，是因为逻辑散在 subprocess 链和 53 处硬编码路径里。

## 三、两条横切设计（现在完全缺失，是真正的使能件）

### A. `core.jobs` —— 任务状态库（SQLite，标准库，零新依赖）

**现在的状况**：一篇文献做到哪一步，唯一记录是 Zotero 上的标签。
于是「已精读过的只补缺的部分」要靠**翻文件系统猜**；失败了没有原因；
中断了不能续跑；面板看不到进度；不知道某篇的 summary 是哪个模型、哪版提示词产的。

**设计**：`workflow_data/state.db`，核心一张表：

```
runs(item_key, step, status, started_at, finished_at,
     producer, prompt_ver, schema_ver, model, cost, error)
```

一行 = 某篇文献的某个步骤的一次执行。带来：

- **续跑**：崩了从断点接着做，不重跑花钱的步骤
- **重试策略**：外部 API 失败自动退避重试，而不是整篇失败
- **「只补缺的」变成一句 SQL**，不再是文件系统考古
- **溯源**：每份产物都知道自己由哪个模型 + 哪版提示词生成
- **升级即查询**：提示词升到 v3 → `WHERE prompt_ver < 3` 就是待重跑清单
- **面板真进度**：现在只能看日志尾巴，以后能看「3/12 篇，当前在解析」

> 这一条直接服务于总目标：**升级某一步之后，只重跑受影响的部分，别的一动不动。**

### B. `core.paths` —— 数据契约的唯一实现

`docs/数据契约.md` 写得很好，但它只是**散文**。53 处手工拼路径意味着契约随时可能被违反而无人知道。

```python
# core/paths.py —— 全系统唯一知道目录长什么样的地方
def paper_dir(key)   -> .../library/<key>
def fulltext(key)    -> .../library/<key>/parsed/full.md
def layout(key)      -> .../library/<key>/parsed/layout.json
def summary(key)     -> .../library/<key>/summary.html
def meta(key)        -> .../library/<key>/meta.json
def structured(key)  -> .../structured/<key>.json
```

改目录布局 = 改一个文件 + 一个迁移脚本。且可以写一个**契约测试**：
扫全库，验证每个 key 目录都满足契约，缺什么一目了然。

## 四、命名：代码目录改 ASCII，用户看到的一律保持中文

**改**：`文献精读/` → `pipelines/deepread/`，`modules/` → 拆进 `core/ domain/ adapters/`。

**理由**（不是审美，是硬约束）：
- 中文文件夹没法当 Python 包用，`python -m` 用不了 —— 这正是 40 处 `sys.path` 补丁的来源
- 跨平台、跨工具（git、CI、MCP 客户端、别的 agent）路径易出问题
- 已有踩坑先例：路径一旦跨文件夹拼接就极脆

**你完全不受影响**，因为：
- 根目录的 `控制面板.bat`、`精读监听.bat` 保持中文不变，你的入口没变
- 面板、精读报告、问答回答，全部中文不变
- 每个包的 `CLAUDE.md` 保持中文，注册表里保留中文显示名（「文献精读」）
- 你从来不需要键入文件夹名 —— 你点面板

## 五、测试策略（这是整个重构最重要的一步，不是附属品）

现在零测试，所以没人敢改，所以只能加不能改，所以有了今天的样子。

三层：

| 层 | 跑什么 | 要求 | 何时跑 |
|---|---|---|---|
| **单元测试**（pytest） | `domain/` 全部纯函数：裁图坐标、切块、SI 过滤、schema 校验 | 全离线，秒级，必须永远绿 | 每次改动 |
| **契约测试** | 用 2~3 篇留样文献的 `parsed/` 数据跑全流程，比对产出 | 离线（LLM 走录制的假响应） | 每次改动 |
| **实测**（现 selftest） | 真连 Zotero / Ollama / 各 API | 需要环境，允许红 | 手动 / 体检 |

关键动作：**把 selftest 一刀切成 `--offline` 和 `--live` 两档**。
现在体检默认 5 警告 1 失败，噪音盖住了真信号 —— 分档之后，
「离线档必须全绿」就成了一条**可执行的红线**。

## 六、迁移路线（分阶段，全程保持可用，绝不大爆炸）

> 原则：**每一阶段结束时系统都必须是能跑的**；每阶段单独 commit，随时可回退。

### 阶段 0 · 安全网（先决条件，其余全部依赖它）
1. 加 `pyproject.toml`，`pip install -e .` → **删掉 40+ 处 sys.path 补丁**
2. 引入 pytest；给 `domain` 候选模块补单元测试
3. selftest 切 `--offline` / `--live` 两档；体检据此重算红黄绿
4. **取得一次全绿基线并记录下来** —— 没有基线，后面无法判断「是不是我改坏的」

### 阶段 1 · 内核环
5. 写 `core/paths.py`，把 53 处硬编码路径全部改过来（机械、低风险）
6. `core/log.py` 替掉 `zotero_watcher` 里劫持 `print` 的写法
7. `core/errors.py`：一套异常分类，让调用方能分辨「外部服务挂了」和「输入不对」

### 阶段 2 · 拆开公理层
8. `modules/*` 按「是否碰网络/硬盘」分入 `core / domain / adapters`
9. **删掉 `zotero_watcher` 里重复的 `zget`/`find_pdf`/`SUPP_PAT`**，改用 adapters
10. chromadb 包进 `adapters/vectordb.py`（现被 3 个脚本直接 import，等于焊死）
11. 加一条依赖方向检查（domain 不许 import adapters 等），并入离线测试

### 阶段 3 · 编排环 + 状态库（收益最大，也最需小心）
12. `deepread_v4.main()` 拆成 `pipelines/deepread` 的若干 step
13. watcher 改为**直接调函数**，不再 subprocess 拉脚本
14. 建 `core/jobs` + `state.db`
15. **新旧并行**：用开关切换，同几篇文献两条路各跑一遍，逐字节比对产物

### 阶段 4 · 界面环
16. 统一 CLI：一个 `lit` 命令带子命令（替掉散落的 30 个脚本入口）
17. `panel.py` 1012 行拆开：HTML 模板出文件、业务逻辑改调 pipelines
18. MCP 服务重新指向 pipelines —— 它会自然变薄，这正是当初想拆的方向
19. watcher 瘦成 ~80 行：看标签 → 入队 → 完事

### 阶段 5 · 文档收口
20. `架构总览.md` 已过时 → 改为**自动生成**的依赖与契约地图（手写地图必死，交接文件是反证）
21. `归档_旧版本/` 移出仓库（945 行死代码）
22. 60KB / 98KB 两份流水账在切割线处封存，新账另起

## 七、明确不做的事（防止重构失控）

- **不换语言、不上框架**（不引 FastAPI / Celery / Django）。单用户本地平台，标准库足够；
  宪法的「少依赖」是对的。新增依赖只有 pytest（开发期）。
- **不动 `workflow_data/` 里的数据**。数据是不可再生资产，重构只动代码。
- **不重写「能用且没人抱怨」的算法**（裁图聚类、SI 过滤等）—— 只是搬家 + 补测试。
- **不追求 100% 覆盖率**。`domain` 层要高覆盖，`apps` 层不测。
- **不为架构而架构**（宪法第八条第 5 点）。每一步都要能回答「这解决了哪个具体的痛」。

## 八、这份设计和宪法的关系

宪法说：公理 → 定理 → 界面。**方向完全正确，本设计不推翻任何一条。**

本设计做的是三件宪法没做的事：

1. **把「公理层」拆成三种**（内核 / 纯逻辑 / 外接口）。它们只是都「底层」，
   但依赖性质和变化频率完全不同，混在一起就没法分别对待 ——
   这是今天「想换个模型却不知道要改几处」的直接原因。
2. **给铁律 2（单向依赖）配上强制力**。宪法禁止循环依赖，但没有任何机制阻止它。
   目录分环 + 一条自动检查，规则才真正生效。
3. **补上「状态」这一维**。宪法讲的是**结构**（谁调用谁），
   但一个长时间、要花钱、会失败的系统还需要**过程**（谁做到哪、失败在哪、该重跑谁）。
   这就是 `core.jobs` 存在的理由。
