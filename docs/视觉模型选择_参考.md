# 视觉模型选择 · 参考（图表数字化用）

> 背景：图表数字化需要视觉模型。DeepSeek 当前 API 不支持视觉（2026-07 仍文本-only）。
> 你的情况：几万篇文献要跑（成本敏感）+ 本地 RTX 3060 12GB。
> 策略：本地视觉模型主力（零成本大规模）+ 云端高精度备选。

---

## 一、本地（主力，零成本）—— 正在下载

**qwen2.5-VL:7b**（Ollama）
- 为什么选它：7B 适配你的 12GB 显存；qwen-VL 系列专门强于**图表/文档理解**，
  是本地视觉模型里做图表数字化最合适的。
- 成本：零 API 费，本地跑。适合几万篇的大规模场景。
- 用法：接入后设 `OLLAMA_VISION_MODEL=qwen2.5vl:7b`，provider='ollama'。
- 已在后台下载（约 6GB）。

**若精度不够，可升级本地模型**（需更大显存或接受更慢）：
- qwen2.5-VL:32b（更准，但 3060 跑不动，需换卡或量化）。

---

## 二、云端 API（高精度备选，你自己决定要不要弄 key）

按"性价比 + 中文/图表友好"排序，供你参考去开通：

| 服务 | 视觉模型 | 特点 | 大概成本 |
|------|---------|------|---------|
| **阿里通义千问** | qwen-vl-max / qwen-vl-plus | 中文强、图表好、国内直连快、有免费额度 | 低（plus 更便宜）|
| **智谱 GLM-4V** | glm-4v | 国内、中文好、便宜 | 低 |
| **OpenAI** | gpt-4o / gpt-4o-mini | 精度顶尖，mini 便宜 | mini 低、4o 中 |
| **Claude** | claude 视觉版 | 精度高、擅长复杂图 | 中 |

**建议**：你若要弄云端备选，**优先通义千问 qwen-vl**——和你本地 qwen-VL 同源、
中文和图表友好、国内快、有免费额度试用。开通后把 key 给我，我接入（走 OpenAI 兼容格式）。

**成本控制原则**（呼应你的大规模担忧）：
- 大规模粗提取 → 本地 qwen2.5-VL（免费）。
- 少数关键图要高精度 → 云端。
- 分层用，绝不所有图都上云端。
