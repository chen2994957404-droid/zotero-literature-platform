# 正文数据关联 · 方向说明

> 用户战略判断（2026-07-24）：重要数据作者一定写进正文，读图边际价值低；
> 把算力用在"吃透并关联正文数据"更有价值。本文说明这个方向具体是什么、怎么走。

---

## 一、为什么是"关联"而非"读图"

- **正文已含精华数据**：论文的关键结论数值（最高强度、最优配比、关键性能）
  作者必然写进正文/摘要。结构化抽取从正文就能拿到。
- **读图只在"要完整曲线/密集点"时才有价值**（如做数据拟合、复现曲线、ML训练）——
  属深度研究阶段。当前"广度找方向"阶段，读图边际价值低。图表数字化积木已验证可用、
  搁置待命，深度分析时再启用。
- **真正的金矿是"关联"**：单篇数据有限；把几百篇正文的"材料-结构-性能-机理"
  连成关系网，能回答单篇没有、只从关联中涌现的问题（呼应"涌现"哲学）。

## 二、关联能回答什么（真实例子）

已在 154 篇上跑过最简关联（按动态键机理分组），一个模式立刻浮现：
- "氢键"组出现 104.6 MPa 高拉伸强度；"硼氧"组性能全是冲击/热稳定、无高强度。
- → 提示："要做高强度材料，氢键+相分离路线比硼氧路线更可能出高强度。"
  这是单篇看不到、横向关联才涌现的方向指引。

更进一步能回答：
- 哪些**不同体系**通过**同一机理**达到了相似性能？（机理的普适性）
- 同一性能指标，哪条技术路线的天花板最高？（路线对比）
- 这个方向的**空白**在哪？（没人做过的"机理×性能"组合 = 潜在 idea）

## 三、路线（第一性原理：先保证数据质量，再关联）

**关联（定理）的质量取决于底层数据（公理）的质量。数据脏，关联结论不可信。**
所以顺序是：

### 第 1 步：保证数据质量（正在验证）
- 现状问题：只 13 篇精层可用、多篇 N/A、机理分类粗糙、中英混杂。
- 做法：用干净英文 schema + DeepSeek 精抽。**先小范围验证**（10-20篇）：
  确认"干净数据→好关联"这条路通，再决定是否花钱铺全库。

### 第 2 步：在干净数据上做关联分析
- 归一化字段（如动态键类型的多种表述归成标准类别）。
- 按机理/性能/体系交叉分组，找模式、矛盾、空白。
- 这层纯文本、不烧视觉模型，成本低。

### 第 3 步（远期）：连成知识图谱
- 把"材料-结构-性能-机理"抽成节点+关系（三元组），连成可查询、可视化的网。
- **按分层复杂度策略**（宪法）：这是组合层，copy MatKG 等成熟骨架、依赖 NetworkX，
  不从零硬写。

## 四、与现有积木的关系

- 复用公理件：zotero_client（取正文）、pdf_parse（解析）、llm_client（抽取）。
- 结构化抽取（定理）产出干净数据 → 关联分析（新定理）→ 知识图谱（组合层）。
- 图表数字化积木：搁置待命，深度数据分析时才启用。
