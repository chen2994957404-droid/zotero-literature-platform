# 项目结构导览 · 这个项目由什么组成

> 给**人**读的一份地图，目的是让你打开任何一个文件夹都知道「这是干嘛的」。
> 不用记，看不懂的时候回来翻一下就行。
>
> 相关的另外几份：`README.md` 怎么用（给你）· `AGENTS.md` 给 AI 的正本 ·
> `HANDOVER.md` 我们做到哪了（自动生成）· `REBUILD.md` 这次重构的施工记录。
>
> 写于 2026-09-01（R7 重构完成之后）。

---

## 一、一句话看懂整体

```
你打个标签  →  平台自动干活  →  结果回到你的 Zotero 里
```

代码按「**什么会让它需要改**」分成五层，从下往上：

| 层 | 是什么 | 什么会让它改 | 规模 |
|---|---|---|---|
| `shared/kernel/` | 地基：路径、配置、日志、异常、锁 | 几乎不会改 | 3500 行 |
| `shared/domain/` | 纯逻辑：算法、格式、字段定义 | 只有我们自己想法变了 | 800 行 |
| `shared/adapters/` | 对外接口：Zotero、大模型、MineRU… | **外部世界变了**（换 API、换模型）| 3300 行 |
| `tools/` | 十个工具，每个是一个能力 | 需求一变就变 | 9600 行 |
| `host/` | 平台自身：面板、体检、部署、监听服务 | 运维方式变了 | 5400 行 |

**依赖只能从上往下**：`host → tools → domain/adapters → kernel`。
反过来不行，有测试当场拦（`tests/test_architecture.py`，24 条守卫）。

为什么值得这么分：**换掉 MineRU 只需要改一个文件**，
因为全项目只有 `shared/adapters/pdf_parse/` 那一块知道 MineRU 存在。

## 三、`tools/` —— 十个工具，一个工具一个文件夹

**这是整个结构的核心思路：想优化哪个能力，就只打开那一个文件夹。**
工具之间**不许互相调用**（有守卫拦），所以改一个不会波及另一个。

| 工具 | 干什么 | 花钱？ |
|---|---|---|
| `deepread` | 一篇文献 → 中文图文精读报告，自动传回 Zotero。**最常用** | 花 |
| `extract` | 一批文献 → 结构化字段 + 横向对比表 | 花 |
| `paperdb` | 结构化记录 → 能筛能比大小的查询库 | 不花 |
| `library` | 查 Zotero 库（搜条目、标签、合集、拿 PDF）| 不花 |
| `ask` | 问自己的文献库（RAG，答得深、附来源）| 花 |
| `askworld` | 问全世界的文献（带原文出处）| 花 |
| `discover` | 找新文献：搜全球 → 对照我的库 → 排序 | 花 |
| `direction` | 方向地图：一条窄带里谁做了什么、空白在哪 | 花 |
| `digitize` | 论文图里的曲线 → 数据点 | 花 |
| `curate` | 库房维护：打标签、附件改名、清重复 | 花 |

### 每个工具文件夹里长得一模一样

| 文件 | 是什么 | 你会关心吗 |
|---|---|---|
| `__init__.py` | **对外契约**：这个工具提供哪几个函数。开头的说明写清了它是什么 | 想了解就看它 |
| `<实现>.py` | 干活的代码，想拆几个文件都行 | 一般不用看 |
| `cli.py` | 命令行入口（`python -m tools.<名>`），只解析参数 | 想知道怎么敲命令 |
| `mcp.py` | 给 AI 的接口，只做参数转换 | 不用看 |
| `tool.toml` | **一句话说明 + 花不花钱 + 有什么副作用 + 要哪台机器** | 想知道代价就看它 |
| `README.md` | 给人的说明 | ✅ 想用它就看这个 |
| `SKILL.md` | 给 AI 的手册，含**什么时候别用我** | 不用看 |
| `CLAUDE.md` | 给 AI 的完整说明书（含这块的坑与铁律）| 想深入就看 |
| `INCIDENTS.md` | **这个工具踩过的坑**（坑号 + 现象 + 对它意味着什么）| ✅ 出问题时看 |
| `prompts/` | 给大模型的提示词，`<名>_v<版本>.txt`，**只增不改** | ✅ 想改精读风格就改这里 |
| `evals/` | 评测：怎么判断这个工具产出的东西「好不好」 | 见第八节 |
| `tests/` | 这个工具的自动测试 | 不用看 |
| `selftest.py` | 离线自测，不花钱不联网 | 不用看 |

具体每个工具的实现文件：

- `deepread` — `main_text.py` 正文 · `si.py` 补充材料 · `merge.py` 合并 ·
  `batch.py` 批量 · `tags.py` 标签状态机 · `si_filter/` 从 SI 里挑实验细节
- `extract` — `batch.py` 批量 · `wizard.py` 重抽向导 ·
  `domain_filter.py` 领域过滤 · `compare_models.py` 比两个模型
- `curate` — `junk.py` 清垃圾 · `rename.py` 附件改名 · `tags.py` 标签改造 ·
  `backfill.py` 补元数据
- `discover` — `collect.py` 收集 · `importer.py` 按 DOI 导入 ·
  `match.py` 跟我的库像不像 · `thesis.py` 学位论文
- `direction` — `brainstorm.py` 创意讨论 · `bibliometrics/` 文献计量（聚类、趋势）
- `ask` — `vectorize.py` 向量化 ｜ `askworld` — `search.py` 纯检索
- `digitize` / `library` / `paperdb` — 代码都在 `__init__.py` 里，一个文件就够

## 四、`shared/` —— 被两个以上的地方用到的东西才配住这里

规矩很硬：**只有一个使用者的东西，要搬回那个使用者里去**（有守卫查）。
不然这里几年后会变成全项目最乱的地方 —— 因为没人知道动它会影响谁。

### `shared/kernel/` —— 地基，谁都依赖它，它不依赖任何人

| 块 | 干什么 |
|---|---|
| `paths.py` | **全项目唯一知道文件放在哪的地方**。数据目录改一次布局，只改这一个文件 |
| `config/` | 密钥与配置（环境变量 → 系统凭据库 → `.env`）|
| `cli/` | 命令行参数解析，禁止别处手写 `sys.argv` |
| `log.py` | 统一日志：时间戳 + 落盘 + 自动轮转 |
| `errors.py` | 异常分类，让调用方知道**该不该重试** |
| `jobs.py` | 状态库：谁做到哪一步了、能不能跳过（省钱的关键）|
| `role.py` | **机器角色闸门**：这台机器允不允许写 Zotero / 跑花钱的活 |
| `proc_lock/` | 单实例锁，防止同一个服务跑两份 |
| `heartbeat.py` | 心跳与进度信号（看门狗靠它判断服务死没死）|
| `subproc/` | 静默子进程调用（不弹黑窗口）|
| `prompts/` | 读提示词文件（带版本号）|
| `mcp_prompt.py` | 给 AI 的提示卡片统一格式 |

### `shared/domain/` —— 纯逻辑，不联网、**不知道文件放在哪**

| 块 | 干什么 |
|---|---|
| `figure_crop/` | 按坐标从原 PDF 裁出**完整的图**（不用解析器的碎图）|
| `schema/` | 结构化抽取有哪些字段、性能字符串怎么拆成数值 |

### `shared/adapters/` —— **唯一允许联网的一层**

| 块 | 包住谁 |
|---|---|
| `zotero_client/` | Zotero（读本地 API、找 PDF；写在 `_web.py`，全项目唯一碰 Zotero 写接口的文件）|
| `llm_client/` | 各家大模型（云端 / 本地 Ollama）|
| `embed/` | 本地 bge-m3 向量化 |
| `pdf_parse/` | MineRU 云端 PDF 解析 |
| `vectordb/` | 向量库（现在是 Chroma）|
| `openalex/` · `crossref/` · `sciverse/` | 三个学术检索源 |
| `snowball/` | 引文雪球（建在 openalex 之上）|
| `query_expand/` | 把中文问题拆成英文检索式 |
| `wechat_seed/` | 从公众号文章里取种子文献 |

## 五、`host/` —— 平台自身：不是能力，是让平台活着的东西

**没人可以依赖它，它可以依赖所有人。** 所以跨工具的编排都放这儿。

| 块 | 干什么 | 你怎么碰到它 |
|---|---|---|
| `panel/` | 控制面板（本地网页）—— 你和系统的主要交互入口 | 双击 `控制面板.bat` |
| `watcher/` | **常驻服务**：盯标签 → 精读 → 抽取 → 回写。`service.py` 干活，`watchdog.py` 看着它别死 | 打个标签就自动跑 |
| `autosync/` | 每小时一次：新文献自动进向量库和对比表 | 自动，不用管 |
| `doctor/` | 体检 + 诊断报告 + 查产物缺口 | 双击 `诊断报告.bat` |
| `deploy/` | 拉新代码 + 装包 + 重启服务；数据搬家 | 双击 `更新平台.bat` |
| `mcp/` | 让 AI 能直接用这些工具的协议层 | 在 Claude 里直接用 |
| `codegen/` | 所有生成器：`HANDOVER.md` / `.claude/` / 坑的总目录 | 不用管 |

> **为什么精读监听在 `host/` 而不在 `deepread/` 里**：它精读完还要顺手抽取，
> 横跨两个工具。而工具之间不许互相调用，跨工具的编排就属于平台层。

## 六、`data/` —— 你的数据，五层

分层的判据是「**重建它要付出什么**」：

| 层 | 放什么 | 弄丢了怎么办 |
|---|---|---|
| `raw/` | MineRU 解析出来的东西（`<KEY>/parsed/full.md`、图、坐标）| **要重新花解析额度** |
| `curated/` | 精读产物（`<KEY>/summary.html`、`meta.json`）| 要重新花大模型的钱 |
| `serving/` | 对比表、向量库、方向地图 | 随时可重建，不花钱 |
| `state/` | 索引与状态（`state.db`、`papers.db`、`evalset.json`）| 索引可重建；**`evalset.json` 是你打的评价，不可重建** |
| `logs/` | 日志 | 丢了就丢了 |
| `backup/` | 备份 | — |

⚠ 整个 `data/` 不进版本库（两台机器各自生成），
只有 `evalset.json` 等三样不可重建的例外。

## 八、几个「知道了会省事」的点

### 每个文件夹都有自己的 `CLAUDE.md`

这是让 AI 帮你改东西的关键：新对话里**只选中一个文件夹**，
它一进来就知道这块是干什么的、有哪些坑、改完怎么验证 ——
不用把整个项目塞给它。

### `.claude/` 全是自动生成的

十个工具的 skill 从各自的 `SKILL.md` + `tool.toml` 生成，
四个平台 skill 从 `docs/howto/skills/` 生成。**手改会被测试当场拦下**。
改完源跑 `python host/codegen/skills.py`。

### 三条验证命令（改完代码跑这个）

```bash
python -m pytest -q                            # 272 条测试 + 24 条架构守卫
python host/doctor/health_check.py --offline   # 离线体检，必须 10 通过 0 失败
python host/doctor/health_check.py             # 完整体检（本机没开服务会有黄，正常）
```

### 「评测」和「体检」不是一回事

- **体检**回答「能不能跑」—— 全项目都有
- **评测**（`tools/<名>/evals/`）回答「**跑出来的东西对不对**」—— 10 个里 9 个有了

| 工具 | 验的是什么 | 还缺什么 |
|---|---|---|
| `deepread` | 客观快照 + 你打的好/差评价 | 样本攒够才能校准出自动质量分 |
| `curate` | 附件分类 / 垃圾分组 / 标签改写（25 条）| — |
| `paperdb` | 4 条造的记录 + 9 个查询用例 | — |
| `extract` | 综述判定 / 档次 / 有值 / 性能拆解（23 条）| 「模型抽得准不准」要你人工核对几篇 |
| `discover` | 排序规则，钉住「相关度压过被引」（12 条）| 真实召回质量要主力机的数据 |
| `direction` | 聚类，**答案由构造保证**（10 条）| 真实窄带上效果好不好要人判断 |
| `ask` | 可追溯性：每段带出处、来源不多不少、库空不硬答 | 答案质量要你出题 |
| `askworld` | 同上 + 跑题证据筛掉、检索式转英文 | 答案质量要你出题 |
| `library` | 检索的不变量（要真实 Zotero，`pytest -m live`）| — |
| `digitize` | ⬜ **空的** | 要几张已知真值的图 + 花钱调云端模型 |

**每一套都「故意破坏一次、确认会红」验过** —— 不会红的评测比没有更糟。

## 九、还没处理好的（我知道，但没做）

**这一节是这份文档最该被读的部分。** 按重要性排：

### 1. 主力机（B 机）还没切过来 —— 唯一会影响你日常使用的一条

代码搬了家，但 B 机上两个计划任务的命令行是**注册在 Windows 里的**，
还指着已经不存在的模块。**不改的话精读监听和每小时同步都不会再工作，
而且不会有任何报错**（任务照样显示「运行成功」）。

**怎么办：在主力机上双击一次 `launch/更新平台.bat`。**
它会自动发现并改正，然后重启服务、跑体检。你只按这一次。

顺带：B 机上的 MCP 注册（Claude 用的那套）也要重新指一次，
服务入口现在是 `host/mcp/server.py`。

### 2. `digitize` 还没有评测，另外几个只做了一半

**`digitize` 是唯一完全空着的**，而它恰恰是最该有的一个：本地模型会编出
看似合理的假数据，**肉眼根本看不出来**。填它需要几张你自己画的、
已知真值的图，再花钱调一次云端模型比对误差 —— 这两样我都替你做不了。

另外几个做了「能确定的那一半」，还缺的那一半都需要你：

| 工具 | 还缺什么 | 为什么要你 |
|---|---|---|
| `extract` | 模型抽得准不准 | 要几篇**你人工核对过**的 `structured/<KEY>.json` 当金标 |
| `ask` / `askworld` | 答案质量 | 要「已知答案在哪一篇」的问题 —— 你才知道自己库里哪篇讲了什么 |
| `discover` | 真实召回质量 | 天然金标是「你后来实际导入了哪几篇」，那数据在主力机上 |
| `direction` | 真实窄带效果 | 「这两篇确实是一支吗」只有你判得了 |

### 3. 精读评价的历史快照口径变了

修好了「百分数从来没被数进去」的老毛病（伸长率、修复效率这类数值一直被漏掉），
但你之前打过的评价是用旧口径算的，**两把尺子量的数不能直接比**。

**怎么办**：在主力机上跑一次
`python -c "from tools.deepread import evals; evals.recompute()"`。
精读文件还在盘上，重算是零成本的。面板的评价卡片上也会提示还剩几条没刷。

### 4. 运行时的名字和新位置对不上（**故意不改**）

日志还叫 `zotero_watcher.log`、锁还叫 `zotero_watcher`、
状态库里的生产者还叫 `deepread_v4` —— 都是搬家前的名字。

**故意留着**：它们连着磁盘上已有的日志、锁、几百条状态记录，
改名要连带处理历史数据，收益却只是「名字好看点」。
知道它对不上就行。

### 5. 一些较小的

- `specs/`（还没实现的想法）是空的 —— 目前想法都记在 `docs/待办与需求.md` 里
- `docs/explain/架构重构_v2总体设计.md` 的目录名已经改对了，
  但第六节「迁移路线」是历史章节，别照着做
- 精读的「废品线」是 3000 字，这个数字是拍出来的，还没有数据支持
- Elsevier 的 SI 是不是叫 `mmc1.pdf`、`.docx` 的 SI 叫什么 —— 没能核实
  （A 机的测试库里没有这类附件）。**你在主力机上时，让 Claude 看一眼
  真实的附件文件名**，对得上就把这两种命名也加进 SI 判据
