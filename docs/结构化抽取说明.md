# 结构化抽取说明 · Structured Extraction

> 由 Claude 于 2026-07-24 新增。这是继"精读线"和"向量化问答线"之后的**第三条线**：
> 把文献从"可语义检索"升级为"可筛选、可聚合、可横向对比"，用来支撑材料发现
> （从横向对比中发现空白/矛盾 → 催生研究 idea）。

## 为什么要这条线（和向量化的区别）

向量化给模型的是"语义相似的一团正文"——能问答，但**不能精确、不能聚合、不能横向比**。
比如问"库里所有拉伸强度>50MPa的体系按温度排序"，向量检索做不到。

结构化抽取把每篇文献抽成**对齐的字段**（材料体系/合成条件/性能数值/自愈合机制…），
汇成一张对比表。竖着扫同一字段，就能发现"同样是氢键，为什么有的104MPa有的很软"
这种规律——研究 idea 往往从这种对比里冒出来。

## 两级结构（完全对称于两级向量化）

|          | 粗层（广撒网·全库）                | 精层（高质量·重点文献）            |
|----------|-----------------------------------|-----------------------------------|
| 脚本     | `extract_library.py`              | `extract_structured.py`           |
| 吃什么   | Zotero `/fulltext`（不解析PDF）   | MineRU 高质量 `parsed/full.md`    |
| 用什么模型 | **本地 qwen2.5:7b-instruct**（免费不限量） | 云端 **DeepSeek-v4-pro**（准） |
| 定位     | 全库粗抽，供横扫找方向            | 重点文献精抽，数值可信            |
| 成本     | 0（纯本地）                       | 每篇几分钱                        |

**精层优先原则**：已被任一层抽过的 key，粗层自动跳过，绝不覆盖高质量结果
（和 `vectorize_library.py` 里"已有精读向量则跳过"完全一致的设计）。

## 怎么跑

```bash
# 粗层：全库广撒网（需 Zotero 桌面程序开着，读本地全文API）
python scripts/extract_library.py            # 增量
python scripts/extract_library.py --rebuild  # 重抽全部

# 精层：抽 library 里已精读的文献（需联网调 DeepSeek）
python scripts/extract_structured.py         # 增量
python scripts/extract_structured.py <KEY>   # 只抽某篇
python scripts/extract_structured.py --rebuild
```

精层已接入 `zotero_watcher.py`：**在 Zotero 打「待精读」标签的文献，精读完会自动做精层抽取并入表**，无需手动跑。

## 产物（都在 workflow_data/structured/）

- `<key>.json` — 每篇的结构化字段（`source` 字段标 `coarse`=粗层 / 无=精层）
- `compare.md` — ★所有文献对齐的横向对比表，**这是找 idea 的载体**

## schema 在哪改（这是领域判断，改字段=改这里）

字段定义集中在 `extract_structured.py` 顶部的 `SCHEMA` 字典。
粗层 `extract_library.py` 直接 import 复用它，改一处两层同步生效。
当前方向：软物质 / 动态键弹性体 / 自愈合 / 结构-性能。
想加列（如"相畴尺寸""氢键密度"）就往 SCHEMA 加一行，然后 `--rebuild` 重抽。

## 防幻觉设计（下游可信度的保证）

1. 找不到的字段一律填 `N/A`，禁止编造（N/A 本身是有价值的信号=这里是空白）
2. 数值必须带单位、不许换算（防有效数字/单位错误往下游传播）
3. temperature=0.1 求稳；Ollama `format:json` + 粗层额外做 JSON 容错解析
4. 粗层本地7B质量低于精层pro——只用于广度筛选，不用于精确决策
5. `key_properties` 字段说明放宽为「任何量化表征结果」（力学/分子量/流变/热/电导/灵敏度），
   避免只认力学量而漏掉表征类文献的核心数据（见踩坑记录 #12）

## Provider 切换（云 / 本地）

`extract_structured.py` 支持云端 DeepSeek（默认）和本地 Ollama 两条线：

- 默认走 DeepSeek：`python scripts\extract_structured.py [KEY]`
- 切本地：`$env:EXTRACT_PROVIDER="ollama"; $env:OLLAMA_MODEL="qwen2.5:7b-instruct"`

**实测结论（踩坑记录 #13）**：抽取吃精度，本地 7B 会漏数值/错配单位/幻觉，
产生「看着对其实错」的脏数据。抽取是一次性低成本任务 → **继续用 DeepSeek**；
本地模型（qwen/bge-m3）留给向量化和精读。开关保留，换 32B 级本地模型时可再评估。
