# subproc · 子进程调用

> 你可能是被单独选中这个积木文件夹打开的，看不到项目其他部分。本文件是你的全部上下文。

## 这是什么

**一块「公理件」** —— 平台的最小可复用单元。
公理特征：只做一件不可再分的事，这里是「跑一条外部命令并拿回结果」。

用户是材料方向研究者，**不懂编程**。技术决策你自己拿主意。

## 职责

Windows 上调外部命令，把三件最容易漏掉的事一次做对：

1. **不弹控制台窗口**（`CREATE_NO_WINDOW`）
2. **有超时**（默认 120 秒），不会永远挂住
3. **UTF-8 编码**（注入 `PYTHONIOENCODING` / `PYTHONUTF8`），中文不乱码

## 对外接口

| 函数 | 用途 |
|---|---|
| `run(cmd, timeout, cwd, env, check)` | 跑完等结果，返回 CompletedProcess |
| `out(cmd, default='')` | 只要 stdout；失败/超时返回 default，**不抛异常** |
| `powershell(script)` | 跑一段 PowerShell 并返回输出 |
| `spawn(cmd)` | 后台启动长驻进程，不等待、不弹窗，自动把 python.exe 换成 pythonw.exe |

## 为什么存在（两个真实事故）

**踩坑 #31 — 弹窗**：面板每 15 秒、看门狗每 60 秒各查一次进程，
裸调 `subprocess` 会不停闪蓝色控制台窗口打扰用户。
散落在 6 个文件、17 处的调用各写各的，**修一处漏一处**。

**踩坑 #32 — 中文乱码**：Windows 子进程默认按系统区域编码（中文系统是 GBK）写 stdout，
父进程按 UTF-8 解码 → 全是乱码。这个问题存在很久，一直被误当成
「PowerShell 显示问题」而没深究，实际是子进程编码问题，且会真的损坏数据。

**为什么做成积木而不是逐处修**：逐处修只解决今天这些，明天新写的代码还会再犯。
做成积木后「调子进程」只有一个正确入口。**从源头杜绝优于事后补救。**

## 配套的防腐机制

体检里有一项 `c_no_popup`，会扫描全项目，揪出绕过本积木的裸 `subprocess` 调用。
**规范如果没有自动检查兜着，迟早会腐坏。**
（`modules/subproc` 自身和 `归档_旧版本/` 已豁免。）

## 谁在用它

面板（查进程/重启服务/跑自测）、看门狗（查进程/杀进程/重启 watcher）、
proc_lock（判断 PID 是否存活）、体检（查任务计划）。
