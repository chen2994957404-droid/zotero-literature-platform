# lib_match · 文献对照

> 你可能是被单独选中这个积木文件夹打开的，看不到项目其他部分。本文件是你的全部上下文。

## 这是什么

**一块「公理件」**，而且是**整个找文献平台里最不可替代的一块**。

外部检索谁都能调（OpenAlex、Sciverse 都是公开 API，别人也能接）。
本平台真正的护城河是：**只有它知道用户已经有什么、读过什么、在做什么方向。**
把外部结果和本地库对照这一步做好，搜索才从「又一个 Google Scholar」
变成「知道我在干什么的助手」。

用户是材料方向研究者（聚硼硅氧烷/动态键弹性体），**不懂编程**。

## 它回答两个不同的问题（别混为一谈）

| 问题 | 输出 | 用途 |
|---|---|---|
| 这篇我有没有？ | `status`: have / likely / new | 去重，避免重复导入 |
| 这篇值不值得读？ | `relevance`: 0~1 | 决定看不看 |

**第二个问题才是关键。** 搜回 250 篇时，「有哪些」没用，「哪几篇值得现在读」才有用。

## ⚠ 核心设计主张：高被引 ≠ 对你有用

一篇 300 次引用的通用综述，往往不如一篇 5 次引用但正好做你那个体系的论文。
所以 `rank()` 的默认权重是 **相关度 0.6 / 被引 0.25 / 新鲜度 0.15** —— 相关度占大头。

被引数还做了开方压缩（`sqrt(c)/20`），避免超高被引的一家独大。
库里已有的直接减 1.0 沉底，但仍列出（让用户知道「我这个方向抓得准不准」）。

**改权重前请先想清楚这条主张还成不成立**，别为了让结果"看起来权威"就抬高被引权重。

## 对外接口

| 函数 | 说明 |
|---|---|
| `build_index(force=False)` | 拉本地库的标题/DOI 集合，带 5 分钟缓存 |
| `match_many(papers)` | **批量**对照。搜回 200 篇时逐篇调用会慢几十倍 |
| `match(paper)` | 单篇，内部走 match_many，不另写一套逻辑 |
| `rank(papers, matches)` | 综合排序，返回 [(paper, match, score)] |

## 两层判别

1. **精确层**：DOI 相同、或标题归一后相同 → `have`。便宜且确定，先做。
2. **语义层**：标题+摘要向量化，与向量库比对。
   - 相似度 ≥ 0.92 **且标题也像** → `likely`（很可能是同一篇换了写法）
   - 相似度本身 → `relevance`

阈值 `DUP_SIM=0.92` / `STRONG_SIM=0.75` 是实测调的，改之前先跑自测看会不会误判。

## 降级策略（重要）

- **Zotero 没开** → 精确层返回空集，仍可靠语义层工作
- **Ollama 没跑** → 语义层跳过，保留精确层结果，`relevance` 为 None
- 排序时 `relevance=None` 给中性分 0.5，**不惩罚**

一句话：**任何一个依赖挂掉都只损失一部分能力，不会让整个功能失效。**

## 实测基准（改动后应对得上）

- 库内真实文献 → `have`，相关度约 **0.96**
- 完全无关的文献（我用「拜占庭钱币冶金学」测的）→ `new`，相关度约 **0.54**

区分度够大。如果改动后这两个数字靠近了，说明判别能力退化了。
